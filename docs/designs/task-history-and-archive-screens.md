## 1. 목적과 범위

이 문서는 앱을 열었을 때 쓰는 할 일 화면, 완료·놓침·건너뜀 이력 화면, 보관된 Reminder를 관리하는 보관함의 정보 구조와 상호작용을 정의한다. 세 화면은 주 내비게이션에서 각각 바로 열 수 있고 앱 진입 기본 화면은 `할 일`이다(`D-079`).

이 문서는 화면의 정보 우선순위와 동작 초안이다. 색상·서체·간격 등 시각 디자인 토큰과 정확한 반응형 breakpoint는 여기서 고정하지 않는다. 넓은 화면의 navigation 배치와 breakpoint는 `DS-002`와 함께 확정한다. 화면에서 사용하는 ID 및 상태 의미의 기준은 이 설계에 복사해 새 정책으로 만들지 않고 연결된 결정·요구사항을 따른다.

## 2. 화면 구조와 진입 흐름

```text
앱 시작
└── 할 일 (기본)
    ├── 내 할 일
    ├── 내가 요청한 일
    └── 가구 전체 보기

주 내비게이션
├── 할 일
├── 이력
│   ├── 내 담당 Reminder (매 진입 기본)
│   └── 가구 전체 이력 (현재 화면 세션에서만 선택 유지)
└── 보관함
    ├── 보관 Reminder 상세
    ├── 복원
    └── 영구 삭제 확인
```

모바일에서는 세 목적지를 하단 주요 내비게이션으로 제공한다. 충분한 폭의 화면에서 목적지를 놓는 위치와 좁은 화면에서의 정확한 메뉴 breakpoint는 `DS-002`에 맡긴다. 할 일 목록 안의 세 보기 선택은 폭이 충분하면 세 선택 버튼으로, 좁으면 현재 보기 이름을 보여주는 선택 메뉴로 바꾼다(`D-078`, `PR-AC-063`).

## 3. 공통 화면 규칙

- 화면 제목과 현재 목적지를 항상 텍스트로 표시한다. 선택 상태는 색상만으로 표현하지 않는다.
- 데이터 요청 중에는 화면 구조를 유지하는 loading placeholder를 보여준다. 목록 요청 실패 시 기존 결과를 실패 데이터로 오인하게 남겨두지 않고 재시도 action을 제공한다.
- 비어 있는 결과에는 현재 범위와 이유를 함께 설명한다. 빈 상태에 액션을 두는 경우 해당 화면에서 가능한 다음 작업으로 연결한다.
- Reminder 제목을 누르면 Reminder 상세로 이동한다. 완료·보관·복원·삭제는 기존 도메인 권한 및 상태 규칙을 따르며 화면이 별도 권한 정책을 만들지 않는다.
- 주요 버튼은 터치·키보드로 실행 가능하게 하고, 아이콘만 있는 버튼에는 접근 가능한 이름을 제공한다. 상태 뱃지와 완료 여부는 색상 외에도 텍스트·아이콘으로 구분한다.

## 4. 할 일 화면

### 4.1 기본 구성

```text
┌────────────────────────────────┐
│ Notify Me                  프로필 │
│ 할 일                            │
│ [내 할 일] [내가 요청한 일] [가구 전체] │  ← 좁은 화면에서는 선택 메뉴
├────────────────────────────────┤
│ 기한 초과                         │
│ [상태] 제목              [완료]   │
│        예정 시각 · 담당자 · 요청자 │
│ 오늘                              │
│ [상태] 제목              [완료]   │
│        시간 또는 장소 조건         │
│ 예정                              │
│ [상태] 제목              [완료]   │
│        예정 시각 · 담당자 · 요청자 │
└────────────────────────────────┘
│       할 일       이력      보관함 │
└────────────────────────────────┘
```

시각 배치는 작은 화면의 개념 예시다. 카드 내부의 정확한 정보 줄바꿈과 넓은 화면 배열은 viewport 검토 중 조정한다.

### 4.2 보기별 포함 규칙

| 보기 | 포함할 현재 회차 |
|---|---|
| `내 할 일` | 현재 로그인 사용자가 활성 담당자인 Reminder의 활성 미완료 회차 |
| `내가 요청한 일` | `requester_user_id`가 현재 사용자인 활성 미완료 회차. 담당자가 다르거나 아직 지정되지 않아도 포함 |
| `가구 전체 보기` | 가구의 모든 활성 미완료 회차. 무담당 회차도 포함 |

세 보기는 동일한 기한 섹션과 정렬 규칙을 쓴다(`D-072`, `D-076`, `PR-AC-056`, `PR-AC-061`). 하나의 회차가 한 보기에서 완료되면 서버 동기화 후 그 회차가 모든 활성 보기에서 사라진다.

### 4.3 섹션·카드 정보

- 섹션 순서는 `기한 초과` → `오늘` → `예정`이다. 날짜 구분은 사용자 표시 시간대를 따른다(`D-065`).
- 시간 Trigger는 각 섹션 안에서 예정 시각 오름차순이다. 시간이 없는 LOCATION Trigger는 `예정` 섹션에 둔다(`D-072`).
- 카드는 제목, 현재 Occurrence 상태 뱃지, 시간 또는 장소 조건의 짧은 설명, 담당자와 요청자를 표시한다. 내용은 제목을 읽는 흐름을 방해하지 않도록 짧게 표시하고, 전체 내용은 상세에서 제공한다.
- 완료 action은 카드에서 바로 실행할 수 있다. 가구 구성원 누구나 현재 업무 회차를 완료할 수 있고, 한 명이 완료하면 회차 전체가 완료된다(`D-010`, `D-013`).
- 반복 Reminder의 현재 `PENDING` 회차에는 `이번 회차 건너뛰기` action을 제공한다. 실행하면 선택한 회차만 `SKIPPED`로 바꾸고 다른 회차는 유지한다(`D-075`, `PR-AC-060`).
- 제목/카드 본문을 누르면 Reminder 상세로 이동한다. 편집·담당자 변경·보관·삭제 action은 상세 화면의 기존 결정된 흐름을 사용한다.

### 4.4 빈 상태와 오류 상태

| 상황 | 표시와 다음 동작 |
|---|---|
| 전체 할 일이 없음 | “아직 할 일이 없습니다”와 Reminder 추가 진입점을 제공한다. |
| 현재 보기만 비어 있음 | “이 보기에는 할 일이 없습니다”와 선택된 보기 이름을 함께 표시한다. 다른 보기로 이동하는 선택 컨트롤은 유지한다. |
| 조회 중 | 각 섹션과 카드의 대략적인 크기를 유지하는 placeholder를 표시한다. |
| 조회 실패 | 실패 메시지와 재시도 action을 표시한다. 사용자 입력 중인 새 Reminder 초안은 보존한다. |
| 한 섹션만 비어 있음 | 빈 섹션을 만들지 않는다. 다른 섹션의 항목만 정상 순서로 표시한다. |

## 5. 이력 화면

### 5.1 조회 범위와 정렬

화면을 새로 열 때마다 `내 담당 Reminder` 범위로 시작한다. 사용자는 같은 화면에서 `가구 전체` 이력으로 바꿀 수 있지만 이 선택은 현재 이력 화면 세션에서만 유지한다. 주 내비게이션에서 이력을 떠난 뒤 다시 진입하면 기본 범위로 초기화한다(`D-080`, `D-088`). 이 범위는 조회 필터일 뿐 다른 구성원의 데이터 접근 권한을 제한하지 않는다.

완료(`COMPLETED`), 놓침(`MISSED`), 사용자가 건너뜀(`SKIPPED`)을 하나의 목록에 함께 표시하고 상태 뱃지로 구분한다. 정렬은 상태 발생 시각 내림차순이다(`D-081`). 같은 발생 시각 항목은 `AuditEvent.id` 오름차순을 보조 정렬로 사용해 페이지 이동과 재조회 때 순서를 안정적으로 유지한다.

### 5.2 이력 카드와 상세 흐름

```text
┌────────────────────────────────┐
│ 이력                            │
│ [내 담당 Reminder] [가구 전체]  │
├────────────────────────────────┤
│ 완료  두부 사오기                │
│       11월 10일 18:42 · 완료자 이름 │
│ 놓침  분리수거                   │
│       11월 10일 07:00 · 담당자 이름 │
│ 건너뜀 월말 가계부 정산          │
│       11월 9일 21:10 · 수행자 이름 │
└────────────────────────────────┘
```

각 항목은 상태, Reminder 제목, 상태 발생 시각, 관련 행위자 표시를 우선한다. 항목을 누르거나 Reminder 상세의 이력 action을 누르면 해당 Reminder의 수명주기 흐름, Occurrence 진행 흐름, 변경 이력 목록을 볼 수 있다(`D-035`, `D-037`). 변경 이력에는 주요 값의 변경 전·후, 담당자·Trigger·반복 설정 변경, 완료 취소를 포함한다. Reminder 수명주기와 회차 진행 상태는 각각 별도 흐름으로 보여주고 현재 상태를 강조한다.

조회 범위에 해당하는 이력이 없으면 “표시할 이력이 없습니다”를 표시한다. 가구 전체 범위에서 이력이 비었더라도 현재 사용자의 권한은 바뀌지 않으며, 범위를 다시 `내 담당 Reminder`로 바꾸는 control은 유지한다.

### 5.3 화면 이탈·복귀

- 이력 화면에서 보기 전환은 즉시 새 범위로 재조회한다.
- 같은 내비게이션 세션 안에서 이력 항목의 상세/상태 흐름 화면에 들어갔다가 뒤로 돌아오면 직전 범위와 스크롤 위치를 복원한다.
- 주 내비게이션으로 이력을 떠나면 범위 선택 상태를 버린다. 이후 이력을 다시 열면 `내 담당 Reminder`를 선택한다(`D-088`).

## 6. 보관함 화면

### 6.1 목록

보관함은 `archived_at` 내림차순, 즉 가장 최근 보관한 Reminder부터 표시한다(`D-089`). 보관 시각이 같은 항목의 보조 정렬은 `reminder_id` 오름차순으로 고정한다. 카드는 제목, 내용 요약, 보관 시각, 반복 여부를 표시한다. 반복 Reminder는 보관 중 반복과 알림이 일시 중지되었음을 텍스트 뱃지로 알린다(`D-033`).

```text
┌────────────────────────────────┐
│ 보관함                          │
├────────────────────────────────┤
│ [반복 일시중지] 월말 가계부 정산 │
│               11월 10일 보관     │
│                    [복원] [···]  │
│ 두부 사오기                      │
│        11월 8일 보관             │
│                    [복원] [···]  │
└────────────────────────────────┘
```

항목 메뉴의 영구 삭제는 Reminder 상세 삭제와 같은 확인 흐름을 사용한다. 확인 화면에는 제목과 앱에서 복구할 수 없다는 설명, 명시적 `영구 삭제` final action이 있어야 한다(`D-084`, `PR-AC-065`).

### 6.2 복원과 삭제 상태

- `복원`은 활성 목록으로 Reminder를 되돌린다. 반복 Reminder는 보관 중 만들지 않은 회차를 보충하지 않고 다음 미래 예정 회차부터 재개한다. 보관 전에 생성한 미완료 회차는 기존 결정에 따라 다시 활성화한다(`D-033`, `D-034`).
- 복원에 실패하면 보관함 카드를 유지하고 실패 안내와 재시도 방법을 제공한다.
- 영구 삭제를 취소하면 보관함으로 돌아가고 데이터는 바꾸지 않는다. 삭제에 성공하면 해당 카드가 목록에서 사라진다.
- 보관함이 비었으면 “보관된 Reminder가 없습니다”를 표시한다. 영구 삭제된 항목은 보관함에서 복구할 수 없다(`D-032`).

## 7. 핵심 화면 동작 검증 시나리오

아래는 설계에서 구현 검증으로 연결할 시나리오다. 실제 automated test와 기기 검증은 [테스트 전략](../08-test-strategy.md) 및 연결 기능의 개발 루프에서 작성·실행한다.

| 시나리오 | 기대 결과 | 연결 기준 |
|---|---|---|
| 앱을 처음 연다 | 할 일 화면과 `내 할 일` 보기를 연다. | `PR-AC-056`, `D-072` |
| 화면 폭이 좁아진다 | 세 보기 버튼이 현재 선택을 나타내는 선택 메뉴로 바뀌고 가로 넘침이 없다. | `PR-AC-063`, `D-078` |
| 요청자가 다른 사람의 Reminder를 등록했다 | `내가 요청한 일`에는 담당자와 무관하게 표시되고, `내 할 일`에는 현재 담당자가 아니면 표시되지 않는다. | `PR-AC-061`, `D-076` |
| 여러 담당자 중 한 명이 완료한다 | 서버 동기화 후 해당 회차가 완료되고 활성 할 일 보기에서 빠진다. | `D-010`, `D-013`, `PR-AC-056` |
| 반복 Reminder의 현재 회차를 건너뛴다 | 현재 회차만 `SKIPPED` 이력에 나타나고 다른 회차는 유지된다. | `D-075`, `PR-AC-060` |
| 이력에서 가구 전체 보기로 바꾼 뒤 나간다 | 다시 이력에 진입하면 `내 담당 Reminder` 범위로 시작한다. | `D-080`, `D-088` |
| 완료·놓침·건너뜀 이력이 섞여 있다 | 한 목록에서 상태 뱃지와 상태 발생 시각 최신순으로 표시한다. | `D-081`, `PR-AC-011` |
| Reminder를 여러 개 다른 시각에 보관한다 | 가장 최근 보관 항목이 위에 오고 반복 항목에는 일시 중지 상태가 보인다. | `D-033`, `D-089`, `PR-AC-034` |
| 보관 Reminder를 복원한다 | 보관함에서 사라지고 활성 흐름으로 돌아간다. 반복 회차는 보관 중 누락분을 만들지 않는다. | `D-033`, `D-034`, `PR-AC-034` |
| 보관함에서 영구 삭제를 누른 뒤 취소한다 | 제목·복구 불가 안내가 먼저 보이고 취소하면 항목이 그대로 남는다. | `D-084`, `PR-AC-065` |
