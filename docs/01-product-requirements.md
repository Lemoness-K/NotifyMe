## 1. 목적과 제품 경계

Notify Me는 같은 가구의 구성원이 자신 또는 서로에게 부탁을 남기고, 일정이나 장소가
되면 시스템 알림으로 상기받고, 완료 결과를 공유하는 서비스다. 1차 운영은 Raspberry
Pi를 인터넷에서 HTTPS로 접속 가능한 서버로 운영한다. MVP는 집 안팎에서 네트워크와
서버가 상시 연결된다고 가정한다(`D-011`).

MVP는 공유 Web UI를 Capacitor Android 앱 셸에서 재사용하고, Kotlin 네이티브 기능으로
알림과 지오펜싱을 제공한다(`D-003`, `D-008`). iOS는 후속 플랫폼이다(`D-003`).

## 3. 핵심 사용자 흐름

### 3.1 최초 설정

1. 운영자는 지정한 검증 Google 계정에 대해 서버 명령을 한 번 실행해 최초 Household와 첫 Admin Membership를 만든다. 이 초기 작업은 공개 UI로 제공하지 않는다(`D-074`).
2. 최초 Admin 또는 초대받은 구성원이 인터넷을 통해 Web UI 또는 Android 앱을 연다.
3. 기존 사용자는 Admin에게 지정된 Google 이메일로 초대 URL을 받아 해당 계정으로 로그인하고, 새 사용자는 링크에서 해당 Google 계정으로 가입한다. 초대 코드를 직접 입력하지 않고 링크의 가입 확인을 완료한다(`D-023`, `D-024`, `D-029`).
4. Android 앱이 설치 ID와 기기 capability를 서버에 등록한다.
5. 앱은 알림, 정확한 시간 알람, 위치 권한 상태를 읽고 필요한 Android 시스템 설정 화면으로 안내한다.
6. 서버에 저장된 활성 리마인더를 내려받아 로컬 예약·지오펜스를 reconcile한다.

### 3.2 리마인더 생성·동기화

1. 작성자는 자동 기록한다. 제목·내용을 입력하고, 기본으로 자신이 선택된 담당자 목록을 확인한다. 필요하면 담당자를 추가·제거하고 요청자를 다른 가구 구성원으로 바꾼다(`D-069`).
2. 알림 기준으로 날짜·시간 또는 장소 중 하나를 선택한다. 장소 기준이면 반경을 슬라이더로 정하고, 반복 설정은 별도 항목에서 입력한다.
3. 저장 시 서버는 가구 소속과 권한을 확인하고 Reminder/Occurrence를 저장한다.
4. 연결된 담당자 기기는 FCM 변경 동기화 신호 또는 앱 시작·foreground·boot 동기화로 서버 revision을 확인하고 자신의 시간 예약·지오펜스를 갱신한다. FCM 전달은 best-effort이며 사용자 표시 알림으로 사용하지 않는다(`D-046`, `D-049`, `D-050`).
5. 앱은 마지막 동기화 시각과 예약/지오펜스 반영 상태를 표시한다.

### 3.3 앱 UI 비가시 상태의 시간 알림

1. 서버에서 동기화된 회차를 Android 로컬 예약 어댑터가 OS에 예약한다.
2. 앱 UI가 보이지 않아도 예정 시각에 일반 Android 시스템 알림을 표시한다(`D-004`).
3. 알림을 탭하면 앱의 리마인더 상세로 이동한다.
4. 알림을 열고 상세 조회와 완료 처리를 서버에 즉시 반영한다(`D-011`).

### 3.4 앱 UI 비가시 상태의 장소 알림

1. 장소 좌표와 반경(m)을 포함한 회차를 서버에서 동기화한다. 반경은 해당 Reminder의 위치 설정값이다(`D-017`).
2. Kotlin 지오펜싱 어댑터가 대상 기기의 OS 지오펜스를 등록한다.
3. 선택한 장소 이벤트(진입·이탈·머무름·이탈 후 경과)가 발생하면 앱 UI가 보이지 않아도 시스템 알림을 표시한다(`D-014`). 한 Reminder에는 장소 이벤트 하나만 설정하고, 시간 Trigger와 함께 설정하지 않는다(`D-015`).
4. 이벤트와 완료를 서버에 반영한다. MVP는 네트워크 연결을 가정한다(`D-011`).

### 3.5 완료와 이력

1. 구성원이 목록이나 알림에서 회차를 완료한다.
2. 서버는 완료자, 완료 시각, occurrence revision을 기록한다.
3. 한 구성원의 완료로 담당자 전체에 대해 그 회차가 완료된다. 어느 구성원이나 완료 취소할 수 있다(`D-010`, `D-013`).
4. 완료·놓침·건너뜀 이력에서 원본 리마인더와 반복 회차를 조회한다.

### 3.6 연결된 기기 동기화

기기는 인터넷을 통해 서버의 변경 revision을 확인하고 최신 회차를 기준으로 로컬 시간 예약과
지오펜스를 조정한다. 앱이 닫힌 상태의 변경 동기화 신호로 FCM을 사용한다(`D-046`).

### 3.7 설정 변경

1. 앱 메뉴에서 별도 설정 화면을 연다.
2. 화면은 가구 설정, 개인 설정, 기기 권한·상태를 구분해 표시한다(`D-019`).
3. 가구 설정 변경은 같은 가구에 적용하고, 개인 설정 변경은 현재 사용자에게만 적용한다.
4. OS 권한은 앱에서 강제로 바꾸지 않고 현재 상태와 시스템 설정 진입 기능을 제공한다.

### 3.8 보관과 영구 삭제

1. 가구 구성원은 Reminder를 보관함으로 옮겨 활성 목록에서 감출 수 있다.
2. 보관된 Reminder는 보관함에서 조회·복원할 수 있고, 기존 설정과 이력을 유지한다. 보관 중 알림과 새 반복 회차 생성을 멈춘다.
3. 보관함에서도 Reminder를 영구 삭제할 수 있다. 활성 목록에서도 바로 영구 삭제할 수 있다.
4. 영구 삭제는 앱에서 되돌릴 수 없고 관련 회차 이력도 사용자 화면과 운영 DB에서 즉시 제거한다.
   기기 동기화 tombstone과 암호화 백업은 최대 30일 보존하며, 백업 복원 전에 삭제를 재적용한다
   (`D-032`, `D-058`).

### 3.9 계정 삭제와 가구 종료

계정 삭제는 개인 로그인·프로필을 제거하지만 가구 공유 업무와 이력은 남은 구성원을 위해 유지한다. 가구 종료는 Admin이 시작하며, 구성원이 있더라도 별도 확인 후 종료할 수 있다. 확인 화면은 모든 구성원이 접근을 잃고 공유 데이터가 앱에서 복구 불가능하게 삭제된다는 점을 알린다(`D-068`).

## 4. 권한 매트릭스

가구 역할은 `Admin`과 `Member`다(`D-020`). 활성 가구에는 Admin이 최소 한 명 있고 Member는
0명 이상일 수 있다(`D-021`). `D-010`에 따라 두 역할 모두 모든 reminder를
생성·조회·수정·삭제·완료·완료 취소할 수 있다. 담당자만 수정·완료하도록 제한하지 않는다.
담당자는 여러 명일 수 있으며(`D-012`), 가구 구성원 한 명이 완료하면 해당 회차 전체가
완료된다(`D-013`). 같은 일을 각자 완료해야 한다면 사람별로 리마인더를 따로 만든다.

| 기능 | Member | Admin | 시스템 운영자(후속) |
|---|---:|---:|---:|
| 가구 리마인더 생성·조회·수정·보관·복원·영구 삭제 | 허용 | 허용 | 제한적 지원 |
| 완료/완료 취소·완료 이력 조회 | 허용 | 허용 | 감사 목적 |
| 가구 설정 조회 | 허용 | 허용 | 지원 정책 필요 |
| 가구 설정 변경 | 불가 | 허용 | 지원 정책 필요 |
| 구성원 초대·제거·역할 변경 | 불가 | 허용 | 후속 |

| 본인 설정 조회·변경 | 본인만 | 본인만 | 지원 정책 필요 |

Reminder의 보관은 복원 가능한 동작이고, 삭제는 앱에서 복원할 수 없는 영구 삭제로 제공한다
(`D-032`). 상세 데이터는 운영 DB에서 즉시 제거하고, 기기 동기화 tombstone과 암호화 복구 백업은
최대 30일 보존한 뒤 파기한다(`D-058`).

## 5. 네트워크 전제

집 안팎에서 서버와 인터넷이 상시 연결되어 있다고 가정한다(`D-011`). CRUD와 완료는 서버에
직접 반영하며 오프라인 편집·충돌 병합은 MVP 범위 밖이다. Android는 알림 실행을 위해
기기 예약과 지오펜스를 유지하며 앱이 닫힌 상태의 서버 변경 신호로 FCM을 쓴다(`D-046`).

## 6. 수용 기준

- `PR-AC-001` 두 household 참여자가 각자 로그인하고 동일 가구 리마인더를 조회한다.
- `PR-AC-002` household 모든 참여자가 모든 reminder를 생성·조회·수정·보관·복원·영구 삭제할 수 있다(`D-032`).
- `PR-AC-003` household 모든 참여자가 모든 occurrence를 완료·완료 취소할 수 있다.
- `PR-AC-004` 서버에 저장한 날짜·시간 회차가 Android에 로컬 예약된다.
- `PR-AC-005` Android 앱 UI가 보이지 않는 상태에서도 OS 알림 권한이 허용된 기기에서 시간 시스템 알림이 표시된다(`D-004`). 정확 알람 접근 권한이 없는 설치의 지연 가능 동작은 `D-047`, 24시간 이후 catch-up 억제는 `D-048`을 따른다.
- `PR-AC-006` 동기화한 장소 회차가 지정 장소 도착 시 시스템 알림을 표시한다(`D-005`). 지오펜스 용량 초과로 새 장소 Reminder 저장을 막는 동작은 `PR-AC-068`을 따른다(`D-090`).
- `PR-AC-007` 집 밖에서도 서버 조회·변경과 동기화가 가능하다(`D-011`).
- `PR-AC-008` 기기 재부팅·앱 재시작·권한 변경 후 활성 예약과 지오펜스가 reconcile된다. Android 설정에서 앱을 강제 종료한 경우에는 수동으로 앱을 다시 연 뒤 full sync와 reconcile을 수행한다(`D-050`).
- `PR-AC-009` 권한 거부·알림 채널 차단·위치 서비스 비활성 상태를 사용자가 확인하고 설정 화면으로 이동한다. 백그라운드 위치 권한이 거부되어도 LOCATION Reminder는 저장한다. 해당 설치에 장소 알림 불가 상태와 Android 설정 바로가기를 표시하며, 권한 회복 뒤 해당 기기의 Trigger를 reconcile한다. 다른 구성원 설치의 기능 상태는 바뀌지 않는다(`D-044`).
- `PR-AC-010` 연결된 기기는 집 안팎에서 서버의 최신 상태와 동기화한다(`D-011`).
- `PR-AC-011` 완료·놓침·건너뜀 상태는 각각 회차 이력에 남고, 반복 리마인더의 회차별 이력을 조회할 수 있다. 건너뛴 회차는 연령에 따라 자동 삭제하지 않는다(`D-031`, `D-075`). 이력 화면은 기본으로 현재 로그인 사용자에게 현재 담당자로 지정된 Reminder의 회차 이력을 표시하며, 가구 전체 이력으로 전환할 수 있다. 과거 회차의 표시도 이력 발생 당시 담당자가 아니라 조회 시점의 활성 Assignment를 따른다(`D-080`). `COMPLETED`, `MISSED`, `SKIPPED` 기록은 상태 뱃지를 붙여 한 목록에 함께 표시하고 상태 이벤트 시각 기준 최신순으로 정렬한다. 예정 시각은 정렬 기준으로 사용하지 않는다(`D-081`). 과거 담당자 재배정에 따른 이력 귀속과 같은 이벤트 시각 기록의 tie-break 순서는 `DS-005`에서 정한다. 이력 화면에 진입할 때마다 담당 Reminder 범위로 초기화하고 가구 전체 선택은 현재 화면 세션에서만 유지한다(`D-088`).
- `PR-AC-012` 알림·로컬 예약·지오펜싱·권한·시스템 설정은 platform-neutral port를 통하며, Web/Capacitor 공유 UI와 도메인 코드가 Android Kotlin 또는 후속 플랫폼 SDK를 직접 참조하지 않는다. 각 플랫폼 구현은 capability별 adapter module로 분리한다(`D-006`, `D-008`, `D-052`).
- `PR-AC-013` Reminder 생성 시 같은 가구의 담당자를 한 명 이상 선택한다(`D-012`). 담당자 변경 시 이전 담당자의 미발생 예약·지오펜스를 취소하고 새 담당자의 알림 가능한 기기에 재조정한다. Admin이 마지막 담당자를 구성원에서 제거해 담당자가 0명이 된 기존 Reminder는 `D-059`의 무담당 상태를 허용한다. 무담당 Reminder에는 알림을 예약하지 않으며, 비담당 가구 구성원의 조회·수정·완료 권한은 유지한다(`D-010`, `D-045`, `D-059`).
- `PR-AC-014` 여러 담당자가 지정된 회차를 가구 구성원 한 명이 완료하면 모든 구성원에게 해당 회차가 완료 상태로 표시되고 실제 완료자가 기록된다(`D-010`, `D-013`).
- `PR-AC-015` 각자 수행할 일을 별도 리마인더로 만들면 한 항목의 완료가 다른 항목의 완료 상태를 바꾸지 않는다(`D-013`).
- `PR-AC-016` 장소 알림에서 진입, 이탈, 지정 시간 이상 머무름, 이탈 후 지정 시간 경과 중 원하는 이벤트를 알림 기준으로 설정할 수 있다(`D-014`). 활성 Reminder의 해당 Occurrence가 미완료 상태면 새로 인식된 각 조건 event마다 한 번 알린다. 같은 event의 중복 callback은 억제하고, 같은 진입 또는 머무름 상태가 지속되는 동안에는 반복하지 않는다. 각 새 transition, 새 연속 머무름 구간, 재진입 후 새 이탈 countdown은 별도 event다(`D-041`, `D-016`). 완료·취소·놓침·건너뛴 회차와 보관된 Reminder는 추가 알림을 만들지 않는다. 기기가 조건 event를 인식하면 서버 동기화나 push 응답을 기다리지 않고 즉시 로컬 알림을 표시한다(`D-042`). OS의 event 감지 시각은 별도로 보장하지 않는다. 사용자 실시간 좌표·경로를 기기나 서버에 저장하지 않고, server event metadata는 30일 후 삭제한다. geofence에 필요한 사용자가 지정한 장소 좌표는 Trigger 설정으로 보관한다(`D-043`). `DWELL(N)`과 `AFTER_EXIT(N)`은 5·10·15·30·60분 빠른 선택 중 가구 설정 상한 이하 항목과 분 단위 직접 입력을 제공하고 기본값은 10분이다(`D-082`). 직접 입력은 1분부터 가구 설정 상한까지 허용하며 기본 상한은 60분이다(`D-085`, `F-SET-006`). 상한 변경은 저장된 Trigger 값을 자동 변경하지 않고, 새 duration 또는 duration 수정 시에만 적용한다. 입력·검증 화면은 `DS-006`에서 구체화한다(`PR-AC-066`).
- `PR-AC-017` 각 Reminder에는 `TIME` 또는 `LOCATION` Trigger 중 하나만 저장할 수 있다. 두 유형을 동시에 설정할 수 없으며, 장소 Trigger에는 이벤트 유형 하나만 선택한다(`D-014`, `D-015`).
- `PR-AC-018` `AFTER_EXIT(N)` 타이머가 만료되기 전에 재진입하면 기존 타이머를 취소하고, 다음 이탈부터 N분을 다시 센다(`D-016`). N은 `D-082`의 빠른 선택 또는 `D-085`의 가구 설정 상한 내 직접 입력으로 지정한다. 직접 입력 검증은 `DS-006`에 반영한다(`PR-AC-066`).
- `PR-AC-019` 앱 프로세스 재생성이나 기기 재부팅 후에도 저장된 `AFTER_EXIT` deadline을 복구해 남은 시간을 이어서 센다. 이미 취소되거나 만료 처리된 타이머는 다시 알리지 않는다(`D-016`).
- `PR-AC-020` 장소 Trigger를 생성·수정할 때 옵션의 기본값 100m를 초기 반경으로 표시하고, 설정된 최소·최대 범위의 슬라이더로 해당 Reminder의 반경을 25m 간격으로 조정·저장할 수 있다(`D-017`, `D-018`, `D-039`). 초기 최소·최대·기본값은 각각 50m·500m·100m다(`D-038`).
- `PR-AC-021` Admin은 가구 설정에서 장소 반경 최소값·최대값·기본값을 미터 단위로 설정할 수 있다. 초기값은 최소 50m, 기본 100m, 최대 500m이며, 저장 시 `최소값 ≤ 기본값 ≤ 최대값`을 검증한다. 새 범위를 저장하면 범위를 벗어난 활성·보관 Reminder 반경을 가장 가까운 새 경계값으로 자동 조정하고, 설정과 영향받은 반경을 함께 저장한다. 조정 이력에는 변경을 시작한 Admin과 이전·새 반경을 기록하고, 연결된 활성 기기의 지오펜스를 갱신한다. 보관된 Reminder의 지오펜스는 복원할 때 조정된 반경으로 등록한다(`D-018`, `D-020`, `D-038`, `D-040`).
- `PR-AC-022` 전역 설정 화면은 가구 설정, 개인 설정, 설치 기기의 권한·상태를 구분해 보여주고, Reminder에 속한 설정은 해당 Reminder 생성·수정 흐름에서 다룬다. `USER` 값은 로그인 사용자 `user_id`에 귀속하고 같은 사용자의 설치에서 적용한다(`D-019`).
- `PR-AC-023` 선택 가능하거나 설정 가능한 각 기능은 `HOUSEHOLD`, `USER`, `INSTALLATION`, `REMINDER` 중 정확히 하나의 소유 범위를 설정 카탈로그에 등록하고 기본값·자료형·검증 규칙·비활성화 동작·마이그레이션을 선언한다. 실제 값은 해당 scope의 기준 저장 위치에만 둔다. `USER` 값은 `user_id`에 귀속하고 같은 사용자의 설치들에서 읽으며, OS 소유 `INSTALLATION` 값은 계정·가구 설정으로 복제하지 않고, `REMINDER` 값은 해당 Reminder·Trigger·RecurrenceRule에 보존한다(`D-019`).
- `PR-AC-024` 기능을 추가하거나 제거할 때 설정 카탈로그와 설정 스키마 마이그레이션을 함께 갱신한다. 기능 비활성화나 제거만으로 기존 사용자 데이터와 이력을 조용히 삭제하지 않으며, 기존 데이터의 처리 방식을 정의한다(`D-019`).
- `PR-AC-025` Membership은 `ADMIN` 또는 `MEMBER` 역할 하나를 가진다. Admin만 가구 설정과 구성원 역할을 변경할 수 있고, 두 역할 모두 가구 리마인더를 CRUD·완료할 수 있다(`D-010`, `D-020`).
- `PR-AC-026` 활성 가구는 Admin을 한 명 이상 유지한다. 마지막 Admin의 퇴장이나 강등은 다른 활성 Member에게 Admin 역할을 넘기는 변경과 한 트랜잭션으로 처리한다. 인계할 대상이 없으면 퇴장·강등을 거부한다(`D-021`).
- `PR-AC-027` MVP는 하나의 가구 공간만 생성·사용하며 여러 가구를 만들거나 전환하는 UI를 제공하지 않는다. 데이터/API는 `User`, `Household`, `Membership`를 분리하고 모든 가구 소유 데이터를 `household_id`로 격리해 향후 한 사용자의 다중 가구 참여를 지원할 수 있어야 한다(`D-022`).
- `PR-AC-028` Admin은 초대 대상의 Google 이메일을 지정해 가구 가입 URL을 생성·공유할 수 있다. 새 사용자는 해당 링크에서 Google 계정을 만들고, 기존 사용자는 로그인한 뒤 코드를 직접 입력하지 않고 가입을 완료한다. 수락 시 유효한 Firebase ID token이 `google.com` provider에서 발급됐고 `email_verified`가 참이며 인증된 이메일이 초대 대상과 일치해야 한다. 불일치 요청은 초대를 소비하지 않는다. 가입자는 항상 `MEMBER`로 추가하며, 기존 Admin은 가입 후 별도 권한 변경으로 `ADMIN` 승격을 할 수 있다. 초대 코드는 예측 불가능하고 발급 후 24시간 만료·일회용·취소 가능해야 하며, 링크 조회(GET)만으로는 초대를 소비하거나 Membership를 만들지 않는다(`D-023`, `D-024`, `D-027`, `D-028`, `D-029`).
- `PR-AC-029` 계정 인증 방식이 자체 비밀번호 또는 외부 제공자 중 무엇이든 앱의 업무 데이터는 내부 `User.id`와 `Membership`를 기준으로 소유·인가한다. 외부 계정은 검증된 제공자 식별자(`issuer` + `subject`)를 내부 사용자에 연결하고, 역할·가구 권한은 인증 제공자 claim만으로 부여하지 않는다.
- `PR-AC-030` MVP에는 Firebase Authentication의 Google 로그인만 제공한다. API는 Firebase ID token을 검증해 내부 `User.id`에 매핑하며, 내부 ID는 로그인 이름이나 비밀번호가 아니고 사용자가 입력·관리하지 않는다(`D-024`).
- `PR-AC-031` 별도 파일·장치·서비스에 보관하는 백업은 암호화하고, 복구 key는 백업 본체와 분리해 보관한다. 운영 SQLite 파일은 인터넷에 직접 노출하지 않고 전용 서비스 계정의 최소 권한으로 접근한다. DB 저장 암호화는 SQLite의 구체적 지원 방식과 위협을 검토해 결정하며, 정전·재부팅 뒤에는 수동 key 입력 없이 서비스를 시작한다(`D-025`, `D-053`, `D-077`, `NFR-SEC-006`, `NFR-REL-007`).
- `PR-AC-032` 반복 Reminder의 새 회차 예정 시각이 도달하면 이전 `PENDING` 회차를 `MISSED`로 닫고 이력에 보존한다. 새 회차는 원래 반복 일정에 따라 계속 유지한다. 단발 Reminder의 미완료 회차는 시간 경과나 장소 알림 발생만으로 닫지 않고, 사용자가 완료하거나 취소할 때까지 활성 할 일로 표시한다. 시간 Trigger의 단발 회차는 `OVERDUE` 목록에 표시한다(`D-030`).

- `PR-AC-052` MVP는 `ko-KR`과 `en-US` UI·시스템 문구를 제공하고 사용자는 개인 설정에서 언어를 선택할 수 있다. 유효한 저장 사용자 locale이 있으면 우선한다. 저장 선택이 없거나 지원되지 않으면 지원되는 기기 locale을 사용하고, 기기 locale도 지원되지 않으면 `ko-KR`을 사용한다. locale 선택은 서버에 저장해 사용자의 다른 설치에서도 동기화한다. UI 및 시스템 생성 문구는 locale resource/key로 분리하고, API는 안정적인 오류 코드·enum·구조화 값을 반환한다. 날짜·시간·숫자 표현은 사용자 locale/time zone에 맞추며, Reminder 제목·내용 등 사용자 작성 값은 번역하거나 변경하지 않는다(`D-065`, `D-066`, `D-093`).
- `PR-AC-053` 계정 삭제는 재인증과 명시적 확인을 요구한다. 서버는 삭제 시작 즉시 계정 접근을 막고 Firebase identity·프로필·세션·개인 설정·기기 token을 제거한다. Household Reminder·Occurrence·완료·공유 변경 이력은 남기되 삭제 계정의 요청자·행위자·완료자 식별자와 해당 계정의 Assignment만 제거하고 이력에는 `탈퇴한 구성원`으로 표시한다. 다른 담당자와 그 알림은 유지한다. 무담당이 되면 `D-059`, `D-060`을 적용한다. 계정 삭제 뒤 Admin이 0명이 될 가구가 있다면 다른 구성원에게 Admin을 넘기거나 해당 가구를 먼저 종료해야 한다. 계정·기기 정리 신호는 best-effort로 전달하고 다음 접근 때도 정리한다. 계정 삭제 기능은 MVP에서 제외한다(`D-021`, `D-059`, `D-060`, `D-068`).
- `PR-AC-054` Admin은 활성 구성원이 남아 있어도 가구를 종료할 수 있으며 다른 구성원의 동의는 요구하지 않는다. 확인 화면은 현재 구성원 수, 전체 구성원의 접근 회수, 공유 Reminder·회차·이력의 앱 내 복구 불가 삭제를 명시한다. 종료 확정 즉시 초대·API 접근을 차단하고 Reminder·Trigger·Assignment·Recurrence·Occurrence·완료·이력·설정·기기별 동기화·미전달 알림 작업을 운영 DB에서 제거한다. 다른 가구의 사용자 계정은 유지한다. 종료 신호를 받은 앱은 로컬 데이터를 정리하고 한 번 안내하며, 신호를 놓친 앱은 다음 동기화 때 접근 종료 안내와 정리를 한다. FCM 전달 및 force-stop 중 즉시 안내·정리는 보장하지 않는다. 동기화 tombstone과 암호화 백업은 최대 30일 유지하고 복원 전에 종료 표식을 재적용한다. 앱 복원은 불가하며 기술적 보존 세부사항은 개인정보 처리방침에 설명한다. 가구 종료 셀프서비스는 MVP에서 제외한다(`D-058`, `D-068`).
- `PR-AC-055` Reminder 생성 시 작성자는 로그인 사용자로 자동 기록한다. 요청자도 로그인 사용자를 기본값으로 선택하되 같은 가구의 다른 활성 구성원으로 바꿀 수 있다. 담당자 선택에는 로그인 사용자를 기본 포함하고, 같은 가구의 다른 활성 구성원을 추가하거나 제거할 수 있지만 저장 시 담당자는 한 명 이상이어야 한다. 생성 후 요청자와 담당자는 일반 수정 흐름에서 변경할 수 있다(`D-010`, `D-012`, `D-013`, `D-069`).
- `PR-AC-056` 앱을 열면 첫 번째 목록 보기는 `내 할 일`이며 현재 사용자가 담당자인 활성 미완료 회차를 보여준다. 목록 보기 순서는 `내 할 일` → `내가 요청한 일` → `가구 전체 보기`다(`D-072`, `D-076`). 세 보기는 기한 초과·오늘·예정 섹션 순서와 개별 Occurrence 상태 뱃지를 공유한다(`D-036`). 오늘·예정 분류는 사용자의 표시 시간대(`D-065`)를 따르고 각 섹션의 시간 Trigger는 예정 시각이 빠른 순으로 정렬한다. 시간 Trigger가 없는 장소 Reminder는 예정 섹션에 표시한다. `가구 전체 보기`에는 무담당 회차를 포함한 모든 활성 미완료 회차가 표시된다. 완료·놓침·건너뜀 이력과 보관함은 별도 화면에서 조회한다(`D-075`). 앱 진입 기본 화면은 `할 일`이며 세 화면은 주요 내비게이션에서 바로 연다(`D-079`, `PR-AC-064`).
- `PR-AC-057` 시간 알림과 장소 알림은 Android OS에서 별도로 관리할 수 있는 알림 채널을 사용한다. 앱은 알림 권한·채널 상태를 보여주고 OS 설정으로 이동하는 기능을 제공하지만, 채널 on/off와 조용한 시간을 앱 설정에 중복 제공하지 않는다. 앱은 예정 시각에 시간 알림을 게시하고 장소 event 감지 직후 로컬 알림을 게시하며(`D-042`), 최종 표시·소리·방해 금지 적용은 해당 설치의 Android 설정을 따른다(`D-073`).
- `PR-AC-058` 서비스 초기화 담당자는 서버 명령에 지정한 검증 Google/Firebase 계정에 대해 Household 1개와 최초 `ADMIN` Membership 1개를 생성할 수 있다. Household와 Membership는 함께 원자적으로 만들어져야 한다. 이미 초기화된 서비스에서는 명령이 새 Household·계정을 만들지 않고 실패해야 한다. 공개 웹/API는 최초 Admin을 선점하는 가입 경로를 제공하지 않는다. 이후 구성원은 지정 이메일 기반 초대 흐름으로 가입한다(`D-023`, `D-024`, `D-029`, `D-074`).
- `PR-AC-059` Android 사용자 알림은 `VISIBILITY_PRIVATE`로 게시하고 잠금 화면용 일반 `publicVersion`을 제공한다. 앱에는 잠금 화면 원문 공개를 제어하는 중복 설정을 두지 않으며, 실제 표시 수준은 Android OS 사용자 설정을 따른다(`D-026`).
- `PR-AC-060` 가구 구성원 누구나 반복 Reminder의 현재 `PENDING` Occurrence 하나만 건너뛸 수 있다. 해당 회차만 `SKIPPED`로 바꾸며 RecurrenceRule과 다른 회차는 변경하지 않는다. `SKIPPED`는 `COMPLETED`·`MISSED`와 구분해 회차 이력에 남고, AuditEvent에 수행자와 시각을 기록한다. 변경 동기화 뒤 담당자 기기에서 해당 회차의 시간 알람과 지오펜스를 취소한다(`D-010`, `D-031`, `D-075`).
- `PR-AC-061` 두 번째 목록 보기인 `내가 요청한 일`은 `requester_user_id`가 현재 사용자인 활성·미완료 Occurrence를 보여준다. `created_by`가 아니라 요청자를 기준으로 하며, 담당자가 누구인지 또는 지정되지 않았는지와 무관하게 포함한다(`D-069`, `D-076`). 기한 초과·오늘·예정 분류, 시간 Trigger 정렬, 장소 Trigger 표시와 상태 뱃지는 `PR-AC-056`의 규칙을 재사용한다. 완료·놓침·건너뜀 회차와 보관 Reminder는 이 보기에 포함하지 않는다.
- `PR-AC-062` MVP의 NestJS API·Worker 장기 실행 프로세스는 `systemd` 서비스로 등록해 RPi 부팅 시 자동 시작하고 비정상 종료 시 재시작한다. 애플리케이션 로그는 표준 출력·오류로 기록하고 `journald`에서 확인할 수 있어야 한다. 운영자는 서비스 상태와 최근 로그, Caddy 외부 경로로 공개되지 않는 로컬 헬스체크, 디스크·메모리 사용량과 백업 결과를 명령으로 확인할 수 있어야 하며 별도 대시보드는 요구하지 않는다. 애플리케이션 실행환경과 영속 데이터·설정·비밀값을 분리해 추후 Docker Compose 이전을 허용한다. 구체적인 unit, 경로, 헬스체크 및 운영 명령은 `DS-008`에서 정한다(`D-025`, `D-077`, `NFR-REL-007`).
- `PR-AC-063` 세 가지 활성 할 일 보기의 선택 컨트롤은 화면 폭에 맞춰 전환한다. 전체 보기 이름을 나란히 표시할 수 있는 폭에서는 세 보기를 직접 선택하는 버튼으로 표시하고, 좁은 화면에서는 현재 선택된 보기 이름을 보여주는 선택 메뉴로 바꾼다. 두 형태 모두 키보드와 터치로 사용할 수 있고, 현재 선택은 색상만으로 표시하지 않으며, 화면 가로 넘침을 만들지 않는다. 버튼에서 메뉴로 전환하는 정확한 breakpoint는 `DS-002`, `DS-005`에서 정한다. 앱 진입 시 기본 보기는 기존과 같이 `내 할 일`이다(`D-072`, `D-076`, `D-078`, `NFR-UX-001`).
- `PR-AC-064` 주요 내비게이션에서 `할 일`, `이력`, `보관함` 화면을 각각 바로 열 수 있고, 앱 진입 기본 화면은 `할 일`이다. 모바일 주요 내비게이션은 하단에 표시한다(`D-079`). 넓은 화면에서의 배치와 반응형 전환은 `DS-002`, `DS-005`에서 정한다. 세 항목은 키보드와 터치로 조작할 수 있고 현재 화면은 색상만으로 구분하지 않으며 가로 넘침을 만들지 않는다(`PR-AC-043`, `NFR-UX-001`, `NFR-UX-003`).
- `PR-AC-065` 영구 삭제 확인 화면에는 대상 Reminder의 제목과 앱에서 복구할 수 없다는 안내를 표시한다. 사용자가 `영구 삭제`를 명시적으로 한 번 더 선택해야 삭제가 확정된다(`D-084`).
- `PR-AC-066` `DWELL(N)`과 `AFTER_EXIT(N)`의 직접 입력은 정수 분 단위로 1분부터 가구 설정 `max_location_duration_min`까지 허용한다. 초기 상한은 60분이며 Admin은 10~1,440분 범위에서 조정할 수 있다. 빠른 선택은 설정 상한 이하만 노출한다. 설정 상한을 변경해도 이미 저장된 Trigger 값은 자동 변경하지 않으며, duration을 새로 설정하거나 수정할 때 상한을 검증한다(`D-085`, `F-SET-006`).
- `PR-AC-067` Admin은 가구 설정에서 주간 반복 convention을 월요일 시작(`MONDAY_START`), 일요일 시작(`SUNDAY_START`), ISO 8601(`ISO_8601`) 중 선택할 수 있고 초기값은 월요일 시작이다. 첫 주에는 시작일을 포함해 이후의 선택 요일만 회차로 만든다. 새 RecurrenceRule은 생성 시 convention을 저장하며, 설정 변경은 기존 규칙을 이동시키지 않는다. N주 반복은 첫 예정 회차가 속한 주를 anchor로 계산하며 전역 ISO 주차의 홀짝에 의존하지 않는다(`D-083`, `D-086`). `MONDAY_START`와 `ISO_8601`은 현재 회차 날짜 계산 결과가 같고, ISO convention은 ISO week-year 표기를 뜻한다.
- `PR-AC-068` 새 LOCATION Reminder 생성이나 담당자 추가·변경으로 대상 Android 설치 중 하나라도 지오펜스 용량 한도를 넘게 되면 해당 생성·변경 전체를 저장하지 않는다. 화면은 용량이 찬 설치를 알리고 입력·수정 내용을 유지한다. 사용자는 기존 지오펜스를 해당 설치에서만 제거하거나 다른 LOCATION Reminder를 보관·삭제해 슬롯을 확보한 뒤 다시 시도할 수 있다. 기존 geofence 제거 전 대상 Reminder·설치와 그 설치의 장소 감지만 중지된다는 사실을 표시하고 확인을 받는다. 제거 후 해당 Reminder의 상태를 그 설치에서 감시 중지로 표시하고, 사용자가 용량을 확보한 뒤 다시 활성화할 수 있다. 가구 Reminder와 다른 설치는 유지한다. 위치 권한이 거부된 경우는 별개로 `D-044`에 따라 Reminder 저장을 허용하고 해당 설치의 알림 불가 상태를 표시한다(`D-090`).
- `PR-AC-069` Reminder에서 완료 검증을 선택적으로 켜고 다른 가구 구성원을 검증자로 지정할 수 있다. 검증이 켜진 회차는 담당자가 완료를 표시하면 검증 대기로 전환하고, 지정 검증자가 승인하면 완료로 확정되며 거절하면 미완료로 돌아간다. 응답 전에는 검증 대기를 유지한다. 검증자 권한·요청 취소/만료·재알림·복수 담당자 상호작용과 화면·데이터 세부사항은 후속 상세 설계에서 정한다(`Q-063`, `D-091`, `F-REM-009`).
- `PR-AC-070` MVP는 선택적으로 활성화할 수 있는 주간 운영 보고와 즉시 장애 알림을 지원한다. 보고는 매주 제공하고 장애 알림은 장애가 감지되면 즉시 제공한다. 운영자 자격, 보고 내용·기준 시간대, 장애 판정·중복 억제, 수신자·전달 채널·재시도 정책은 후속 상세 설계에서 정한다. 별도 승인 전에는 유료 서비스나 추가 외부 사업자 계정을 요구하지 않는다(`Q-064`, `D-092`, `F-OPS-007`~`F-OPS-008`).

## 7. 구현·기기 검증 사항

현재 열린 질문의 상태는 [사용자 결정 및 질문 등록부](./decision-register.md)에서 관리한다. 질문 원문과 인터뷰 맥락은 해당 인터뷰 기록에 두며, 이 요구사항 문서에는 질문 정의를 복제하지 않는다.

- Android Doze·제조사별 배터리 최적화 동작은 실기기 검증 대상으로 남긴다. 앱은 예외를 직접 요청하지 않고, 확인 가능한 설치 capability와 사용자 설정 안내를 제공한다(`D-051`).
