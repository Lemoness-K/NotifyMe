## 사용자 답변 요약

### Q-011. Android 클라이언트 구현

- 설치형 Android 앱을 사용한다.
- 공유 Web UI는 Capacitor 앱 셸에서 재사용한다.
- 알림과 지오펜싱은 Kotlin 네이티브 기능으로 구현한다.
- 이 구성을 MVP 구현안으로 승인한다.

### Q-012. LAN 밖 동기화 경계

- LAN 밖에서의 즉시 동기화는 요구하지 않는다.
- 휴대폰은 집 LAN에 재접속했을 때 동기화한다.
- 이미 기기에 예약된 시간 알림과 장소 지오펜스는 LAN 밖에서도 계속 동작해야 한다.

### Q-005. household 권한

- household의 모든 참여자는 모든 reminder를 생성·조회·수정·삭제할 수 있다.
- household의 모든 참여자는 모든 reminder를 완료·완료 취소할 수 있다.
- 담당자만 조작할 수 있도록 제한하지 않는다.

## 제품 요구사항 반영

- `F-CLI-002` Android 앱 셸과 `F-CLI-003` Kotlin 네이티브 어댑터를 MVP로 확정한다.
- `F-NOT-002` 시스템 알림, `F-NOT-003` 로컬 시간 예약, `F-TRG-003` 장소 도착 지오펜싱을 앱 UI 비가시 상태의 핵심 경로로 둔다.
- `F-REM-001`~`F-REM-005`의 생성·조회·수정·삭제·완료 권한은 household 참여자 모두에게 부여한다.
- `F-NOT-006`~`F-NOT-007`의 사용자 설정·권한 상태는 Kotlin adapter가 읽고 설정 화면으로 안내한다.
- `D-001`, `D-002`, `D-009`에 따라 RPi API의 외부 공개와 LAN 밖 서버 동기화는 MVP에 포함하지 않는다.

## LAN·오프라인 동작 합의

```text
집 LAN 연결
  └─ 서버 CRUD/동기화 → Android local alarm·geofence reconcile

집 밖 또는 RPi 미접속
  └─ 마지막 동기화된 시간·장소 알림은 계속 동작
  └─ 서버 최신 상태 조회·즉시 변경 반영은 지원하지 않음

집 LAN 재접속
  └─ 마지막 revision 이후 변경 동기화 → local alarm·geofence 재조정
```

기존 로컬 예약의 동작은 RPi가 살아 있거나 인터넷에 연결되어 있는지와 분리한다. 단,
Android OS의 강제 종료, 배터리 최적화, 권한 거부, 제조사별 백그라운드 정책은 플랫폼
제약으로 별도 표시하고 수용 기준에서 허용 범위를 정한다.
