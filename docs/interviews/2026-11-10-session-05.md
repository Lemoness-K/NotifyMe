# Notify Me 설계 인터뷰 — 2026-11-10, 세션 05

- 목적: 남은 MVP 동작 결정을 한 번에 다섯 항목으로 묶어 빠르게 확인한다.
- 기준 문서: [사용자 결정 및 질문 등록부](../decision-register.md)
- 응답 방식: 각 Q에 선택 번호로 답한다. 일부만 답해도 되며 답이 없는 질문은 열린 상태로 남긴다. 독립 결정은 답변 후 영향 문서별로 나눠 반영하고 공통 추적표는 마지막에 함께 정합화한다.

## Q-052 — 완료 이력의 기본 조회 범위

- 맥락: 회차 이력은 가구 단위로 계속 보존하고, 앱의 주요 메뉴에 `이력` 화면을 두기로 했다(`D-031`, `D-079`). 모든 가구 구성원은 리마인더를 조회·관리할 수 있지만 완료 이력 화면의 기본 조회 범위는 아직 정하지 않았다.
- 질문: `이력` 화면에서 기본으로 누구의 완료·놓침·건너뜀 기록을 보여줄까요?
- 추천: 가구의 모든 기록을 함께 보여준다. 공유 업무를 가족이 이어서 확인할 수 있고, 기존 가구 단위 데이터 권한과도 일관된다.
- 선택지: 가구 전체 기록(추천); 현재 사용자가 요청했거나 담당한 기록만; 내 관련 기록을 기본으로 보여주고 가구 전체 기록으로 전환.
- 답변: 이력은 기본으로 내가 담당자인 Reminder를 보여주고, 화면에서 가구 전체 이력으로 전환한다.
- 상태: 해결 — `D-080`, `PR-AC-011`; 조회 시점의 현재 담당자를 기준으로 한다. 화면 표현은 `DS-005`에서 정한다.

## Q-053 — 이력 목록 정렬과 상태 표시

- 맥락: 완료·놓침·건너뜀 기록은 각각 보존되며 별도 이력 화면에서 조회한다(`PR-AC-011`, `PR-AC-056`). 화면에서 상태를 어떻게 묶고 최근 기록을 어떻게 찾을지는 아직 정하지 않았다.
- 질문: 이력 화면의 기본 목록은 어떤 방식으로 보여줄까요?
- 추천: 세 상태를 한 목록에 섞고 가장 최근에 발생한 기록부터 보여준다. 상태 뱃지로 종류를 알아보게 하면 최신 변경을 쉽게 찾으면서 이력 전체도 한눈에 훑을 수 있다.
- 선택지: 완료·놓침·건너뜀 통합 목록, 최신순(추천); 상태별 탭; 상태별 섹션으로 나눈 목록.
- 답변: 추천대로 완료·놓침·건너뜀을 한 목록에 함께 표시하고 최신순으로 정렬한다.
- 상태: 해결 — 상태 발생 시각 기준 정렬은 `D-081`, `PR-AC-011`; 같은 시각 항목의 보조 정렬 기준은 `DS-005`에서 정한다.

## Q-054 — 장소 조건의 시간 입력

- 맥락: 장소 조건은 `진입`, `이탈`, `DWELL(N)`, `AFTER_EXIT(N)` 중 하나를 선택한다. `AFTER_EXIT(N)`은 N분 안에 재진입하면 타이머를 취소하고 다음 이탈부터 다시 센다(`D-014`, `D-016`). N을 만드는 입력 방식은 정하지 않았다.
- 질문: 사용자가 머무름 또는 이탈 후 경과 시간을 어떻게 지정하게 할까요? 선택한 N은 두 시간 조건에서 같은 방식으로 입력한다.
- 추천: 5·10·15·30·60분 빠른 선택과 직접 입력을 함께 제공하고 기본값은 10분으로 둔다. 자주 쓰는 시간을 빠르게 고르면서 다른 시간도 지정할 수 있다. 직접 입력의 허용 범위와 세부 검증은 `DS-006`에서 정한다.
- 선택지: 5·10·15·30·60분 중 선택만(기본 10분); 분 숫자 직접 입력만(기본 10분); 빠른 선택과 직접 입력 함께 제공(추천, 기본 10분).
- 답변: 추천대로 5·10·15·30·60분 빠른 선택과 직접 입력을 제공하고 기본값은 10분으로 한다.
- 상태: 해결 — `D-082`; 직접 입력 범위와 검증은 `DS-006`에 구체화한다.

## Q-055 — 주간 반복 간격의 기준

- 맥락: 주간 반복에서 선택 요일과 반복 간격을 표현하는 도메인 필드는 있지만, `2주마다`처럼 간격이 1보다 클 때 기준 주를 정하지 않았다. 반복 시작 anchor와 회차 생성 규칙도 `DS-010`에서 확정할 항목이다.
- 질문: 예를 들어 격주 월요일 반복은 어떤 주를 기준으로 계산할까요?
- 추천: 첫 예정 회차가 속한 주를 기준으로 N주 간격을 계산한다. 반복이 시작되는 시점과 사용자가 선택한 일정이 직접 연결되고 ISO 주차의 짝·홀수에 좌우되지 않는다.
- 선택지: 첫 예정 회차가 속한 주부터 N주 간격(추천); ISO 달력 주차의 짝·홀수에 맞춤; MVP에는 매주만 제공하고 격주 이상은 후속으로 둠.
- 답변: 추천대로 첫 예정 회차가 속한 주를 기준으로 N주 간격을 계산한다.
- 상태: 해결 — `D-083`, `PR-AC-050`; 주 경계·첫 주 필터링·규칙 수정 후 anchor는 `DS-010`에서 구체화한다.

## Q-056 — 영구 삭제 확인 방식

- 맥락: 가구 구성원은 활성 또는 보관된 Reminder를 영구 삭제할 수 있고, 앱에서는 삭제된 항목이나 회차 이력을 복원할 수 없다(`D-032`, `D-058`, `PR-AC-035`). 삭제 버튼을 누른 뒤 사용자 확인 단계는 아직 정하지 않았다.
- 질문: 영구 삭제 전에 어떤 확인을 요구할까요?
- 추천: 확인창에 Reminder 제목과 앱에서 복구할 수 없다는 점을 보여주고, 사용자가 `영구 삭제` 버튼을 한 번 더 누르게 한다. 실수를 막으면서 제목 입력이나 여러 확인 단계의 부담은 피한다.
- 선택지: 제목과 복구 불가 안내를 보여주는 한 번의 명시적 확인(추천); 확인을 위해 Reminder 제목을 직접 입력; 삭제 전에 별도 확인을 두 번 수행.
- 답변: 추천대로 제목과 앱에서 복구할 수 없다는 안내를 보여준 뒤, 사용자가 `영구 삭제`를 한 번 더 눌러 확인한다.
- 상태: 해결 — `D-084`, `PR-AC-065`; 확인창 세부 구성은 `DS-004`에서 정한다.
