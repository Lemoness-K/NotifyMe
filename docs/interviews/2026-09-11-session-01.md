## 답변이 필요한 질문

### Q-001. 접속 범위와 Raspberry Pi 환경

초기 버전을 집 안의 같은 Wi-Fi에서만 사용할 예정인가, 아니면 두 분이 외출 중일 때도
인터넷으로 접속해야 하는가?

가능하면 다음 환경도 함께 확인한다.

- Raspberry Pi 모델과 RAM
- 운영체제와 32/64비트 여부
- microSD 외 SSD 사용 여부
- 보유 도메인, 공인 IP/DDNS, 포트 포워딩 또는 VPN/터널 사용 경험

영향: HTTPS, 인증 강도, 네트워크 구성, PWA와 웹 푸시, 백업 방식.

### Q-002. 실제 알림과 장소 기능의 기대 수준

MVP에서 필요한 알림 수준은 무엇인가?

- 앱을 열었을 때 오늘/예정/기한 초과 항목을 보는 수준
- 앱을 닫아도 휴대폰에 도착하는 웹 푸시
- 특정 장소에 도착하거나 떠날 때 앱이 닫혀 있어도 울리는 위치 알림

주 사용 기기도 확인한다.

- 두 사람 모두 Android인지, iPhone도 포함하는지
- Chrome 등 특정 브라우저로 제한해도 되는지

영향: PWA만으로 가능한 범위, 외부 Push 서비스 의존, Android 네이티브 앱 필요성.

### Q-003. 사용자·담당자·권한 정책

다음 항목에 대한 원하는 규칙은 무엇인가?

- 두 사람이 반드시 별도 계정으로 로그인하는가?
- 향후 자녀·부모 등 3명 이상을 한 가구 공간에 초대할 계획이 있는가?
- 리마인더 담당자는 한 명인가, 여러 명도 가능한가?
- 만든 사람과 담당자 중 누가 수정, 완료, 완료 취소, 삭제할 수 있는가?
- 삭제해도 완료·변경 기록을 계속 남겨야 하는가?

영향: 계정과 초대, 데이터 모델, 권한 검사, 감사 이력.

## 답변과 파생 결정

### 2026-09-12 사용자 답변 요약

- 초기에는 집 안 Wi-Fi/LAN에서만 사용한다.
- 사용성이 검증되면 DDNS와 포트 포워딩으로 외부 접속을 추가한다.
- 두 사용자 모두 Android를 사용한다.
- 앱 UI가 보이지 않아도 일반 Android 앱처럼 시스템 알림을 받아야 한다.
- 특정 장소에 도착했을 때도 자동으로 알림이 울려야 한다.
- 향후 iOS를 지원할 수 있도록 알림과 시스템 설정을 인터페이스화한다.
- GCM과 같은 원격 전달 방식의 안정성을 기대한다. 현재 제품인 FCM을 후보로 검토한다.

### 파생 결정

- D-001: 1차 운영은 Raspberry Pi 집 안 LAN 우선이다.
- D-002: 외부 접속은 후속 DDNS·포트 포워딩 단계에서 검토한다.
- D-003: MVP 모바일은 Android 2대를 지원하고 iOS는 후속 확장한다.
- D-004: Android 앱 UI가 보이지 않아도 일반 시스템 알림이 와야 한다.
- D-005: 특정 장소 도착을 기기가 자동 감지하여 알림을 표시해야 한다.
- D-006: 알림·로컬 예약·지오펜싱·권한·시스템 설정은 인터페이스/어댑터로 분리한다.
- D-007: 원격 전달 제공자는 GCM 대신 FCM을 후보로 검토하되 도메인에 종속시키지 않는다.
