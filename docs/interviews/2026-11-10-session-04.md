## Q-048 — 최초 Household와 Admin 부트스트랩

- 맥락: MVP는 하나의 Household만 운영하고(Admin/Member 역할은 이미 결정됨), 초대는 기존 Admin이 발급한다. 최초 Household와 첫 Admin을 만드는 방법은 정해지지 않았다.
- 질문: 처음 Household와 Admin은 어떻게 만들까요? 추천은 운영자가 서버 명령으로 지정한 Google 계정을 최초 Admin으로 1회 등록하는 방식입니다. 외부 공개 후 임의의 첫 가입자가 관리자 자리를 선점할 위험과 별도 공개 부트스트랩 화면을 줄입니다.
- 제안 선택지: 서버 명령으로 1회 생성(추천), 일회용 웹 설정 코드, 첫 로그인 사용자가 자동 관리자.
- 사용자 답변: 서버 명령으로 1회 생성(추천).
- 결정: 검증된 지정 Google 계정에 첫 Admin을 연결하고 Household와 Membership를 생성한다. 초기화 뒤 재실행은 실패하며 공개 first-claim 경로는 제공하지 않는다(`D-074`).
- 상태: 해결. 세부 CLI 인자·사전 조건·재실행 오류는 `DS-003`에서 정한다.

## Q-049 — 사용자가 반복 회차를 직접 건너뛰는 규칙

- 발견 맥락: 마스터 기능 트리 `F-REC-006`과 Occurrence 상태 흐름에는 사용자 회차 건너뛰기가 있었지만, 권한·회차 범위·이력·기기 예약 정리 정책이 정해지지 않았다. 시스템이 무담당 때문에 자동으로 건너뛰는 회차(`D-060`)와 원인을 구분해야 한다.
- 사용자 답변: 추천대로 가구 구성원 누구나 현재 회차만 건너뛴다.
- 결정: 반복 Reminder의 현재 `PENDING` Occurrence 하나만 `SKIPPED` 처리한다. RecurrenceRule과 다른 회차는 바꾸지 않는다. 건너뛴 회차는 완료·놓침과 구분하고 수행자·시각을 이력에 남긴다. 변경 동기화 후 담당자 기기의 해당 회차 시간 알람·지오펜스를 취소한다(`D-075`). 이력은 기존 보존 정책(`D-031`)을 따른다.
- 상태: 해결. 화면 동작과 경계 사례는 `DS-005`, `DS-006`, 기기 예약 취소·stale callback 처리는 `DS-011`에서 상세화한다.

## Q-047 — 내가 요청한 일 목록 보기

- 맥락: `내 할 일`은 현재 사용자가 담당자인 활성 미완료 회차를 보여주고, `가구 전체 보기`는 household의 모든 활성 미완료 회차를 보여준다. 요청자와 작성자는 별도 개념이다(`D-069`).
- 질문: `내가 요청한 일`을 MVP에 넣을지, 넣는다면 기존 두 보기와 어떤 순서·범위를 가질지 결정한다.
- 추천: 보기 순서를 `내 할 일` → `내가 요청한 일` → `가구 전체 보기`로 두고, 두 번째 보기는 현재 사용자가 요청자인 활성 미완료 회차를 담당자와 무관하게 표시하며 기존 섹션·정렬을 재사용한다.
- 사용자 답변: `내가 요청한 일`을 두 번째 보기로 넣고 `가구 전체 보기`를 세 번째 보기로 둔다.
- 결정: 추천한 범위와 순서를 MVP에 적용한다. 요청자 ID가 현재 사용자와 같은 활성 미완료 Occurrence를 표시하며, 담당자 유무와 무관하게 포함한다. 목록 구분·정렬·상태 표시는 다른 보기와 공유한다(`D-076`, `PR-AC-061`).
- 상태: 해결. 화면 전환·선택 표시·빈 상태는 `DS-005`에서 상세화한다.

## Q-046 — RPi process 실행과 최소 운영 관측

- 맥락: RPi에서 NestJS API와 Worker를 운영한다. 자동 부팅·재시작은 이미 요구사항이다(`D-025`, `NFR-REL-007`). 실행 감독 방식과 최소 상태·로그 점검법은 미결정이었다. 외부 ingress는 Caddy만 사용하고 관리 포트는 공개하지 않는다.
- 질문: RPi에서 NestJS 장기 실행 프로세스를 무엇으로 시작·재시작하고, 운영자가 서비스 상태·오류 로그·헬스체크·디스크/메모리·백업 결과를 어떤 최소 수단으로 확인할까? 별도 대시보드가 필요한가?
- 추천: MVP는 `systemd` 서비스로 호스트에서 직접 실행하고 부팅 자동 시작 및 비정상 종료 재시작을 설정한다. 앱 표준 출력·오류는 `journald`에서 확인하고, 서비스 상태·최근 로그·로컬 전용 헬스체크·디스크/메모리·백업 결과는 운영 명령으로 점검한다. 대시보드는 두지 않는다. 애플리케이션 실행환경과 영속 데이터·설정·비밀값을 분리해 두면 나중에 Docker Compose로 옮길 수 있다.
- 비교 논의: 사용자는 systemd의 낮은 운영 부담·호스트 직접 실행과 Docker의 배포 이식성을 비교해 물었다. Linux 컨테이너는 호스트 커널을 공유하므로 속도만으로는 선택하기 어렵고, MVP에서는 단일 RPi의 단순 운영이 우선이라는 점을 설명했다. Docker로 이전할 수 있지만 DB 데이터 volume과 설정 분리, 이전 중 백업·복원 및 기동 검증이 필요하다.
- 사용자 답변: 추천한 대로 systemd로 실행한다.
- 결정: MVP의 NestJS 장기 실행 프로세스는 systemd가 관리하며, 앱 로그는 journald로 확인한다. 헬스체크는 외부에 공개하지 않고 운영 점검은 명령 기반으로 한다. MVP에 Docker를 추가하지 않되 추후 이전이 가능하도록 실행환경, 데이터, 설정과 비밀값을 분리한다(`D-077`, `PR-AC-062`, `ADR-038`).
- 상태: 해결. 실제 systemd unit, 권한·경로, 헬스 경로, 운영 명령, 업데이트·백업 검증과 RPi에서의 smoke 절차는 `DS-008`에서 구체화한다.

## Q-050 — 목록 보기 전환 방식

- 맥락: 앱 진입 시 `내 할 일`을 먼저 보여주고, 사용자가 `내가 요청한 일`과 `가구 전체 보기`로 바꿔볼 수 있다(`D-072`, `D-076`, `PR-AC-056`). 세 보기의 순서는 정해졌지만, 모바일부터 데스크톱까지 화면에서 전환 컨트롤을 어떻게 보여줄지는 아직 정하지 않았다.
- 질문: 세 가지 할 일 보기 사이를 어떤 UI로 전환하면 좋을까요? 반응형 화면에서 선택 상태도 한눈에 알 수 있어야 한다.
- 추천: 화면 폭에 따라 탭형 선택 컨트롤과 간결한 선택 메뉴를 전환한다. 넓은 화면에서는 세 보기를 바로 누를 수 있고, 좁은 휴대폰에서는 긴 한글 라벨이 서로 밀리지 않는다. 구체적인 전환 폭과 접근성 동작은 `DS-002`, `DS-005`에서 정한다.
- 선택지: 폭에 따라 탭형 컨트롤/선택 메뉴 전환(추천), 모든 화면에서 탭형 컨트롤 사용, 모든 화면에서 선택 메뉴 사용.
- 사용자 답변: 화면 폭에 맞춰서 전환하도록 한다.
- 결정: 충분한 폭에서는 세 보기 버튼을 나란히 표시하고, 좁은 화면에서는 현재 선택된 보기 이름을 보여주는 선택 메뉴로 바꾼다. 정확한 breakpoint와 접근성 동작은 `DS-002`, `DS-005`에서 정한다(`D-078`, `PR-AC-063`).
- 상태: 해결.

## Q-051 — 완료 이력과 보관함의 진입 위치

- 맥락: 앱 진입 화면은 `내 할 일`이고, 활성 할 일 보기 세 가지의 순서와 반응형 전환 방식은 정해졌다(`D-072`, `D-076`, `D-078`). 완료·놓침·건너뜀 이력과 보관함은 각각 별도 화면에서 조회한다(`PR-AC-056`). Reminder 상세의 이력 버튼은 해당 Reminder의 상태 흐름과 변경 이력을 보여준다(`D-035`). 아직 정하지 않은 것은 완료 이력 목록과 보관함 화면을 앱의 어느 위치에서 여는지다.
- 질문: 사용자가 완료 이력과 보관함을 앱에서 어떻게 찾아가면 좋을까요? 모바일과 넓은 화면 모두에서 현재 위치와 이동 경로를 쉽게 이해할 수 있어야 한다.
- 추천: `할 일`, `이력`, `보관함`을 주요 내비게이션의 바로 가기로 둔다. 모바일에서는 화면 아래쪽 내비게이션을 사용할 수 있고, 넓은 화면에서의 배치는 `DS-002`에서 정한다. 앱을 열었을 때는 계속 `할 일`을 먼저 보여준다. 이 방식은 완료 내역을 돌아보거나 보관한 항목을 복원할 때 진입점을 찾기 쉽다.
- 선택지: 세 화면을 주요 내비게이션에 항상 표시(추천); `할 일`만 주요 내비게이션에 두고 이력·보관함은 할 일 화면 안에서 열기; `할 일`과 `더보기`를 주요 내비게이션에 두고 이력·보관함은 `더보기` 아래에 배치.
- 사용자 답변: 추천한 대로 한다. 앱에 들어오면 `할 일`을 먼저 보여주고, 주요 메뉴에서 `할 일`·`이력`·`보관함`을 바로 열 수 있게 한다.
- 결정: 세 화면을 주요 내비게이션에 항상 제공하고 모바일에서는 하단에 배치한다. 태블릿·데스크톱에서의 정확한 배치와 반응형 전환은 `DS-002`, `DS-005`에서 정한다(`D-079`, `PR-AC-064`).
- 상태: 해결.
