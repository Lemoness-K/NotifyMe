# 요구사항 분석 질문 및 요약 확인

## 질문 결과

이번 단계에서 별도의 제품 범위 질문은 추가하지 않는다. 문서화된 MVP의 동작과 수용 기준은 기존 기준 문서에 정의되어 있고, 새로 승인된 Q-063·Q-064의 범위 포함 여부도 앞 단계에서 결정되었다. 아래 세부 정책은 범위 문서가 후속 상세 설계로 남겨 두었으므로 이 단계에서 임의로 확정하지 않는다.

## 후속 설계에서 다룰 미결정 항목

- **Q-063 — 선택적 완료 검증**: 검증자를 지정할 수 있는 구성원·권한, 검증 대기 요청의 취소·만료·재알림, 반복 회차와의 상호작용, 구체적인 화면·데이터 동작.
- **Q-064 — 운영자 주간 보고 및 즉시 장애 알림**: 운영자 자격, 보고 내용과 기준 시간대, 장애 신호·판정·중복 억제, 전달 채널과 재시도. 비용이나 외부 계정이 필요한 선택은 별도 승인 전까지 전제하지 않는다.
- **테스트 정책 문서 정합성**: Practices Discovery에서 승인한 TDD, 위험 기반 자동 검증, CI 및 80% 전체 라인 커버리지 목표와 `docs/08-test-strategy.md`의 고정 전체 커버리지 기준 미사용 문구를 구현 전 정합화한다. 승인된 팀 실천은 유지하고, 모순을 문서에서 해소한다.

## Consolidated Summary Confirmation

- 이번 작업은 기존 설계 문서를 계속 기준으로 사용하며, 해당 문서를 대체하거나 폐기하지 않는다.
- 기존 문서에 정의된 MVP를 상세 설계하고 구현한다. 계정과 단일 가구, 구성원·권한, Reminder와 회차, 시간·장소 알림, 반복, 목록·이력·보관·삭제, 설정, 접근성·보안·개인정보·운영 요구사항을 포함한다.
- 앞서 승인한 **Q-063 선택적 완료 검증**을 MVP에 추가한다. Reminder별 설정, 담당자의 완료 표시 후 검증 대기, 지정 검증자의 승인 후 완료, 거절 후 미완료 복귀, 미응답 시 검증 대기를 요구사항에 반영한다. 아직 정하지 않은 세부 정책은 열린 상태로 유지한다.
- 앞서 승인한 **Q-064 운영자 주간 보고 및 즉시 장애 알림**을 MVP에 추가한다. 상세 설계에서 정하기로 한 수신자 자격·보고 내용·장애 기준·전달 채널·재시도 정책은 열린 상태로 둔다. 별도 승인 없이 유료 서비스나 새 외부 사업자를 요구하지 않는다.
- 문서에서 MVP 이후로 분류한 기능은 이번 구현에서 제외하고 기존 후속 작업으로 보존한다. 실제 Raspberry Pi 설치, 외부 인터넷 공개, 라우터 포트 개방도 수행 범위에 포함하지 않는다. 배포 준비는 포함한다.
- 보안, 개인정보 보호, 가구 데이터 격리, 시간대와 일정 정확성, 신뢰성, 접근성, 기기 권한 및 플랫폼 경계를 기존 요구사항 수준으로 유지한다. 계획된 기술 스택은 구현 전 검증 대상으로 취급한다.
- 팀 실천으로 승인한 TDD, 위험 기반 테스트, CI, 80% 전체 라인 커버리지 목표를 반영하고, `docs/08-test-strategy.md`와의 문서 모순은 구현 전에 해소한다.
- 요구사항에는 안정적인 기능·비기능 ID를 부여하고, 기존 제품 수용 기준·사용자 결정·열린 질문 및 설계 작업과 추적표로 연결한다. 아직 열린 정책은 임의의 요구사항으로 확정하지 않는다.
