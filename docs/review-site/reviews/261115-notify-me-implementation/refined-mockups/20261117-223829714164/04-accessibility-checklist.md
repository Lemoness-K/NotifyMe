# Notify Me — 접근성 체크리스트

## 목표와 기준 입력

- 목표: 사용자 화면을 WCAG 2.1 AA 성공 기준에 맞춰 설계하고, 구현 단계에서 수동·자동 검증한다. 이 체크리스트는 설계 요구이며 아직 구현 적합성 결과를 뜻하지 않는다.
- `wireframes`: [저충실도 화면 구성](../../ideation/rough-mockups/wireframes.md)
- `user-flow`: [핵심 사용자 흐름](../../ideation/rough-mockups/user-flow.md)
- `stories`: [승인된 사용자 스토리](../user-stories/stories.md)
- `requirements`: [요구사항](../requirements-analysis/requirements.md)
- `team-practices`: [팀 실천](../practices-discovery/team-practices.md)
- 공식 기준: [W3C WCAG 2.1](https://www.w3.org/TR/WCAG21/)

## 뷰포트 폭과 CSS pixel

- 웹 화면의 viewport 너비는 CSS px로 기술한다. CSS px는 화면의 물리 pixel 수나 PPI를 뜻하지 않는다. 브라우저 확대·운영체제 배율·화면의 픽셀 밀도에 따라 화면에 대응되는 물리 pixel 수는 달라질 수 있다.
- 제품은 고정된 기기 종류나 최소 지원 화면 폭을 선언하지 않는다. 화면은 가용 폭, 글자 확대와 한국어·영어 문구 길이에 맞춰 재배치한다.
- WCAG 2.1 AA 성공 기준 1.4.10 Reflow는 일반적인 세로 스크롤 콘텐츠가 320 CSS px 상당 너비에서도 정보 또는 기능 손실 없이 한 방향으로 읽히도록 요구한다. 이 조건은 적합성 확인 viewport다. 제품의 최소 하드웨어 너비나 물리 pixel 목표로 기록하지 않는다. 예외는 사용상 의미가 있는 2차원 콘텐츠에만 한정한다.
- 검증 표본: 320 CSS px 상당 Reflow 검사, 360 CSS px compact 배치 표본, 중간 폭에서 전환 검토, 넓은 폭에서 제한된 본문 폭 검토. 표본은 기기 지원 경계가 아니다.
- 기준 상세: [WCAG 2.1 SC 1.4.10](https://www.w3.org/TR/WCAG21/#reflow), [W3C Reflow 이해](https://www.w3.org/WAI/WCAG21/Understanding/reflow).

## 키보드·초점·포인터

- [ ] 로그인, 주요 내비게이션, 보기 선택, Reminder 생성·수정, 완료·검증, 이력·보관함 동작과 설정을 키보드만으로 실행할 수 있다 (2.1.1 Keyboard).
- [ ] 키보드 초점이 구성 요소 사이에서 논리적인 콘텐츠 순서로 이동하고, 포커스가 화면에서 보이며 sticky header/footer 뒤에 가려지지 않는다 (2.4.3 Focus Order, 2.4.7 Focus Visible).
- [ ] 열리는 선택 메뉴, 프로필 메뉴, 확인 dialog는 열고 닫을 수 있으며 초점을 원래 동작 위치로 돌린다. dialog 안에서만 초점이 순환하고 키보드 사용자가 빠져나오지 못하는 trap은 만들지 않는다 (2.1.2 No Keyboard Trap).
- [ ] 폼은 Tab·Shift+Tab으로 탐색 가능하고 라디오·체크·세그먼트 선택은 표준 키보드 동작을 따른다.
- [ ] 기능 아이콘, 프로필 메뉴, 더보기 동작은 포인터와 터치 외에도 접근 가능한 이름과 키보드 동작을 제공한다.

## 의미·구조·보조 기술

- [ ] 페이지에는 고유한 제목과 논리적 heading 구조가 있다. 제목·목록·내비게이션·폼 그룹·dialog의 관계가 프로그램 방식으로 표현된다 (1.3.1 Info and Relationships, 2.4.2 Page Titled).
- [ ] 폼 입력의 레이블, 필수·선택 상태, 단위와 허용 범위가 프로그램 방식으로 연결된다. placeholder만으로 레이블을 대신하지 않는다 (3.3.2 Labels or Instructions).
- [ ] 할 일, 상태, 담당자와 시각은 각 항목 안에서 읽는 순서가 명확하다. 목록의 상태값은 색상만이 아니라 텍스트로도 전달한다.
- [ ] 이미지가 기능을 전달하면 대체 텍스트를 제공하고, 장식 이미지는 보조 기술에서 제외한다. 아이콘 버튼은 목적을 설명하는 이름을 제공한다.
- [ ] 현재 선택된 할 일 보기와 주 내비게이션 목적지는 시각 표시 외에 접근 가능한 선택 상태를 제공한다.

## 색상·대비·시각 표시

- [ ] 본문 텍스트 대비는 일반 텍스트 4.5:1 이상, 큰 텍스트 3:1 이상을 목표로 검사한다 (1.4.3 Contrast Minimum).
- [ ] 컨트롤의 경계·선택·초점 상태와 의미 있는 그래픽은 인접 색상과 3:1 이상으로 구분되는지 확인한다 (1.4.11 Non-text Contrast).
- [ ] 오류, 성공, 놓침, 건너뜀, 검증 대기와 현재 선택을 색상 하나로 구별하지 않는다. 텍스트, 아이콘, 모양 또는 설명을 함께 쓴다 (1.4.1 Use of Color).
- [ ] 텍스트를 200%까지 확대해도 내용·기능이 잘리거나 겹치지 않는다 (1.4.4 Resize Text).
- [ ] 사용자가 WCAG 1.4.12의 줄 높이·문단 간격·자간·단어 간격을 적용해도 정보와 기능이 사라지지 않는지 검사한다 (1.4.12 Text Spacing).
- 대비 수치는 실제 브랜드 색상 선택 후 측정한다. 이 단계에서는 값이 아직 정해지지 않았으므로 대비 합격을 주장하지 않는다.
- 기준 상세: [WCAG 2.1 SC 1.4.3](https://www.w3.org/TR/WCAG21/#contrast-minimum), [SC 1.4.11](https://www.w3.org/TR/WCAG21/#non-text-contrast).

## 양식 오류·상태 변경

- [ ] 저장 실패와 유효성 오류는 문제가 있는 필드와 연결해 설명한다. 오류를 색상만으로 표시하지 않고, 입력을 수정할 방법을 제시한다 (3.3.1 Error Identification, 3.3.3 Error Suggestion).
- [ ] 오류가 여럿이면 오류 요약과 각 필드 오류를 제공하며 키보드·스크린 리더 사용자가 첫 오류로 이동할 수 있다.
- [ ] 저장·동기화·재시도 결과와 회차 상태 변경은 live region 또는 적절한 상태 메시지로 알리고 초점을 강제로 빼앗지 않는다 (4.1.3 Status Messages).
- [ ] 입력 오류, 네트워크 오류와 geofence 용량 부족 뒤 사용자 입력을 보존한다. 저장 중 버튼 중복 실행을 막되 완료 상태와 실패 이유를 읽을 수 있게 한다.
- [ ] 위치·알림 권한이 거부되어도 기본 조회·Reminder 관리를 계속할 수 있고 현재 Installation의 제한 및 OS 설정 이동을 안내한다.
- [ ] 삭제·복원·완료·검증 결과는 변경 전에 대상과 결과를 이해할 수 있고, 저장 실패를 성공으로 표시하지 않는다.

## 반응형·언어·입력 다양성

- [ ] 320 CSS px 상당 너비에서 세로 콘텐츠에 가로·세로 2차원 스크롤이 함께 필요하지 않은지 확인한다. 업무를 이해하는 데 필요한 2차원 지도·데이터 등 승인된 예외가 아닌 UI 표는 접거나 적절한 대체 표시를 제공한다.
- [ ] 사용 가능한 폭에서 상단/하단 내비게이션과 보기 선택이 겹치거나 잘리지 않고 전환된다. 주 기능이 수평 스크롤 영역 뒤에 숨지 않는다.
- [ ] 소프트 키보드가 입력·저장·취소를 가리면 폼을 스크롤하거나 다시 배치한다. 화면 방향이 바뀌어도 입력과 현재 보기 범위를 유지한다.
- [ ] 긴 한국어·영어 제목, 화면 확대, 사용자 작성 텍스트가 줄바꿈되며 주 동작이나 상태가 잘리지 않는다.
- [ ] `ko-KR`·`en-US` locale 변경이 키보드 초점을 잃지 않고 시스템 문구를 다시 표시한다. 사용자가 작성한 Reminder 제목·설명은 번역하지 않는다.
- [ ] 동작 애니메이션은 상태 변화의 유일한 전달 수단이 아니며, OS의 동작 감소 설정을 존중한다.

## 화면별 확인표

| 화면 | 접근성 확인 |
|---|---|
| 초대·로그인 | 계정 불일치·만료 원인과 복구 안내를 읽을 수 있고, 인증 결과가 초점 순서에서 전달되는가. |
| 할 일 | 현재 보기, 기한 분류, Occurrence 상태, 담당자와 행 동작이 키보드·스크린 리더에서 구분되는가. |
| Reminder 생성·수정 | 필수값·Trigger 유형·단위·범위·오류가 각 입력과 연결되고, 넓이·확대·키보드에서 저장 동작이 노출되는가. |
| 상세·완료 검증 | 진행·대기·승인·거절 상태가 문자로 전달되고 완료나 검증 동작의 결과가 상태 메시지로 알려지는가. |
| 이력 | 완료·놓침·건너뜀과 행위자·시각이 정렬된 읽기 순서로 제공되는가. |
| 보관함·삭제 | 복구 불가 안내가 읽히고, dialog의 초점이 열고 닫힐 때 적절히 이동하는가. |
| 설정 | Household·User·Installation 소유 범위와 현재 언어가 구분되고, OS 설정 링크가 목적을 설명하는가. |

## 추적과 구현 인수 기준

- `NFR-UX-001`, `NFR6.1` 및 `US5.6`은 반응형 리플로우, 다양한 입력 방식과 상태의 비색상 전달을 추적한다.
- `US6.2`–`US6.3`은 locale 선택, 사용자 계정 간 설치 공유, UI 문구의 확장 가능한 리소스와 작성 텍스트 원문 보존을 추적한다.
- `US2.1`–`US2.7`, `US3.1`–`US3.5`, `US4.1`–`US4.7`, `US5.1`–`US5.5`, `US6.1`–`US6.8`, `US7.1`–`US7.2`는 화면별 조작과 상태 보존의 출처다.
- 구현 완료 시 자동 검사만으로 WCAG 적합성을 선언하지 않는다. 화면 낭독기, 키보드, 확대·리플로우, 오류 복구, locale별 긴 텍스트의 수동 검토를 포함한다.

## 열린 범위

- Q-063의 권한·취소·만료·재알림·복수 참여 규칙은 확정 전까지 접근성 검증의 기대 상태를 추가하지 않는다.
- Q-064의 운영 보고·장애 알림 세부 흐름에는 새 화면과 접근성 요구를 이 문서에서 만들지 않는다.
- 브랜드 색상과 서체가 결정되면 대비 검사를 다시 수행한다.
