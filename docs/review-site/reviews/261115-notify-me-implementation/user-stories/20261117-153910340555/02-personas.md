# 페르소나 — Notify Me

## 범위와 기준

이 페르소나는 승인된 요구사항 분석과 사용자 스토리 계획 답변을 구체화한다. 가구 구성원은 하나의 핵심 페르소나이며 `요청자`, `담당자`, `Admin`은 별도 인구 집단이 아니라 그 사람이 맡는 작업 맥락·권한이다. 제품 운영자는 서비스 운영 작업을 수행하는 별도 이해관계자다. Q-064가 해결되기 전까지 운영자의 앱 계정, 운영자 식별·권한, 보고 수신자와 전달 채널을 가정하지 않는다.

스토리의 `US1.1` 형식 ID와 수용 기준의 `AC1.1.1` 형식 ID는 이 AIDLC 기록 안에서 추적하는 단계 ID다. 프로젝트의 canonical 사용자 이야기 ID는 계속 `docs/00-master-design.md`의 `US-NNN`이며, 이 문서가 그 번호 체계를 변경하거나 새 project-wide ID를 부여하지 않는다. 기존 대표 시나리오와 이어지는 관계는 `stories.md`에 표시한다.

## 페르소나 우선순위

| 순위 | 페르소나 | 사용자 유형 | 주요 목표 |
|---|---|---|---|
| 1 | 가구 구성원 | 제품의 주요 사용자. 요청자·담당자 맥락을 모두 가질 수 있고, Admin은 권한이 추가된 역할 변형이다. | 가구 안의 부탁을 분명히 등록·배정하고, 알림을 받아 수행하며, 상태와 이력을 공유한다. |
| 2 | 서비스 운영자 | 서비스와 Raspberry Pi 배포를 관리하는 운영 이해관계자. | 서비스 상태·로그·백업·복구를 확인하고, 승인된 운영 알림 기능을 활용한다. |

## P1 — 가구 구성원

- **역할:** 가족, 동거인, 파트너 등 한 가구의 공유 업무를 이용하는 사람.
- **목표:** 부탁을 빠뜨리지 않고 다른 구성원에게 요청하거나 자신에게 배정된 일을 수행한다. 시간·장소 조건으로 적절한 때 알림을 받고, 완료·보관·이력을 확인한다.
- **어려움:** 대화에서 부탁이 묻히거나 요청자와 담당자가 혼동될 수 있다. 이동 중에는 작은 화면과 간헐적인 권한·네트워크 상태를 접하고, 구성원 변경이나 반복 일정에서 오래된 할 일·알림이 남을 수 있다.
- **맥락:** 반응형 웹과 Android 설치에서 같은 가구 데이터를 사용한다. UI 언어는 사용자 계정 설정이며 다른 설치에서도 동기화된다. 작업 제목과 설명은 작성 언어를 유지한다.
- **권한 변형:**
  - **요청자:** 부탁을 등록하고 요청자 맥락에서 그 상태를 따라간다. 로그인 생성자와 요청자는 서로 다른 의미일 수 있다.
  - **담당자:** 지정된 Reminder를 수행한다. 한 Reminder에 여러 담당자가 있을 수 있으며 완료 주체는 이력에 남는다.
  - **Admin:** 가구 구성원·역할과 가구 소유 설정을 관리한다. 마지막 Admin이 제거되거나 강등되지 않도록 한다.
  - 두 역할 모두 가구 Reminder를 공동 관리한다. 권한의 상세 경계는 승인된 권한 매트릭스를 따르며, 이 문서는 담당자 전용 편집 같은 새 제한을 도입하지 않는다.

## P2 — 서비스 운영자

- **역할:** 계획된 Raspberry Pi 기반 Notify Me 서비스를 배포·운영·복구하는 사람.
- **목표:** 서비스가 자동 시작·복구되는지, 상태와 자원 사용이 어떤지 확인하고 일관된 DB 백업을 만들어 필요하면 복구한다.
- **어려움:** 단일 저비용 장치에서 저장장치·전원·네트워크 장애를 다루며, 공개 관리 화면이나 DB 직접 노출 없이 진단해야 한다.
- **맥락:** 운영 작업은 systemd, 명령, journald, 로컬 헬스체크 등 설계된 운영 인터페이스를 사용한다. 실제 RPi 설치·외부 공개는 이번 작업의 성공 기준이 아니다.
- **미결정 경계:** 주간 보고와 즉시 장애 알림은 승인된 MVP 기능이지만, Q-064가 정한 운영자 식별, 보고 내용·시간대, 장애 판정, 수신자·채널·재시도 세부를 결정하기 전에는 구체적인 운영자 계정이나 전달 흐름을 가정하지 않는다.

## 관계와 우선순위

가구 구성원은 제품 UI의 중심 사용자이고, 서비스 운영자는 제품이 안정적으로 제공되도록 돕는 운영 이해관계자다. 운영자는 household의 Admin이나 일반 구성원으로 간주하지 않는다. 이 기록에서는 UI·일상 업무 흐름의 우선순위를 가구 구성원에 두며, 운영 이야기는 승인된 운영 요구사항과 미결정 정책의 경계를 따른다.
