# ADR-026: 영구 삭제와 백업 보존 기간

- 상태: 승인됨
- 날짜: 2026-11-08
- 관련 결정: `D-031`, `D-032`, `D-053`, `D-058`, `D-075`
- 관련 정책: 계정·가구 종료는 `D-068`. 향후 내보내기는 `D-067`
- 관련 요구사항: `F-REM-004`, `F-OPS-003`, `PR-AC-035`, `PR-AC-060`, `NFR-SEC-006`, `NFR-REL-003`
- 관련 문서: [마스터 설계](../00-master-design.md), [도메인·데이터 설계](../02-domain-and-data-design.md), [배포·운영](../06-deployment-and-operations.md), [보안·개인정보](../07-security-and-privacy.md)

## 맥락

완료·놓침·건너뛴 회차는 사용자가 명시적으로 영구 삭제하지 않는 한 계속 보존한다(`D-031`, `D-075`). 사용자가
Reminder를 영구 삭제하면 활성 업무와 연결 이력을 앱에서 즉시 없애고, 일반 사용자 흐름에서
복구할 수 없어야 한다(`D-032`). 동시에 실수로 삭제했거나 서버 장애가 발생했을 때 제한된 기간에
복구할 여지를 남기고, 늦게 동기화하는 기기에도 삭제 사실을 전달해야 한다.

## 결정

- 영구 삭제 명령은 Reminder, Occurrence, Trigger, Assignment와 사용자 조회용 변경 이력을 운영
  데이터베이스에서 즉시 제거한다. 활성·보관 목록과 기기 예약에서도 동기화 후 제거하며, 앱에서는
  복원 기능을 제공하지 않는다.
- 변경 피드와 늦게 접속한 기기에 삭제를 전달하기 위해 `reminder_id`와 `delete_revision`만 포함한
  tombstone을 생성한다. tombstone은 삭제 시점부터 최대 30일 뒤 만료한다. tombstone 만료 후에는
  full snapshot 동기화로 오래된 기기의 데이터를 정리한다.
- 운영 재해 복구 백업은 암호화하고 접근을 제한해 순환 보관하며 최대 30일 보관한다. 일반 앱이나
  가구 구성원은 백업에 접근하거나 백업에서 직접 복구할 수 없다.
- 정상적인 재해 복구에서는 서비스를 다시 공개하기 전에 유효한 tombstone을 백업 snapshot에
  재적용한다. 이 절차는 영구 삭제된 Reminder가 오래된 백업을 통해 되살아나는 일을 막는다.
- 백업 보존 기간 안의 실수 삭제는 서버 운영자가 승인된 복구 절차로 처리할 수 있다. 이는 앱의
  사용자 복원 기능이 아니며, 백업을 격리된 복구 경로에서 열어 선택한 항목만 복구한다. 작업 때는
  tombstone의 명시적 override와 운영자·시각·사유를 감사 기록에 남긴다. 복구 후에는 새 revision을
  발행하고 관련 기기에 동기화한다.
- 삭제 확인 화면에는 영구 삭제와 연결 이력을 앱에서 복구할 수 없다는 점만 표시한다. 백업 기술
  세부사항은 확인 대화상자에 표시하지 않는다. 상용 서비스 공개 시 개인정보 처리방침에는 백업의
  암호화, 최대 30일 보존, 파기 절차를 이해하기 쉬운 표현으로 설명한다.
- 계정·가구 종료의 동작과 삭제 표식·백업 확장은 `D-068` 및 [ADR-036](./ADR-036-account-and-household-closure.md)을 따른다. 향후 데이터 내보내기는 `D-067`을 따른다.

## 결과

- 앱의 영구 삭제는 즉시 효력을 갖고 사용자 셀프서비스로 취소할 수 없다. 제한된 백업 복구는
  운영자만 수행하는 예외적 재해·실수 복구 경로다.
- 모든 백업 종류와 별도 보관 위치에 30일 상한을 적용해야 한다. 상한을 넘겨 보관하는 별도 복사본은
  만들지 않는다.
- backup restore 절차는 유효한 tombstone을 서비스 시작 전에 적용하고, 그 결과를 검증해야 한다.
- 삭제 tombstone은 DB 접근 권한으로 보호하고, 백업은 암호화·접근 제한을 적용한다. 30일 만료
  작업과 운영자 복구 감사 기록을 유지한다.
- 백업 보유가 개인정보 삭제 의무와 어떻게 맞물리는지는 상용 서비스 출시 전에 실제 처리 방식과
  개인정보 처리방침 문구를 함께 검토한다. 개인정보 보호법은 불필요해진 개인정보를 지체 없이
  파기하고 복구·재생되지 않도록 조치할 것을 규정하며, 개인정보 처리방침에는 처리·보유 기간과
  파기 절차·방법을 포함하도록 한다([제21조](https://www.law.go.kr/LSW/lsLawLinkInfo.do?chrClsCd=010202&lsJoLnkSeq=900078981),
  [제30조](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1025127663)).

## 구현 전 검증

- 반복·단발 Reminder와 연결 이력의 삭제가 하나의 서버 명령으로 멱등 처리되는지 확인한다.
- 유효 tombstone이 포함된 오래된 snapshot을 복원해도 삭제 대상이 노출되지 않는지 확인한다.
- 승인된 수동 복구가 감사 기록과 새 revision을 남기고 연결 기기를 정상 동기화하는지 확인한다.
- 운영 backup, 외부 보관 backup, 별도 복구 사본 모두 30일 안에 만료되는지 확인한다.
