# ADR-037: Reminder 생성 시 요청자·담당자 기본값

- 상태: 승인됨
- 결정일: 2026-11-09
- 결정: `D-069`
- 관련 결정: `D-010`, `D-012`, `D-013`, `D-068`
- 관련 요구사항: `F-REM-001`, `PR-AC-055`
- 관련 문서: [마스터 설계](../00-master-design.md), [제품 요구사항](../01-product-requirements.md), [도메인·데이터 설계](../02-domain-and-data-design.md)

## 배경

대화 중 부탁을 빠르게 등록하려면 매번 요청자와 담당자를 빈 상태에서 선택하게 하지 않는 편이 낫다. 다만 Reminder를 기록한 사람, 부탁한 사람, 실제 담당자는 서로 다를 수 있으므로 이 관계를 분리해 둔다.

## 결정

- `created_by`는 Reminder를 실제로 등록한 로그인 사용자로 자동 기록한다. 이는 작성 이력이며 요청자·담당자와 별도 관계다.
- `requester_user_id`는 기본으로 로그인 사용자로 선택하고, 사용자는 같은 household의 다른 활성 구성원으로 바꿀 수 있다.
- 최초 담당자 선택에는 로그인 사용자를 기본 포함한다. 사용자는 같은 household의 활성 구성원을 추가하거나 제거해 복수 담당자를 지정할 수 있지만, 저장 시에는 한 명 이상 남아 있어야 한다(`D-010`, `D-012`).
- 요청자와 담당자는 생성 후에도 일반 Reminder 수정 흐름에서 변경할 수 있다.
- 알림은 기존 결정대로 활성 담당자 설치에만 전달한다. 요청자가 담당자가 아니면 요청자라는 이유만으로 Reminder 알림을 받지 않는다(`D-013`, `D-045`).

## 결과

- 사용자는 본인에게 부탁하는 Reminder를 기본값을 바꾸지 않고 빠르게 저장할 수 있다.
- 다른 구성원이 부탁한 일을 기록할 때는 요청자를 바꾸고 실제 담당자를 선택할 수 있다. 요청자와 담당자가 같을 필요는 없다.
- 모든 관계는 household의 활성 Membership로 검증하고, 서로 다른 household 사용자 ID는 지정할 수 없다.

## 구현 전 검증

- 작성자는 항상 현재 인증 사용자로 기록되고 임의 입력·대리 변경할 수 없다.
- 신규 생성 화면에서 요청자와 담당자의 기본 선택이 명확히 보이며, 요청자 변경과 복수 담당자 선택이 가능하다.
- 생성 command는 요청자와 모든 담당자가 활성 Membership인지 검증한다.
- Reminder를 수정해 요청자나 담당자를 바꿀 때 기존 권한·AuditEvent·Assignment 이력 규칙을 적용한다.
