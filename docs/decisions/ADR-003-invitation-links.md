# ADR-003: 초대 URL을 통한 가구 가입

- 상태: 승인
- 작성일: 2026-11-04
- 승인일: 2026-11-06
- 관련 결정: `D-020`, `D-021`, `D-023`, `D-027`~`D-029`
- 관련 요구사항: `F-HH-002`, `PR-AC-028`

## 배경

MVP는 한 가구를 운영하며, Admin이 다른 구성원을 가구에 추가할 수 있어야 한다. 구성원이
초대 코드를 따로 복사해 입력하는 과정은 불편하다. Raspberry Pi MVP에 이메일 발송 인프라를
추가하지 않으면서, 링크를 열고 계정을 만들거나 로그인해 가입할 수 있는 흐름이 필요하다.
서버는 인터넷에서 접근 가능하므로 초대 URL token과 초대 대상 계정 인증을 함께 검증해야 한다.

## 결정

1. 활성 Admin은 초대 URL을 생성해 복사·공유한다. MVP는 이메일 발송을 포함하지 않는다.
2. URL은 예측 불가능한 일회용 비밀 코드를 담는다. Admin은 가입자에게 코드를 별도로 입력하게
   하지 않는다.
3. 새 사용자는 링크에서 개인 계정을 만들고, 기존 사용자는 로그인한 뒤 가구 가입을 확정한다.
4. 링크 조회(GET)는 가입 안내만 표시한다. 인증 후 사용자의 명시적인 수락 요청(POST)에서만
   초대 소비와 Membership 생성을 한 transaction으로 처리한다.
5. 만료·취소·사용 여부를 서버에서 검사하고, token 원문은 다시 볼 수 없게 한다. DB에는 token
   hash만 저장한다.
6. 초대 링크는 발급 후 24시간 만료한다(`D-028`). Admin은 대상 Google 이메일을 발급 때 지정하고,
   수락자는 해당 이메일이 확인된 Google 계정으로 로그인해야 한다(`D-029`). URL token만 가진 사람은
   가입할 수 없다. Admin은 링크를 의도한 상대와 공유한다.
7. 초대 수락으로 생성되는 Membership의 역할은 항상 `MEMBER`다. 기존 Admin은 가입 후 별도의 권한 변경 작업으로 해당 구성원을 `ADMIN`으로 승격할 수 있다. 초대 링크 자체는 Admin 권한을 부여하지 않는다(`D-027`).

## 고려한 대안

### 초대 코드를 사용자가 직접 입력

- 장점: 링크 자동 처리보다 단순한 웹 흐름을 만들 수 있다.
- 기각 이유: 사용자가 코드를 복사하고 별도 화면에 입력해야 한다.

### 서버가 이메일 초대장을 발송

- 장점: 수신자를 명확히 지정하고 가입 링크를 전달할 수 있다.
- MVP 보류 이유: 이메일 발송 제공자와 SMTP 자격 증명, 반송·재시도 운영이 필요하다. 링크를
  직접 공유하는 흐름으로 먼저 사용성을 검증한다.

### 링크 열기만으로 즉시 가입 처리

- 기각 이유: 메신저 미리보기와 보안 스캐너가 링크를 자동으로 열어 초대를 소비할 수 있다.
  계정 인증 및 사용자의 수락 POST 뒤에만 가입을 처리한다.

## 결과

### 긍정적

- 수신자는 코드를 입력하지 않고 링크에서 가입·로그인을 진행한다.
- MVP에서 이메일 발송 서비스와 외부 계정 설정이 필요하지 않다.
- 단일 사용, 만료, 취소와 token hash를 통해 재사용과 DB 노출 위험을 제한한다.

### 비용과 위험

- 대상 Google 이메일을 잘못 입력하면 초대가 실패하므로 Admin은 공유 전에 주소를 확인해야 한다.
- 링크와 대상 Google 계정이 함께 노출되면 제3자가 가입할 수 있다. 짧은 만료, 일회용 사용, 취소를 유지한다.
- 초대 코드를 URL에서 처리할 때 browser history, reverse proxy access log, analytics, referrer에
  노출되지 않도록 구현해야 한다.
- token 생성·보관·소비 및 race condition에 대한 서버 검증이 필요하다.

## 검증 조건

- 초대 URL은 활성 Admin만 생성·취소할 수 있다.
- 랜덤 코드는 token 원문으로 저장하거나 로그에 남기지 않는다.
- 링크 GET, 미리보기, 잘못된 로그인은 초대를 소비하지 않는다.
- 인증된 수락 요청 하나만 성공하고, 재사용·만료·취소된 token은 거부한다.
- 초대 대상과 다른 이메일이 확인된 계정으로 수락하면 거부하고 token을 소비하지 않는다.
- Firebase ID token의 Google provider 및 `email_verified`를 서버가 검증한 뒤 초대를 수락한다.
- 초대 수락 후에는 해당 household Membership만 생성되고 다른 household에 접근할 수 없다.
- 초대 수락으로 생성된 Membership는 `MEMBER` 역할로 시작한다. Admin 승격은 기존 Admin의 별도 권한 변경 작업에서만 가능하다(`D-027`).
