# ADR-035: 가구 데이터 내보내기 후속 구현

- 상태: 승인됨
- 날짜: 2026-11-09
- 결정: `D-067`
- 관련 결정: `D-031`, `D-032`, `D-058`
- 관련 기능: `F-HIS-005`
- 관련 요구사항: `PR-AC-033`
- 관련 문서: [마스터 설계](../00-master-design.md), [제품 요구사항](../01-product-requirements.md), [도메인·데이터 설계](../02-domain-and-data-design.md), [보안·개인정보 설계](../07-security-and-privacy.md)

## 배경

사용자는 장기적으로 가구의 리마인더와 이력을 내려받을 수 있는 기능을 고려하되, MVP 구현은 미루기로 했다. 데이터 모델이 이식 가능한 구조를 갖추도록 설계 원칙에 반영할 필요가 있다.

## 결정

- MVP에는 데이터 내보내기 화면, API, 파일 생성 작업을 구현하지 않는다.
- 후속 구현의 초기 후보 포맷은 JSON으로 둔다. 실제 포맷과 schema version은 기능 구현을 구체화할 때 결정한다.
- 도메인 데이터는 정규화된 엔티티 관계와 안정적인 내부 식별자로 관리한다. 업무 데이터를 불투명한 단일 JSON blob에만 의존해 저장하지 않는다.
- 내보내기 대상 범위, 권한(Admin 또는 개인), 보관·완료 이력 포함 여부, 위치 Trigger 좌표, 파일 암호화·다운로드·만료 처리는 구현 전 결정한다.
- 계정 또는 household 종료 시 데이터 삭제·보존 방식은 별도 결정 `D-068`을 따른다. 내보내기 결정을 종료 동작에 자동으로 연결하지 않는다.

## 결과

- 스키마는 향후 데이터를 직렬화할 수 있도록 entity identity와 관계를 유지한다.
- MVP 범위와 운영 부담은 늘리지 않는다.
- JSON export가 구현되기 전까지는 제품 UI에서 다운로드 기능을 제공하지 않는다.

## 구현 확인 사항

- Export를 추가할 때 household tenant 경계를 모든 내보낸 entity에서 검증한다.
- 삭제된 Reminder의 tombstone, 인증 credential, push token, 실시간 GPS 이력은 기본적으로 내보내지 않는다. 필요한 예외나 포함할 위치 Trigger 설정은 당시 개인정보·제품 검토에서 정한다.
- Export artifact의 저장 위치, 전송 암호화, 접근 만료와 삭제를 명시한다.
