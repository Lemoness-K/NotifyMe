# ADR-007: Reminder 상태 표시와 이력 화면

- 상태: 승인됨
- 날짜: 2026-11-07
- 관련 결정: `D-030`, `D-032`~`D-037`, `D-075`
- 관련 요구사항: `F-REM-007`, `F-REM-008`, `F-HIS-003`, `PR-AC-036`, `PR-AC-060`

## 배경

사용자는 목록에서 Reminder의 현재 상태를 빠르게 확인하고, 필요할 때 각 Reminder의 상태 흐름과
변경 이력을 더 자세히 살펴보길 원한다. Jira와 같은 워크플로 편집기보다 먼저 상태를 읽고 과거
변경을 이해할 수 있는 고정 UI 흐름이 필요하다.

## 결정

- 할 일 목록과 상세 화면의 주 상태 뱃지는 개별 Occurrence 진행 상태를 표시한다(`D-036`). Reminder 수명주기와 Occurrence 상태는 별도 축이며, 보관된 Reminder는 보관함에서 수명주기를 확인한다.
- 상세의 이력 버튼은 해당 Reminder의 이력 화면을 연다.
- 이력 화면에는 Reminder 수명주기와 Occurrence 진행 상태를 구분한 고정 상태 흐름 다이어그램, 변경 이력 목록을 함께 보여준다.
- 각 다이어그램은 현재 상태를 강조한다. 사용자 정의 상태나 상태 전이는 MVP에서 제공하지 않는다.
- 변경 이력에는 생성, 주요 Reminder 필드·담당자·Trigger·반복 설정 변경, Occurrence 완료·완료 취소·취소·놓침·건너뜀, Reminder 보관·복원을 기록한다(`D-037`).
- 각 이력 항목은 변경자와 시각, 바뀐 항목 및 변경 전·후 값을 표시한다. 생성 이벤트는 생성된 값을 보여준다. 자동 `MISSED` 및 무담당 회차 `SKIPPED` 전이는 actor를 시스템과 원인으로 표시하고, 사용자가 직접 건너뛴 회차는 해당 구성원과 시각을 표시한다(`D-075`).
- 장소 변경은 장소명과 반경만 이력에 포함하고 정확한 GPS 좌표는 제외한다. 영구 삭제한 Reminder의 이력은 사용자 화면에서 제공하지 않는다.

## 결과

- 두 상태 흐름은 [도메인·데이터 설계](../02-domain-and-data-design.md)의 Reminder 및 Occurrence 상태 모델을 기준으로 한다.
- 현재 상태 뱃지와 상세 이력 화면은 같은 서버 상태 및 변경 이력을 사용해 기기 간 표시가 일치해야 한다.
- `ACTIVE`는 Reminder 정의를, `PENDING`은 개별 Occurrence 진행 상태를 나타낸다. 활성 Reminder가 예정 회차를 갖는 것은 정상이며 목록의 주 뱃지는 Occurrence 상태를 표시한다.
- 사용자에게 보이는 변경 이력은 household 권한으로 보호하는 제품 데이터다. 운영 로그와 분리해 관리한다.
