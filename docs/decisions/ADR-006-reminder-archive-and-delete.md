# ADR-006: Reminder 보관과 영구 삭제

- 상태: 승인됨
- 날짜: 2026-11-06
- 관련 결정: `D-010`, `D-031`~`D-034`, `D-058`, `D-075`
- 관련 요구사항: `PR-AC-002`, `PR-AC-011`, `PR-AC-034`, `PR-AC-035`, `PR-AC-060`

## 배경

사용자는 더는 활성 목록에서 보고 싶지 않은 Reminder를 나중에 되살릴 수 있어야 한다. 반면
삭제를 선택한 경우에는 실수 복원 기능 없이 영구 제거하길 원한다. 완료·놓침·건너뜀 이력은 기본적으로
계속 보존하기로 했지만(`D-031`), Reminder 자체를 명시적으로 영구 삭제하면 연결 이력도
사용자 화면에서 제거할 수 있어야 한다.

## 결정

- `Archive`와 `Permanent delete`를 별도 동작으로 제공한다.
- 보관된 Reminder는 활성 목록에서 제외하고 보관함에 표시한다. 기존 설정과 회차 이력을 유지하고
  가구 구성원이 복원할 수 있다.
- 활성 Reminder 또는 보관함의 Reminder를 영구 삭제할 수 있다. 영구 삭제된 Reminder와 회차
  이력은 제품 UI에서 조회하거나 복원할 수 없다.
- 모든 가구 구성원은 Reminder CRUD 권한에 따라 보관·복원·영구 삭제를 할 수 있다(`D-010`).
- 영구 삭제 시 상세 데이터와 연결 회차 이력은 운영 DB에서 즉시 제거하고, 사용자 화면에서는
  복원할 수 없다. 삭제 확인에는 복구할 수 없는 동작임을 표시하되 백업 보관 세부사항은 넣지 않는다.
- 연결 기기 동기화를 위한 최소 tombstone과 암호화 복구 백업은 최대 30일 보존하며,
  백업 복원 전 삭제 tombstone을 재적용한다. 실수 삭제의 서버 운영자 복구는 일반 사용자 기능과 분리한다(`D-058`).
- 반복 Reminder는 보관 중 기기 알림과 새 회차 생성을 중단한다. 보관 중 지나간 회차는 생성하거나
  `MISSED`로 남기지 않고, 복원 후 다음 미래 회차부터 원래 규칙을 이어간다(`D-033`).
- 보관 시작 전 이미 생성된 `PENDING` 회차는 상태를 유지하고 복원 시 다시 활성화한다. 시간 Trigger가 지났다면 `OVERDUE`로 표시하되 지난 알림은 재생하지 않는다. 장소 Trigger는 다시 등록한다(`D-034`).
- Reminder의 상태 뱃지와 Reminder·Occurrence 상태 흐름 다이어그램·변경 목록은 [ADR-007](./ADR-007-reminder-status-history-view.md)에서 정한다.

## 결과

- UI와 API는 `archive`, `restore`, `permanent delete`를 별도 명령으로 다룬다.
- 영구 삭제 전에 되돌릴 수 없고 완료·놓침·건너뜀 이력도 화면에서 사라진다는 확인을 보여준다.
- 동기화는 archived 상태와 permanent-delete tombstone을 구분해야 한다. 상세 정책은
  [ADR-026](./ADR-026-permanent-delete-and-backup-retention.md)을 따른다.
- Reminder·Occurrence 변경 이력에 표시할 event와 변경자·시각·이전·새 값 범위는 [ADR-007](./ADR-007-reminder-status-history-view.md)의 `D-037`에서 정한다. 영구 삭제된 이력은 사용자 화면에서 제공하지 않는다.
