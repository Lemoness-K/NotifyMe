# ADR-036: 계정 삭제와 가구 종료

- 상태: 승인됨
- 결정일: 2026-11-09
- 결정: `D-068` (`Q-009` 해결)
- 관련 결정: `D-021`, `D-032`, `D-058`, `D-059`, `D-060`, `D-067`
- 관련 요구사항: `PR-AC-033`, `PR-AC-035`, `PR-AC-053`, `PR-AC-054`
- 관련 문서: [마스터 설계](../00-master-design.md), [제품 요구사항](../01-product-requirements.md), [도메인·데이터 설계](../02-domain-and-data-design.md), [보안·개인정보 설계](../07-security-and-privacy.md)

## 배경

계정은 한 사람의 로그인·개인 설정을 나타내고, Household는 여러 사람이 함께 관리하는 Reminder와 이력을 소유한다. 두 개념을 같은 삭제 동작으로 처리하면 한 사람의 탈퇴가 남은 구성원의 업무를 지우거나, 반대로 가구를 끝내도 공유 데이터가 계속 남는 문제가 생긴다. 현재 설계는 가구별 업무 데이터 격리와 계정의 다중 가구 확장을 고려하며, MVP에서는 가구 하나만 사용한다(`D-022`).

## 결정

계정 삭제와 가구 종료를 서로 다른 동작으로 둔다. 계정 삭제는 개인 식별·로그인 데이터를 제거하고 공유 Household의 데이터는 남긴다. 가구 종료는 해당 Household의 공유 데이터 전체를 제거한다. 두 작업은 MVP 구현 범위에는 넣지 않으며, 셀프서비스 기능을 만들기 전 이 정책을 적용한다.

### 계정 삭제

- 삭제 요청은 재인증과 명확한 확인을 요구한다. 서버는 먼저 계정을 `DELETE_PENDING`으로 막아 API 접근과 새 세션을 차단한 뒤 삭제 작업을 멱등적으로 완료한다. Firebase 삭제가 일시 실패하면 접근은 계속 막고 재시도한다.
- Firebase `AuthIdentity`, 내부 프로필, 세션·refresh token, `UserSettings`, `DeviceInstallation`과 FCM token을 제거한다. 개인 정보가 든 모든 공유 데이터 참조(요청자, 생성·수정자, 완료자, 이력 행위자, 초대 행위자 등)는 사용자 ID와 표시 이름을 지운다. 필요한 과거 행만 남을 때는 User FK 없이 `탈퇴한 구성원`으로 표시하도록 한다. 관련 FK는 삭제 뒤 null 또는 익명 행을 허용하도록 설계한다.
- 계정 삭제 후 활성 Admin이 0명이 될 Household가 있으면 사용자는 다른 구성원에게 Admin을 넘기거나 해당 Household를 종료해야 한다(`D-021`). 삭제할 사용자가 마지막 구성원인 Household는 가구 종료와 계정 삭제를 함께 수행하고, 공유 데이터 삭제를 별도로 확인받는다.
- 사용자의 모든 Household Membership를 비활성화하고 그 사용자의 활성 Assignment만 종료·익명화한다. 같은 Reminder의 다른 담당자 Assignment와 알림은 그대로 유지한다. 담당자가 남아 있지 않으면 현재 및 이미 미리 생성된 회차를 보존하고 trigger·알림·새 회차 생성을 멈춘다. 재지정 시 현재 회차는 유지하고, 그 뒤 이미 생성된 과거 회차는 `SKIPPED`·`NO_ACTIVE_ASSIGNEE`로 기록하며 무담당 기간의 미생성 회차는 보충하지 않고 미래 회차부터 재개한다. 현재 회차는 다음 반복 시각까지 미완료면 기존 규칙대로 `MISSED` 처리한다(`D-059`, `D-060`).
- 사용자의 기기에는 계정 삭제·접근 회수 control signal을 가능한 경우 먼저 발행한 뒤 기기 token을 제거한다. 신호를 놓친 설치도 다음 실행 때 계정 접근 거부를 확인하면 관련 캐시와 로컬 알람·geofence를 정리한다. FCM 신호와 force-stop 중 로컬 정리는 best-effort다. 서버는 삭제 완료 뒤 해당 계정의 기기 token을 보유하지 않는다.
- 과거 Reminder, Occurrence, 완료 기록과 공유 변경 이력은 남은 가구 구성원이 계속 사용할 수 있게 유지한다. 변경 전·후 업무 값도 보존하지만, 삭제한 사람은 이력 화면에서 `탈퇴한 구성원`으로만 표시한다.
- Household의 Reminder는 특정 작성자 소유가 아니라 가구 공유 데이터로 취급한다. 계정 삭제만으로 그 사람이 만들었던 Reminder를 함께 삭제하지 않는다. 사용자가 특정 Reminder도 지우려면 기존 영구 삭제 동작을 별도로 사용한다(`D-032`, `D-058`).

### 가구 종료

- Admin은 다른 활성 구성원이 있더라도 가구 종료를 실행할 수 있다. 다른 구성원의 동의는 요구하지 않는다. 확인 화면에서 구성원 수와 모든 구성원의 접근 상실 및 공유 데이터 삭제를 알리고 명시적으로 재확인한다. 마지막 Admin 보호 규칙(`D-021`)과 별개의 종단 동작이다.
- 종료가 확정되면 즉시 household 접근을 거부하고 초대 링크를 무효화한다. household 폐쇄 상태와 ID/revision만 든 household-level tombstone을 먼저 기록하고, 해당 가구 구성원 기기에 종료 signal을 best-effort로 전송한다. signal을 받은 앱은 로컬 캐시·알람·geofence를 정리하고 한 번 종료 안내를 표시한다. signal을 놓치면 다음 실행 때 동기화 후 가구 접근 종료 안내를 표시하고 같은 정리를 한다. FCM 전달 및 force-stop 중 즉시 정리는 보장하지 않는다.
- Reminder, Recurrence, Occurrence, Trigger, Assignment, 완료·변경 이력, 설정, 초대, household별 DeviceTrigger·SyncState, ChangeFeed·Outbox·미전달 알림 작업 등 해당 household 소유 데이터를 운영 DB에서 제거한다. 다른 household에도 속한 사용자 계정과 기기 설치 자체는 유지하고, 닫힌 household와 연결된 로컬 상태만 제거한다.
- 다른 구성원이 있는 경우 종료를 시작한 Admin이 종료 영향과 구성원 수를 확인하도록 한다. 종료가 확정된 뒤에는 남은 구성원도 해당 household에 접근할 수 없다.
- 사용자 화면에는 가구와 공유 데이터가 삭제되고 앱에서 복구할 수 없다는 점을 알린다. 서버 동기화 tombstone과 암호화 재해 복구 백업은 기존 최대 30일 정책에 맞춰 운영하고, tombstone을 백업 복원 전에 재적용한다(`D-058`). 이 기술적 유예 기간은 삭제 확인 UI에 노출하지 않고, 서비스 개인정보 처리방침의 보유·파기 설명에 포함한다.
- `D-068`은 Reminder에 한정된 기존 삭제 표식(`D-058`)을 계정·household 종료까지 확장한다. 동기화·복원 표식은 entity 종류, 안정 ID, 삭제 revision만 담고 이름·이메일·인증 provider 식별자는 포함하지 않으며 최대 30일 뒤 만료한다.
- 데이터 내보내기는 MVP에 없으므로 종료 확인 전에 현재 내보내기 기능이 제공되지 않는다는 점을 알린다. 향후 내보내기 기능이 구현되면 종료 전 내보내기를 제공할지 그 시점의 설계에서 정한다(`D-067`).

## 결과 및 유의점

- 개인 계정 제거와 가구 공유 기록 보존을 분리하므로, 한 구성원의 탈퇴가 남은 구성원의 할 일을 없애지 않는다.
- 공유 이력은 유지하면서 직접 식별자와 행위자 연결을 지운다. Reminder 본문이나 변경 값 자체에 개인 정보가 들어 있을 수 있으므로 계정 삭제가 Household 공유 데이터 전체의 삭제를 뜻하지 않는다는 점을 UI에서 구별하고, 실제 서비스 공개 전에 관련 보유·삭제 처리와 개인정보 처리방침을 검토한다.
- 계정 삭제 요청, 공유 이력의 익명화, Firebase·FCM 데이터 및 운영 백업은 개인정보 보호법의 파기·삭제 요구 조항과 함께 검토한다. 이 ADR은 법률 적합성을 단정하지 않으며, 상용 공개 전 실제 데이터 흐름과 고지 문구를 별도로 확인한다([제21조](https://www.law.go.kr/LSW/lsLawLinkInfo.do?chrClsCd=010202&lsJoLnkSeq=900078981), [제36조](https://law.go.kr/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1029335317)).
- 계정·가구 삭제는 멱등 작업으로 구현한다. Firebase 연결 해제 실패는 재시도하며, household 종료 transaction은 접근 차단·초대 폐기·tombstone·ChangeSignal/outbox와 업무 데이터 제거를 일관되게 처리한다.
- User 삭제 단계의 재시도·부분 실패가 발생해도 `DELETE_PENDING` 계정은 다시 인증·사용될 수 없으며, 성공 완료 뒤 모든 직접 식별자와 provider mapping이 운영 DB에서 제거되는지 확인한다.
- 삭제 tombstone과 백업 보존은 기존 Reminder 영구 삭제 정책과 동일한 상한을 적용한다. 백업 복구가 계정이나 종료된 Household를 되살리지 않도록 복원 전 삭제 표식을 재적용한다.
- 이 결정으로 `Q-009`를 해결한다. 계정·가구 삭제 기능 자체는 후속 셀프서비스 구현 범위로 두고, 데이터 모델과 운영 복원 절차는 이 정책을 지원해야 한다.

## 구현 전 검증

- 계정 삭제 때 직접 식별자와 인증·기기 자격 증명이 제거되고, 공유 업무·완료 이력은 탈퇴자 이름 없이 계속 조회되는지 확인한다.
- 삭제한 사용자의 Assignment만 종료되어 다른 담당자와 그 알림은 유지되는지 확인한다. 마지막 담당자가 사라지면 현재·미리 생성된 회차를 보존하고 trigger/알림과 회차 생성을 멈춘다. 재지정 때 현재 회차를 유지하고 이미 지난 후속 회차는 `SKIPPED`로 남기며 미래 회차부터 재개하는지 확인한다(`D-059`, `D-060`).
- 마지막 Admin은 역할 인계 없이 계정만 삭제할 수 없으며, 유일한 구성원의 결합 종료는 household 데이터 제거까지 원자적으로 처리되는지 확인한다.
- 가구 종료 뒤 API·초대·로컬 알람·geofence·ChangeFeed·Outbox·미전달 알림 작업이 차단·제거되고, 다른 Household를 가진 사용자 및 그 household별 기기 연결에는 영향이 없는지 확인한다.
- 최대 30일 안에 tombstone·백업이 만료되며, 그 전에 복원하더라도 계정 삭제와 가구 종료가 재적용되는지 확인한다.
