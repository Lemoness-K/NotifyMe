# ADR-010: 장소 조건 감지 직후 로컬 알림 표시

- 상태: 승인
- 날짜: 2026-11-08
- 관련 결정: `D-004`, `D-005`, `D-006`, `D-041`, `D-042`, `D-075`
- 관련 요구사항: `PR-AC-016`, `PR-AC-060`, `F-NOT-005`

## 맥락

장소 조건 event는 휴대폰 OS의 geofence callback으로 먼저 인식된다. 알림 표시를 서버 동기화나
push 전달에 묶으면 네트워크·서버·FCM 처리 시간만큼 사용자가 기다리게 된다. 사용자는 장소 조건이
감지되는 즉시 알림을 원한다.

## 결정

기기가 유효한 장소 조건 event를 인식하면 앱은 Android 로컬 시스템 알림을 즉시 게시한다. 해당
처리 경로는 서버 요청, DB 동기화 완료, FCM/APNs 응답, push 재시도 또는 batch 처리 완료를 기다리지
않는다. 알림을 표시한 뒤 event journal과 서버 기록은 별도로 동기화한다.

“즉시”는 OS가 앱에 조건 event를 전달한 뒤 앱이 추가 지연을 두지 않는다는 뜻이다. Android의
백그라운드 geofence callback 자체는 OS 스케줄링, 위치 서비스, GPS/네트워크 위치 조건에 따라
늦어지거나 누락될 수 있으므로 감지 시각에 대한 고정 SLA는 약속하지 않는다.

알림은 `D-041`의 조건을 따른다. 즉 Reminder가 활성이고 Occurrence가 `PENDING`인 동안 새 조건
event마다 한 번 게시하며, 완료·취소·놓침·건너뛴 회차 또는 보관된 Reminder에는 추가 게시하지 않는다(`D-075`).
동일 event의 재처리는 결정적 OS notification ID와 로컬 event journal로 중복 표시하지 않는다.

## 결과

- 서버·네트워크 장애가 있어도 기기가 감지한 장소 조건은 기기 로컬 알림으로 바로 사용자에게 보인다.
- event sync와 감사·진단 기록은 네트워크 복구 뒤 재시도할 수 있고, 서버 기록은 로컬 알림 표시를
  지연시키지 않는다.
- 제품은 Android의 장소 감지 시간을 보장하지 않는다. 플랫폼 감지 지연과 앱 내부 알림 처리 지연을
  구분해 상태·문구를 설계한다.
- 위치 event에 저장할 metadata와 30일 보존 기간은 `D-043`에서 정한다.
