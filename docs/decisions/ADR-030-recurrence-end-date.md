# ADR-030: 반복 Reminder의 선택 종료일

- 상태: 승인됨
- 날짜: 2026-11-09
- 결정: `D-062`
- 관련 결정: `D-030`, `D-061`
- 관련 기능: `F-REC-004`
- 관련 요구사항: `PR-AC-048`
- 관련 문서: [마스터 설계](../00-master-design.md), [제품 요구사항](../01-product-requirements.md), [도메인·데이터 설계](../02-domain-and-data-design.md), [알림·스케줄링](../04-notification-and-scheduling.md)

## 배경

집안일처럼 종료되지 않는 반복 작업도 있지만, 일정 기간만 필요한 반복 작업도 있다. 종료일이 없을 때
무기한 반복을 기본으로 하되 사용자가 필요하면 종료일을 정할 수 있어야 한다. 반복 횟수 제한은 초기
버전에 꼭 필요한지 확인되지 않았다.

## 결정

- 반복 Reminder는 종료일을 비워 둘 수 있으며, 이 경우 반복 규칙이 유지되는 동안 계속 반복한다.
- MVP는 선택 종료일을 제공한다. 종료일은 RecurrenceRule의 `time_zone`으로 해석되는 local date이며,
  종료일 당일 예정 회차까지 생성한다. 종료일은 시작일 또는 시작 예정일보다 이르지 않아야 한다.
- 종료일보다 뒤인 반복 후보에는 Occurrence와 기기 알림 trigger를 만들지 않는다. 종료일 당일을 포함한
  회차들이 끝나면 반복 스케줄링은 추가 회차를 만들지 않는다.
- 종료일 경과는 Reminder 수명주기를 바꾸지 않으며, 마지막 미완료 회차를 자동 완료·취소·`MISSED`로
  바꾸지 않는다. 해당 회차는 기존 규칙에 따라 사용자가 완료하거나 취소할 때까지 유지한다.
- 반복 횟수(`max_count`) 제한은 MVP에서 제공하지 않는다.

## 결과

- 반복 설정 UI에는 `종료일 없음`이 기본값으로 표시되고, 사용자가 선택 종료일을 추가할 수 있다.
- API와 Worker는 종료일을 규칙의 시간대로 검증하고 종료일 이후 후보 materialization과 trigger 생성을
  차단한다.
- 종료일이 지나도 Reminder 자체는 활성 목록에 남을 수 있으며 마지막 미완료 회차를 계속 처리할 수 있다.
- 완료된 반복 회차와 종료된 규칙은 기존 이력 보존 정책을 따른다.

## 구현 시 확인 사항

- 종료일 없는 반복은 계속 다음 회차를 만든다.
- 선택 종료일 당일에 예정된 회차는 생성하고, 그 이후 회차는 만들지 않는다.
- 서로 다른 사용자 시간대가 아니라 RecurrenceRule의 `time_zone`을 기준으로 종료일을 판정한다.
- 마지막 미완료 회차는 종료일을 넘겨도 자동으로 완료되거나 놓침 처리되지 않는다.
- 종료일 이후에는 local alarm과 geofence trigger를 새로 설치하지 않는다.
