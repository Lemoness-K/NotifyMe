# Notify Me 사용자 결정 및 질문 등록부

- 문서 상태: 기준 문서 v1.13
- 작성일: 2026-11-10
- 최근 갱신일: 2026-11-17
- 기준 시간대: Asia/Seoul
- 목적: 확정된 사용자 결정(`D-NNN`)과 모든 질문 ID(`Q-NNN`)의 정의·현재 상태를 제공한다.

## 문서 역할과 기록 기준

- [마스터 설계](./00-master-design.md)는 제품의 목표, 기능 트리, MVP 범위, 전체 설계 방향을 설명한다.
- 이 문서는 결정 ID와 질문 ID의 현재 기준 상태 및 결정 내용을 관리한다.
- [Architecture Decision Record](./decisions/) 문서는 주요 기술 결정의 배경, 대안, 결과를 상세히 설명한다.
- [인터뷰 기록](./interviews/)은 질문의 최초 표현, 대화 맥락, 답변을 시간순으로 보존한다. 인터뷰 기록의 당시 미결정 표시는 현재 상태와 다를 수 있으므로, 최신 상태는 이 등록부를 따른다.
- 질문은 해결되거나 범위에서 제외된 뒤에도 질문 ID 이력 색인에 남긴다. 색인에서 주제, 현재 상태, 연결된 `D-NNN`/`DS-NNN`, 인터뷰 원문을 추적한다.
- 세부 설계 문서는 결정·질문 내용을 복제하지 않고 해당 ID와 이 등록부를 참조한다.

## 확정된 사용자 결정

- `D-001` [폐기: D-011] 1차 배포는 가정 내 LAN 전용이었다.
- `D-002` [폐기: D-011] 외부 접속을 후속 단계에 추가하기로 했었다.
- `D-003` MVP 모바일은 Android 2대를 지원하고 iOS는 후속 확장한다.
- `D-004` 앱 UI가 보이지 않을 때도 일반적인 Android 시스템 알림을 받아야 한다.
- `D-005` 특정 장소 도착을 기기가 자동 감지하여 알림을 표시해야 한다.
- `D-006` 원격 전달, 로컬 예약, 지오펜싱, 권한·시스템 설정은 플랫폼 중립 인터페이스 뒤에 둔다.
- `D-007` GCM의 후속인 FCM을 원격 전달 후보로 검토하되 도메인이 FCM SDK에 의존하지 않게 한다. 실제 사용 범위는 변경 동기화 신호로 제한했다(`D-046`).
- `D-008` MVP는 Capacitor 공유 Web UI와 Kotlin 네이티브 어댑터를 포함한 설치형 Android 앱으로 만든다.
- `D-009` [폐기: D-011] LAN 밖 즉시 동기화 제외 방침이었다.
- `D-010` 같은 가구 공간의 모든 참여자는 모든 리마인더를 생성·조회·수정·삭제·완료·완료 취소할 수 있다.
- `D-011` MVP부터 집 안팎에서 Raspberry Pi 서버에 상시 네트워크 연결이 가능하다고 가정하고, HTTPS로 조회·변경·동기화한다. D-001, D-002, D-009를 대체한다.
- `D-012` 리마인더 하나에 여러 명을 담당자로 지정할 수 있다.
- `D-013` 담당자가 여러 명이어도 가구 구성원 한 명이 완료하면 해당 업무 회차 전체가 완료된다. 같은 일을 각자 완료해야 하면 사람별로 별도 리마인더를 만든다.
- `D-014` 장소 알림은 진입, 이탈, 일정 시간 이상 머무름, 이탈 후 일정 시간 경과 중 하나를 알림 기준으로 설정한다. GPS 오차는 불가피하다. 사용자가 말한 시간과 장소 이벤트의 "조합"은 논리식(AND/OR) 요구가 아니다.
- `D-015` 각 Reminder에는 시간(`TIME`) 또는 장소(`LOCATION`) Trigger 중 하나만 설정한다. 시간 기준과 장소 기준을 한 Reminder에 함께 설정하지 않는다. 장소 Trigger도 진입·이탈·머무름·이탈 후 경과 중 하나를 선택한다.
- `D-016` `AFTER_EXIT(N)` 알림 대기 중 장소에 재진입하면 대기 타이머를 취소한다. 다시 이탈하면 그 시점부터 N분을 새로 센다.
- `D-017` 장소 Trigger의 반경은 Reminder별로 미터 단위로 저장하며, 생성·수정 화면에서 기본값을 보여주고 슬라이더로 조정할 수 있다. 슬라이더 범위는 가구 옵션을 따르며 초기 범위는 `D-038`, MVP 조정 간격은 `D-039`에 따른다.
- `D-018` 별도 앱 설정 화면의 가구 설정에서 장소 반경 최소값·최대값·기본값을 설정한다. 초기 기본값은 100m다.
- `D-019` 설정값은 `HOUSEHOLD`, `USER`, `INSTALLATION`, `REMINDER` 중 정확히 하나의 소유 범위에 둔다. 전역 설정 화면은 household·user 설정과 설치별 상태를 구분하고, Reminder 범위 값은 Reminder 생성·수정 흐름에서 다룬다. 설정 메타데이터는 중앙 설정 카탈로그에 한 번 선언하고 실제 값은 소유자별 저장 위치에 둔다. `USER` 값은 `user_id`에 귀속되어 해당 사용자 설치들에 적용하고, OS 소유 `INSTALLATION` 값은 다른 scope로 복제하지 않는다.
- `D-020` 가구 구성원 역할은 관리자(`ADMIN`)와 멤버(`MEMBER`)로 나누며 각 역할에 여러 명을 둘 수 있다. 가구 설정과 멤버 관리는 관리자만 변경하고, 관리자와 멤버 모두 모든 리마인더를 CRUD·완료할 수 있다.
- `D-021` 활성 가구에는 Admin이 최소 한 명 있어야 하고 Member는 0명 이상일 수 있다. 마지막 Admin이 나가거나 Member로 강등되기 전에 다른 구성원에게 Admin 역할을 넘겨야 하며, 인계와 기존 Admin 변경을 한 번의 원자적 처리로 수행한다.
- `D-022` MVP는 하나의 가구만 운영하고 추가 가구 생성·전환 UI는 제공하지 않는다. 데이터 모델은 User·Household·Membership를 분리해 사용자와 가구의 다대다 관계 및 `household_id` 격리를 유지하고, 다중 가구 기능은 서비스 출시를 고려할 때 추가한다([ADR-002](./decisions/ADR-002-household-scope.md)).
- `D-023` Admin이 일회용 코드를 포함한 초대 URL을 발급해 공유한다. 초대 대상자는 URL로 가입·로그인한 뒤 코드를 직접 입력하지 않고 가구 가입을 완료한다. 링크는 만료되고 한 번만 사용할 수 있으며, MVP에는 링크 복사·공유만 제공하고 이메일 발송 서비스는 추가하지 않는다([ADR-003](./decisions/ADR-003-invitation-links.md)).
- `D-024` MVP 로그인은 Firebase Authentication의 Google provider로 처리한다. 별도 내부 ID·비밀번호 로그인은 제공하지 않는다. 시스템은 Firebase identity를 내부 `User.id`에 매핑하며, 내부 ID는 업무 데이터 관계와 권한 검사에만 사용한다([ADR-004](./decisions/ADR-004-google-authentication.md)).
- `D-025` MVP 보안은 인터넷을 통한 계정·API·데이터 접근을 위협 모델로 삼고, 물리적 기기 탈취와 오프라인 저장장치 열람은 범위에서 제외한다. 정전·재부팅 뒤 RPi 서비스는 사람의 수동 key 입력 없이 자동 시작해야 한다. 전체 디스크 암호화는 필수로 두지 않으며, DB 저장 암호화는 선택한 DB와 구체적인 위협에 맞춰 결정한다. 별도로 보관하는 백업은 암호화한다. 이에 따라 `Q-031`을 해결한다.
- `D-026` 잠금 화면 알림 공개 여부는 Android OS의 사용자 설정이 최종 결정한다. Notify Me에는 이를 중복하는 별도 개인 설정을 두지 않는다. 앱은 민감 알림을 `VISIBILITY_PRIVATE`로 만들고 Android가 잠금 화면에 대신 표시할 일반 문구(`publicVersion`)를 제공한다. Android 알림 설정 화면으로 이동하는 안내를 제공한다. 이에 따라 `Q-015`를 해결한다.
- `D-027` 초대 링크로 가입한 구성원은 항상 `MEMBER` 역할로 추가한다. 가입 후 기존 Admin이 확인한 뒤 필요하면 별도로 `ADMIN`으로 승격한다. 초대 URL은 Admin 권한을 직접 부여하지 않는다. 이에 따라 `Q-027`을 해결한다.
- `D-028` 초대 링크는 발급 시각부터 24시간 동안 유효하며, 수락·취소·만료 시 가입에 사용할 수 없다. 이에 따라 `Q-028`의 유효기간 부분을 해결한다.
- `D-029` Admin은 초대 발급 때 대상 Google 이메일을 지정한다. 수락 요청은 Firebase ID token이 유효하고 Google provider로 인증됐으며 `email_verified`가 참이고 token의 이메일이 초대 대상과 일치할 때만 성공한다. 이메일 불일치 요청은 초대를 소비하지 않는다. 이에 따라 `Q-028`을 해결한다.
- `D-030` 다음 반복 회차의 예정 시각에 도달했을 때 이전의 미완료 반복 회차를 `MISSED`로 닫고 이력에 남긴다. 단발 Reminder의 미완료 회차는 시간 경과나 장소 알림 발생만으로 자동 종료하지 않고 사용자가 완료하거나 취소할 때까지 활성 할 일로 계속 보여준다. 시간 Trigger 단발 회차는 `OVERDUE`로 표시한다. `Q-007`을 해결한다.
- `D-031` 완료·놓침·건너뛴 회차 이력은 명시적 영구 삭제가 적용되는 경우를 제외하고 연령에 따른 자동 삭제 없이 계속 보존한다. 저장 공간이 부족해지면 그때 대안을 검토한다. 계정·가구 종료 시에는 `D-068`에 따라 공유 데이터 유지 또는 전체 제거를 처리하고, 데이터 모델은 후속 내보내기를 고려한다(`D-067`)([ADR-005](./decisions/ADR-005-completion-history-retention.md)).
- `D-032` 리마인더는 `ACTIVE`, `ARCHIVED`, `PERMANENTLY_DELETED` 수명주기를 가진다. 보관은 기록을 유지하고 보관함에서 복원할 수 있지만, 영구 삭제는 활성 목록이나 보관함 어디서든 실행할 수 있고 회차 이력까지 사용자 관점에서 즉시 제거하며 사용자가 복원할 수 없다. 상세 데이터·기기 동기화·백업 정리는 `D-058`을 따른다([ADR-006](./decisions/ADR-006-reminder-archive-and-delete.md)).
- `D-033` 반복 Reminder는 보관 중 알림과 새 회차 생성을 멈춘다. 보관 중 지나간 회차는 새로 만들거나 `MISSED`로 남기지 않고, 복원하면 기존 반복 규칙의 다음 미래 회차부터 재개한다.
- `D-034` 보관 시작 전에 이미 생성된 `PENDING` 회차는 보관해 두었다가 복원 시 그대로 다시 활성화한다. 시간 Trigger의 예정 시각이 지났다면 `OVERDUE`로 표시하고 과거 알림은 재생하지 않는다. 장소 Trigger는 복원 후 다시 등록한다.
- `D-035` 상세의 이력 버튼을 누르면 Reminder 수명주기와 Occurrence 진행 상태를 구분한 고정 상태 흐름 다이어그램, 각 흐름의 현재 상태 강조, 변경 이력 목록을 보여준다. MVP에서는 상태나 전이를 사용자 정의하지 않는다([ADR-007](./decisions/ADR-007-reminder-status-history-view.md)).
- `D-036` 목록의 주 상태 뱃지는 Reminder 수명주기가 아니라 개별 Occurrence의 진행 상태를 표시한다. Reminder 수명주기와 Occurrence 진행 상태는 별도 축으로 관리한다. 보관된 Reminder는 보관함에서 수명주기 상태를 확인한다.
- `D-037` 변경 이력에는 생성, 주요 필드·담당자·Trigger·반복 설정 변경, 회차 완료·완료 취소·취소·놓침·건너뜀, Reminder 보관·복원을 기록한다. 변경자와 시각, 변경 항목 및 이전·새 값을 표시하고 자동 전이는 시스템 행위자로 표시한다. 반복 Reminder 수정은 적용 범위(`이번 회차만`, `이번 회차와 이후 회차`, `전체 반복`)도 기록한다. 무담당으로 인한 반복 일시 중지·재개와 미리 생성된 회차 건너뜀은 `SYSTEM` actor와 사유를 기록하고, 사용자가 직접 건너뛴 회차는 실제 `USER` actor와 시각을 기록한다(`D-075`). 장소 변경은 장소명과 반경만 이력에 표시하고 정확한 GPS 좌표는 포함하지 않는다. 영구 삭제된 Reminder의 이력은 사용자 화면에서 제공하지 않는다.
- `D-038` 장소 반경 옵션의 초기값은 최소 50m, 기본 100m, 최대 500m다. Admin은 가구 설정에서 각 값을 변경할 수 있다.
- `D-039` 장소 반경 슬라이더는 MVP에서 25m 간격으로 조정한다. 사용해본 뒤 필요하면 간격을 재조정한다.
- `D-040` Admin이 장소 반경 최소값·최대값을 바꾸면 범위를 벗어난 활성·보관 LOCATION Reminder의 반경을 새 경계값으로 자동 조정한다. 가구 설정과 영향받은 Trigger 변경을 한 트랜잭션으로 저장하고, Admin을 변경자로 기록하며 기기 지오펜스를 동기화한다([ADR-008](./decisions/ADR-008-location-radius-bound-adjustment.md)).
- `D-041` 활성 Reminder의 미완료 `PENDING` 회차는 새로 인식된 각 장소 조건 event마다 한 번 알림을 받는다. 같은 event의 중복 callback은 억제하고, 동일한 진입·머무름 상태가 이어지는 동안 반복 알림하지 않는다. 새 진입·이탈 transition, 새 연속 머무름 구간, 새 `AFTER_EXIT` countdown은 새 event로 처리한다. 완료·취소·놓침·건너뛴 회차 또는 Reminder 보관 뒤에는 추가 알림을 만들지 않는다(`D-075`; [ADR-009](./decisions/ADR-009-location-alert-retriggering.md)).
- `D-042` 기기가 장소 조건 event를 인식하면 앱은 서버 동기화나 원격 push를 기다리지 않고 즉시 해당 기기의 로컬 시스템 알림을 표시한다. Android가 event를 앱에 전달하는 시점 자체는 OS·위치 조건에 따라 달라질 수 있으며 고정된 감지 지연을 보장하지 않는다([ADR-010](./decisions/ADR-010-location-alert-immediacy.md)).
- `D-043` 앱과 서버는 사용자의 실시간 GPS 좌표나 이동 경로를 수집·저장하지 않는다. 장소 Reminder에 사용자가 지정한 geofence 중심 좌표는 Trigger 설정으로 서버와 대상 기기에 저장한다. 장소 event는 ID·설치 ID·Occurrence·Trigger revision·조건 종류·감지 시각·처리 결과만 서버에 감지 시각부터 30일 보관하고, 기기 local event journal에는 동기화에 필요한 비좌표 metadata만 두며 서버 확인 뒤 지운다([ADR-011](./decisions/ADR-011-location-data-minimization-and-retention.md)).
- `D-044` 백그라운드 위치 권한은 설치 기기별 capability다. 권한이 거부돼도 LOCATION Reminder를 저장할 수 있으며, 해당 설치에는 알림 불가 상태와 Android 설정 바로가기를 표시한다. 다른 구성원 기기의 지오펜스 동작에는 영향을 주지 않는다. 권한이 허용되면 해당 설치의 Trigger를 reconcile한다([ADR-012](./decisions/ADR-012-location-permission-degraded-mode.md)).
- `D-045` 시간·장소 알림은 Reminder에 지정된 담당자에게만 보낸다. 담당자 각자의 알림 가능한 등록 기기를 전달 대상으로 삼고, 비담당 가구 구성원은 알림을 받지 않는다. 비담당자도 기존과 같이 Reminder를 조회·수정·완료할 수 있다([ADR-013](./decisions/ADR-013-assignee-only-notifications.md)).
- `D-046` 시간 알림은 각 담당자 기기의 Android 로컬 알람에 예약한다. FCM은 영향을 받는 담당자 설치에 서버 변경을 알리는 비사용자용 동기화 신호로만 쓰며, 앱이 최신 revision을 가져와 알람·지오펜스를 reconcile한다. FCM 신호는 due-time 사용자 알림으로 표시하지 않고, 앱 시작·foreground 복귀 시에도 서버 상태를 동기화한다. FCM payload는 업무 내용을 담지 않는 동기화 신호 경계로 제한해 `Q-018`을 해결한다([ADR-014](./decisions/ADR-014-local-alarms-and-fcm-sync-signals.md)).
- `D-047` Android 앱은 정확 알람 접근 권한을 요청한다. 권한이 거부되어도 시간 Reminder 저장을 허용하고 해당 설치에는 지연될 수 있는 부정확 알람을 예약한다. 앱은 설치별 지연 가능 상태와 OS 설정 바로가기를 보여주며 권한 획득·복구 시 정확한 예약으로 reconcile한다([ADR-015](./decisions/ADR-015-exact-alarm-permission-fallback.md)).
- `D-048` 활성 Reminder의 `PENDING` 회차에 한해, 시간 알림은 담당자 각 설치에서 예정 시각부터 24시간 이내(경계 포함)에 한 번 표시한다. 24시간을 넘긴 알림은 생략하지만 Reminder와 Occurrence의 기존 상태를 변경하지 않고 기존 할 일 목록 규칙을 유지한다([ADR-016](./decisions/ADR-016-time-alarm-catch-up-window.md)).
- `D-049` FCM ChangeSignal 발송이 일시 실패하면 서버는 exponential backoff로 최대 24시간 재시도한다. outbox 생성 시각부터 24시간을 신호 유효기간으로 두고, FCM TTL에는 남은 유효시간을 넣어 총 수명을 늘리지 않는다. 만료 뒤 재시도를 멈추며 앱 시작·foreground 복귀·부팅 동기화로 복구한다. 이에 따라 `Q-020`을 해결한다([ADR-017](./decisions/ADR-017-fcm-change-signal-retry-and-ttl.md)).
- `D-050` Android 설정에서 Notify Me를 강제 종료한 동안 시간·장소 알림과 FCM 수신은 보장하지 않는다. 앱을 사용자가 다시 열면 서버를 full sync하고 시간 알람·지오펜스를 reconcile한다. 설정·도움말에 이 OS 제약을 안내하며 앱은 강제 종료를 우회하거나 자동 실행하지 않는다([ADR-018](./decisions/ADR-018-android-force-stop-recovery.md)).
- `D-051` 앱은 Android 배터리 최적화 예외를 직접 요청하지 않는다. 설치별로 확인 가능한 알림·정확 알람·위치 capability를 표시하고, 필요한 경우 사용자가 OS 설정을 직접 확인할 수 있는 안내·바로가기를 제공한다. 제조사별 절전 동작은 실기기 검증 대상으로 두며, 예외 설정이 알림 지연을 모두 해결한다고 보장하지 않는다([ADR-019](./decisions/ADR-019-android-battery-optimization.md)).
- `D-052` 공유 UI와 서버 코드는 TypeScript를 사용하고, API는 Node.js에서 실행한다. UI는 반응형 Web 앱으로 구현해 모바일·태블릿·데스크톱 브라우저 및 Capacitor WebView에서 재사용한다. 브라우저는 동기화된 업무 CRUD UI를 제공하며, 백그라운드 시스템 알림·지오펜스는 지원되는 네이티브 설치의 기능으로 구분한다. 네이티브 capability는 플랫폼 중립 port와 capability별 adapter 모듈로 분리하고, MVP Android는 Kotlin adapter로 구현한다. 후속 iOS 등은 같은 port에 Swift adapter를 추가해 공유 UI·도메인 계약의 변경을 최소화한다([ADR-020](./decisions/ADR-020-responsive-web-and-platform-adapters.md)).
- `D-053` MVP 데이터베이스는 SQLite다. DB 파일은 RPi의 로컬 영속 저장소에 두고, 짧은 쓰기 트랜잭션과 MVP 단일 Worker로 SQLite의 단일 writer 동작을 관리한다. DB 접근은 repository와 버전 관리 migration으로 격리하고, PostgreSQL 전환은 상용화 또는 동시성·다중 인스턴스 요구가 구체화될 때 재평가한다. 전환이 자동으로 호환된다고 가정하지 않는다([ADR-021](./decisions/ADR-021-sqlite-mvp-database.md)).
- `D-054` 공유 Web UI는 React Router framework mode를 Vite SPA mode(`ssr: false`)로 구성한다. 같은 정적 build를 브라우저와 Capacitor WebView에서 사용하고, 서버 렌더링 없이 별도 API와 통신한다([ADR-022](./decisions/ADR-022-react-router-vite-spa.md)).
- `D-055` 서버는 Node.js runtime과 NestJS API framework를 사용한다. Raspberry Pi에서 단일 모듈형 모놀리스로 실행하고, NestJS feature module로 업무 기능을 나누되 도메인 규칙을 framework와 DB 구현에서 분리한다. 이에 따라 `Q-016`을 해결한다([ADR-023](./decisions/ADR-023-nestjs-api-framework.md)).
- `D-056` SQLite 접근 도구는 Prisma ORM 7이다. Prisma schema와 SQL migration을 버전 관리하고, NestJS application provider로 Prisma Client를 제공한다. SQLite용 better-sqlite3 adapter를 쓰며, Node.js·ORM·adapter 버전을 함께 고정한다. 이에 따라 `Q-037`을 해결한다([ADR-024](./decisions/ADR-024-prisma-orm-sqlite-access.md)).
- `D-057` 외부 HTTP 진입점은 Caddy다. DDNS hostname에 대한 자동 HTTPS, React 정적 build 제공, NestJS API reverse proxy를 Caddy가 맡는다. TCP 80/443은 Caddy로만 전달하고 내부 앱·DB 포트는 공개하지 않는다. 이에 따라 `Q-017`을 해결한다([ADR-025](./decisions/ADR-025-caddy-ddns-https-ingress.md)).
- `D-058` 영구 삭제는 사용자 화면과 운영 DB에서 즉시 효력을 갖는다. 기기 동기화에는 reminder ID와 delete revision만 든 tombstone을 최대 30일 사용한다. 암호화된 복구 백업은 최대 30일 순환 보관하고, 정상 복원 시 tombstone을 재적용해 삭제 항목이 되살아나지 않게 한다. 실수 삭제 복구는 운영자 전용 감사 절차로만 가능하며 일반 앱에는 복원 기능을 두지 않는다. 삭제 UI에는 백업 보관 세부사항을 표시하지 않지만 출시 시 개인정보 처리방침에 보관·파기 방식을 공개한다. 이에 따라 `Q-009` 중 Reminder 삭제의 tombstone·백업 정책을 해결한다([ADR-026](./decisions/ADR-026-permanent-delete-and-backup-retention.md)).
- `D-059` Admin이 가구 구성원을 제거하면 해당 Membership의 접근을 즉시 끝내고 그 구성원을 활성 Assignment와 해당 가구의 알림 대상에서 해제한다. Reminder·회차·완료 이력은 삭제하지 않는다. 유일한 담당자가 제거되면 현재 `PENDING` 회차를 담당자 없는 상태로 유지하고 목록에 `담당자 없음`을 표시하며 모든 가구 구성원이 계속 조회·완료할 수 있다. 담당자가 남아 있으면 업무와 반복을 그대로 이어간다([ADR-027](./decisions/ADR-027-member-removal-and-unassigned-reminders.md)).
- `D-060` 담당자가 0명이 된 반복 Reminder는 반복 규칙을 유지한 채 자동 일시 중지한다. 현재 미완료 회차와 이미 미리 생성된 회차는 보존하되, 새 회차 생성과 알림을 멈춘다. 담당자가 다시 지정되면 현재 회차는 유지하고, 그보다 뒤에 미리 생성됐으나 재지정 시각보다 과거가 된 미완료 회차는 `SKIPPED`·`NO_ACTIVE_ASSIGNEE` 사유로 이력에 남긴다. 무담당 기간의 미생성 회차는 보충하지 않고 미래 회차부터 재개한다. 현재 회차가 다음 반복 시각까지 미완료이면 기존 규칙대로 `MISSED`로 닫는다(`D-030`, `D-037`, `D-059`; [ADR-028](./decisions/ADR-028-unassigned-recurrence-pause.md)).
- `D-061` 월간 반복은 특정 날짜(1~31일) 또는 `매월 말일`을 선택한다. 특정 날짜가 해당 월에 없으면 그달 회차를 건너뛰며 마지막 날로 보정하지 않는다. `매월 말일`은 2월·30일인 달을 포함해 각 달의 실제 마지막 날짜에 실행한다. 특정 날짜 1일은 월초 규칙을 별도로 두지 않고 날짜 선택으로 표현한다([ADR-029](./decisions/ADR-029-monthly-recurrence-dates.md)).
- `D-062` 반복 Reminder는 기본으로 종료일 없이 계속 반복한다. 사용자는 반복 규칙의 시간대 기준으로 선택 종료일을 추가할 수 있으며, 종료일 당일 회차까지 실행하고 그 이후에는 새 회차와 알림을 만들지 않는다. 종료일이 지나도 마지막 미완료 회차나 Reminder 자체를 자동 완료·놓침·보관·삭제하지 않는다. 반복 횟수 제한은 MVP에서 제공하지 않는다([ADR-030](./decisions/ADR-030-recurrence-end-date.md)).
- `D-063` 반복 Reminder를 수정할 때 저장 전에 `이번 회차만`, `이번 회차와 이후 회차`, `전체 반복` 중 적용 범위를 선택한다. 첫 번째는 반복 규칙을 유지하고 선택한 회차에만 예외를 적용한다. 두 번째는 선택 회차와 이후 회차에 변경을 적용하고 이전 회차는 보존한다. 세 번째는 선택한 변경을 과거를 포함한 시리즈 전체에 적용한다. 전체 적용에서도 완료 여부, 완료자·시각, occurrence identity와 감사 이력은 보존한다. 반복 규칙 변경은 두 번째나 세 번째 범위에서만 적용한다([ADR-031](./decisions/ADR-031-recurring-edit-scopes.md)).
- `D-064` 반복 일정의 존재하지 않는 DST 현지 시각은 DST 간격만큼 앞으로 이동해 한 번 실행하고(예: `02:30`→`03:30`), 중복 시각은 먼저 발생한 instant에서 한 번 실행한다([ADR-032](./decisions/ADR-032-recurrence-dst-resolution.md)).
- `D-065` 일정은 IANA time zone을 기준으로 계산한다. 새 일정은 household 기본 시간대(초기 `Asia/Seoul`)를 기본으로 저장하고, 반복 규칙에는 자체 시간대를 보존한다. 사용자 time zone은 표시 기준이며 변경해도 기존 일정·반복 시간은 이동하지 않는다. locale fallback은 `ko-KR`이다. 번역 resource를 분리하고 API는 locale-neutral code를 반환하며 사용자 작성 문구는 번역하지 않는다([ADR-033](./decisions/ADR-033-time-zones-and-localization.md)). 첫 실행의 locale 선택 순서는 `D-093`을 따른다.
- `D-066` MVP는 한국어(`ko-KR`)와 영어(`en-US`) UI·시스템 문구를 제공하고 언어는 사용자별로 선택한다. 첫 실행에 유효한 저장 locale이 없으면 지원되는 기기 locale을 선택하고, 지원 locale이 아니면 `ko-KR`을 사용한다(`D-093`). 저장된 사용자 선택은 기기 locale보다 우선하며, 날짜·시간·숫자 표시는 선택 locale과 사용자 time zone에 맞춘다([ADR-034](./decisions/ADR-034-mvp-language-support.md)).
- `D-067` 데이터 내보내기를 후속 기능으로 계획하고, 초기 포맷은 JSON을 우선 검토한다. MVP에는 내보내기 UI/API를 구현하지 않는다. 데이터 모델은 엔티티와 관계를 정규화하고 안정적인 식별자를 유지해 향후 내보내기를 막지 않게 한다. 내보내기 대상·민감 필드·권한은 기능 설계 전에 정한다. 계정·가구 종료 동작은 `D-068`에서 별도로 정했다([ADR-035](./decisions/ADR-035-data-export-deferred.md)).
- `D-068` 계정 삭제와 가구 종료를 분리한다. 계정 삭제는 개인 인증·프로필·기기 정보를 제거하고, 공유 Household 데이터와 이력은 유지하면서 탈퇴자 식별·행위자 참조를 지운다. 해당 사용자 Assignment만 종료하며 다른 담당자 알림은 유지한다. 마지막 Admin은 먼저 역할을 넘기거나 해당 가구를 종료해야 한다. Admin은 구성원이 남아 있어도 명시적 확인 후 가구를 종료할 수 있고, 구성원 동의는 요구하지 않는다. 종료 시 모든 구성원의 접근을 즉시 회수하고 가구 소유 데이터·전달 작업을 운영 DB에서 제거한다. 종료 사실을 구성원 기기에 best-effort로 알린다. 계정·가구 삭제 tombstone과 암호화 백업은 최대 30일 유지하고 백업 복원 전에 삭제를 재적용한다. UI는 앱 복원이 불가능함을 안내하고, 서버 보존 세부사항은 개인정보 처리방침에서 설명한다. 종료 셀프서비스는 후속 기능이다([ADR-036](./decisions/ADR-036-account-and-household-closure.md)).

- `D-088` 이력 화면에 다시 진입할 때마다 기본 범위를 현재 사용자가 담당자인 Reminder로 초기화한다. 가구 전체 이력 선택은 현재 화면 세션에서만 유지하고 다음 진입을 위해 계정·기기 설정에 저장하지 않는다. `Q-060`을 해결한다(`F-HIS-001`, `F-HIS-002`, `F-LIST-004`, `PR-AC-011`, `DS-005`).
- `D-089` 보관함은 `archived_at` 내림차순, 즉 가장 최근 보관된 Reminder부터 표시한다. 동일 시각 항목의 안정적인 보조 정렬은 `DS-005`에서 정한다. `Q-061`을 해결한다(`F-REM-004`, `F-LIST-008`, `PR-AC-034`, `DS-005`).
- `D-090` LOCATION Reminder를 새로 만들거나 담당자를 추가·변경할 때, 대상 Android 설치 중 하나라도 지오펜스 용량을 넘게 되면 해당 Reminder/Assignment 변경 전체를 저장하지 않는다. 화면은 용량이 찬 설치를 알리고 입력 내용을 유지한 채 기존 지오펜스 또는 다른 LOCATION Reminder를 정리하도록 안내한 뒤 재시도를 제공한다. 사용자가 기존 지오펜스를 한 설치에서만 제거하기로 선택하면 확인 뒤 해당 설치에서만 그 Reminder의 장소 감지를 끄고, 가구 Reminder와 다른 담당자 설치는 유지한다. 보관·삭제는 기존 Reminder 정책을 따른다. 위치 권한이 거부된 경우 저장을 허용하는 `D-044` 동작은 용량 초과 정책과 별개로 유지한다. `Q-062`를 해결한다(`F-TRG-003`, `F-NOT-007`, `F-SET-004`, `PR-AC-006`, `PR-AC-008`~`PR-AC-009`, `PR-AC-013`, `PR-AC-016`, `PR-AC-068`, `DS-006`, `DS-010`, `DS-011`).
- `D-091` MVP에는 Reminder별 선택적 완료 검증을 포함한다. 설정에서 다른 가구 구성원을 검증자로 지정하고, 담당자가 완료를 표시하면 검증 대기로 전환한다. 지정 검증자의 승인은 완료로 확정하고 거절은 미완료로 되돌리며, 응답 전에는 검증 대기를 유지한다. 검증자 알림은 필요할 때 제공한다. 검증자 자격·세부 권한, 다중 담당자와 검증자의 상호작용, 요청 취소·만료·재알림 및 구체적인 데이터·화면 동작은 상세 설계에서 정한다. `Q-063`의 MVP 포함 결정을 해결한다(`F-REM-009`, `PR-AC-069`, `DS-004`, `DS-005`, `DS-009`).

- `D-093` MVP에서 유효한 저장 사용자 locale은 기기 locale보다 우선한다. 유효한 저장값이 없으면 지원되는 기기 locale(`ko-KR` 또는 `en-US`)을 첫 표시 언어로 사용하고, 기기 locale이 지원되지 않으면 `ko-KR`로 fallback한다. 사용자는 이후 개인 설정에서 언어를 선택할 수 있고 선택값은 서버에 저장해 다른 설치와 동기화한다. `Q-065` 및 AI 제안 `AFR-001`을 해결·승격한다(`F-SET-003`, `PR-AC-052`, `NFR-I18N-001`~`NFR-I18N-002`, `ADR-034`, `FR7.2`, `NFR7`).
