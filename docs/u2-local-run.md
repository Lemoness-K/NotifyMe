# Notify Me U2 실행과 검증

## 로컬에서 가구 가입 확인

[U1 실행 안내](u1-local-run.md)의 로컬 HTTPS 환경을 사용한다. 기존 개발 DB를 사용할 때는 같은 파일에 `npm run migrate`를 실행하고 최초 Admin 등록은 다시 실행하지 않는다. 마이그레이션은 가구·구성원·업무·기존 배정을 보존한다. 기존 DB의 실행을 다시 시작하기 전에 앱을 빌드한다.

1. 테스트 계정으로 로그인하고 **설정 → 초대 관리**에서 `member@example.test`를 초대한다. 최초 응답에서 링크를 복사한다.
2. 별도의 브라우저 프로필에서 링크를 열고 **테스트 계정으로 초대 수락**을 누른다. 로컬 합성 모드는 이 흐름에 별도 테스트 Member를 사용한다.
3. Admin으로 돌아가 **설정 → 구성원 관리**에서 새 Member 확인과 제거를 시험한다. 제거 후 Member가 가구 데이터를 다시 요청하면 거부된다. 개인 설정에는 계속 접근할 수 있다.
4. **설정 → 개인 설정**에서 표시 언어와 시간대를 변경한다. 동일 계정으로 다른 브라우저에서 로그인하면 저장한 선호가 적용된다. 표시 시간대 변경은 저장된 일정의 실행 시각을 바꾸지 않는다.

초대 링크는 24시간 유효하며, 화면이나 링크를 열기만 해서는 소비되지 않는다. 발급 응답이 유실되어 같은 발급 작업을 재시도하면 Admin에게 복구에 필요한 초대 ID를 반환한다. 새 링크가 필요하면 기존 초대를 취소하고 다시 발급한다. 초대 코드와 대상 이메일은 관리자 상태 목록과 운영 로그에 표시되지 않는다.

## 실행 환경 설정

| 변수 | 기본값 | 허용 범위 및 영향 |
| --- | --- | --- |
| `NOTIFY_INVITE_IP_PER_MINUTE` | 30 | 1~1,000. 공급자 검증 전 수락 출처별 분당 요청 |
| `NOTIFY_INVITE_IDENTITY_PER_MINUTE` | 10 | 1~1,000. 검증된 외부 신원별 분당 수락 요청 |
| `NOTIFY_ADMIN_PER_MINUTE` | 20 | 1~1,000. 내부 Admin과 가구 조합별 분당 관리 요청 |
| `NOTIFY_INVITE_CLEANUP_MS` | 300,000 | 1,000~3,600,000ms. 시작 시와 이후 주기마다 만료한 초대의 이메일 정리 |

한도를 초과하면 `429`와 `Retry-After`를 반환한다. 초대 수락 가능 여부는 정리 주기와 관계없이 기한을 검사한다. 정리가 실패하거나 지연되면 이메일이나 초대 코드 없이 로컬 로그에 진단 이벤트를 남긴다. 대상 Caddy 구성은 `X-Notify-Client-IP`를 실제 연결 주소로 덮어쓰며 앱과 로컬 헬스 경계는 loopback에 유지한다.

## 검증

Node.js 24, OpenSSL, Chromium과 Caddy를 준비한 뒤 `npm run verify:u1`을 실행한다. 기존 명령이 U1과 U2의 타입 검사, 빌드, Vitest·Playwright와 전체 라인 커버리지 80% 목표를 검증한다. 로컬 Caddy 실행 파일이 PATH에 없으면 `NOTIFY_TEST_CADDY_BIN`으로 지정한다. 이 검증은 합성 계정과 임시 SQLite에 한정한다. 실제 Google/Firebase 연동과 Raspberry Pi에서의 동작·자원 측정은 별도 환경에서 확인한다.

U2 인프라의 자동 추적은 상위 NFR 설계 Markdown의 상세 ID를 찾지 못했다. U2 독립 검토에서 추적표의 연결 12개를 수동 대조했다.
