# 코드 품질 평가

## 평가 범위

인증·최초 등록·SQLite·복원과 모바일 운영 경로를 정적으로 확인했다. 테스트 실행과 운영 접근은 이번 단계에 포함하지 않았다.

| 항목 | 관찰 |
|---|---|
| 이름과 책임 | `bootstrap-admin.ts`가 입력을 받으며 `auth.ts`가 트랜잭션과 세션을 처리한다. 인증 제공자와 저장소를 주입할 수 있다. |
| 오류 경계 | 인증 공급자 코드가 자격 거부 401과 공급자 장애 503을 구분한다. 예기치 않은 DB 오류는 HTTP 안전 오류로 매핑한다. |
| 테스트 | U1 인증 테스트는 일반 세션·챌린지 재사용·공급자 실패와 CLI 1회 조건을 확인한다. 기존 E2E는 CLI로 최초 가구를 만든 뒤 로그인한다. |
| 접근 경계 | 보호 API가 Firebase Bearer와 앱 세션을 함께 요구한다. 필요한 업무 경로는 활성 멤버십과 역할을 검사한다. |

## 빌드·품질 자동화

`verify:u1`은 타입 검사, Prisma/TypeScript/Vite 빌드, V8 커버리지와 Playwright를 실행하는 기존 명령이다. 완료된 기존 구현 기록에는 Vitest 214건, Chromium 4건, 라인 커버리지 87.16%가 기록돼 있다. Pi ARM64 기록의 부하 시험은 외부 인증, TLS와 Android 실제 동작을 검증하지 않았다.

## 문서 품질과 추적성

기존 CodeKB는 제품 코드가 없던 설계 시점에 작성됐다. 현재의 CLI 구현과 테스트, 가입·복원 코드는 확인됐다. 세부 설계와 추적표에서 `D-074` 최초 관리자 서버 등록, `Q-048` 첫 가구 개설, `DS-003` 계정·가구 온보딩, `F-HH-001` 초기 가구 설정, `PR-AC-058` 최초 관리자 등록 수용 기준을 새 변경과 연결할 필요가 있다.

## 주요 기술 부채·위험 신호

- 중복 가구 제약은 초기화의 의도를 알려주지 않는다. 신규·기존·장애·복원·종료 결과를 구분할 승인된 정책과 검증이 필요하다.
- 메모리 기반 웹 자격 증명과 후보 수명 주기를 함께 설계해야 새로고침과 창 닫기 뒤 권한이 명확해진다.
- 기존 가구·초대 흐름과 운영 복구의 보호 경계에서 회귀를 확인해야 한다. Android 모바일 데이터 경유의 실제 첫 로그인·확정·저장은 별도 검증 대상이다.
