# U4 Android 알림 구현 결과

## Summary

- 기존 데이터에 설치·세대·계획·설치별 장소 제외, 위치 조건 이벤트, FCM 발송 기록을 추가하는 순방향 SQLite 마이그레이션을 구현했다. 새 설치의 장소 수요가 한도를 넘으면 해당 설치의 장소 감지를 대기시킨다. 다른 설치의 상태, 시간 알림과 업무는 유지한다.
- 기존 로그인에 네이티브 챌린지와 설치 세션을 연결했다. Kotlin 어댑터가 고정 HTTPS API에 동기화하며 세션·토큰을 보호 저장한다. 공유 웹은 계정 언어에 따라 설치 상태, 장소 제외·복원, 권한 안내를 표시한다.
- 시간·장소 예약, 재시작·회수·세대 변경 후 이전 범위 정리, FCM 변경 신호, 알림 탭에서 상세 화면까지 연결했다. 비공개 알림은 인가된 내용만 표시하며 공개 잠금 화면용 알림에는 일반 문구를 사용한다.

## Independent review repairs

- 앱 재실행에서 새 FULL 응답을 확인할 때까지 이전 계획에 따른 콜백과 게시를 제한한다. 재부팅·시간 변경에서 기존 시간 예약을 복구하는 경로를 별도로 둔다.
- 위치 권한·서비스가 중단되면 타이머와 마지막 경계를 무효화하고 콜백 식별자를 갱신한다. 재등록 첫 관측은 새 상태의 기준점으로 다룬다.
- 장소 제공자의 제거·재등록이 실패해도 인가된 시간 예약은 먼저 적용한다. 제거 대기와 장소 등록 재시도는 별도로 보존한다.
- 위치 이벤트 입력·저장·재실행 키를 권한이 확인된 epoch에 묶는다. 이전 epoch가 같은 회차와 계획 버전으로 돌아와도 거절한다. HTTP에서 처음에는 이전 세대가 204로 수락되는 실패를 확인했고, 수정을 거쳐 이전 세대 거절과 새 세대 이벤트 기록을 확인했다.
- 앞선 보완 후보 `981510e`의 첫 CI 시도는 Maven Central의 429로 빌드 전에 중단됐고 같은 커밋 재실행에서 통과했다.

## U4 재검토 후 세 건 보완

- R-02. 위치 OFF와 제공자 사용 불가를 수신할 때 예약 작업과 분리된 보호 저장소에 위치 세대를 즉시 기록한다. 이미 대기 중인 콜백은 이전 등록을 사용하지 않는다. 새 등록의 첫 관측은 기준 상태를 잡고, TIME 예약은 위치 중단의 영향을 받지 않는다.
- R-05. 같은 부팅의 기존 등록 ID와 세대·권한을 확인해 정상 프로세스 재생성 뒤 위치 전이와 타이머를 처리한다. 무효화가 저장된 등록은 프로세스 재시작 후에도 폐기한다.
- R-06. 일반 복귀는 일시적 조회 실패에서도 유효한 기존 예약을 유지한다. API 35 시작 기록에 따른 강제 종료와 확인이 불가능한 최초 화면 진입은 인가된 FULL을 저장한 뒤에만 차단을 해제한다. 정지 해제 뒤 부팅 신호와 명시적 접근 회수도 검사한다.
- 수정 전에 새 결정 규칙을 검증하는 네 건이 필요한 경계가 없어서 테스트 컴파일에서 실패했다. 수정 뒤 전체 ARM64 JVM 16건, U4 Vitest 17건과 Chromium 1건, 전체 Vitest 178건과 Chromium 4건이 통과했다.
