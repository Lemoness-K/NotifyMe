# U1 기술 기준과 검증 요구사항

## Sources

U1의 `functional-spec.md`, `rules.md`, Inception `requirements.md`, `contract-summary.md`와 CodeKB `technology-stack.md`를 기준으로 한다.

## Requirements

| ID | 요구사항 | 확인 방법 |
| --- | --- | --- |
| NFR6.1.1 | 공유 웹은 가용 너비에 따라 재배치한다. 대표 폭은 검증 표본으로 사용한다. | 좁은 폭, 넓은 폭 및 폭 변경에서 핵심 흐름을 확인한다. |
| NFR6.2.1 | 로그인·등록·조회와 오류 복구에 키보드와 터치를 각각 사용할 수 있어야 한다. | 기본 조작에서 의도하지 않은 가로 넘침과 진행을 막는 입력 경계를 확인한다. |
| NFR6.3.1 | 상태와 오류를 색상 이외에도 문구나 식별 가능한 상태로 표현한다. | 사용자에게 보이는 상태·오류 표본에서 문구 또는 접근 가능한 상태 표기가 함께 전달되는지 확인한다. |
| NFR6.4.1 | 웹의 기본 업무 기능은 설치의 OS 알림·위치 권한에 의존하지 않는다. | 지원되지 않는 기능을 표시한 상태에서도 등록·조회가 성공한다. |
| NFR7.1.1 | 공유 UI 생성 문구를 번역 키와 언어 리소스로 분리한다. | 도메인 규칙 변경 없이 새 번역 리소스를 연결할 수 있는 구조인지 확인한다. |
| NFR7.3.1 | U1의 시각 표시는 저장 시각과 UI 표현을 분리한다. | 표시 시간대·locale이 달라도 저장 값이 같음을 검증한다. 계정 설정 적용은 U2가 확장한다. |
| NFR7.4.1 | API 오류는 안정된 코드, 구조화된 필드 및 요청 ID로 반환한다. | 언어 설정을 바꿔도 서버 오류 코드와 의미가 같고 UI 표시만 바뀐다. |
| NFR7.5.1 | 사용자 제목과 설명은 번역·치환 없이 보존한다. | 언어를 바꿔도 작성한 원문 및 저장 값이 일치하는지 확인한다. |
| NFR8.1.1 | 공유 UI와 업무 로직은 Android SDK를 직접 참조하지 않는다. | 웹 개발 환경에서 네이티브 플랫폼 의존 없이 빌드·검증한다. |
| NFR8.2.1 | 계획된 프레임워크·저장소 native 의존성은 코드 착수 시 대상 ARM64 호환성을 확인한다. | 지원 구성과 검증 가능한 버전을 기록하고 이후 잠금 파일에서 재현한다. 개발 호스트 성공은 대상 환경 확인과 별도로 기록한다. |
| NFR9.1.1 | 동작 변경은 테스트부터 작성하고 가능한 경우 구현 전 실패를 확인한다. | 변경마다 관련 테스트와 구현 전 실패·구현 후 통과 증거를 남긴다. |
| NFR9.2.1 | 변경 동작과 인증·저장 경계의 주요 위험을 단위·통합·종단 자동 검증과 CI에서 확인한다. | 검증 명령과 적용 수준을 기록한다. 실행되지 않은 검증은 별도로 표시한다. |
| NFR9.3.1 | 승인된 전체 라인 커버리지 80% 목표를 적용한다. | 이전 테스트 문서의 충돌 문구를 구현 전 정합화하고 커버리지 보고서에 범위와 수치를 기록한다. |

## 기술 선택 근거

기존 선택을 사용한다. TypeScript·React Router·Vite는 공유 UI, Node.js·NestJS는 단일 서버, Prisma와 SQLite는 대상 장치의 데이터 저장, Firebase Authentication의 Google 공급자는 외부 신원 검증에 적용한다. 개발용 인증과 비운영 실제 연동 검증을 구분한다. 이 저장소에 앱 코드나 고정된 전체 도구 버전은 아직 확인되지 않았다.
