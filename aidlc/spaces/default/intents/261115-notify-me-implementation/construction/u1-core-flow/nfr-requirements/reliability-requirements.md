# U1 신뢰성 요구사항

## Sources

U1의 `functional-spec.md`, `rules.md`, Inception `requirements.md`, `contract-summary.md`와 CodeKB `technology-stack.md`를 기준으로 한다.

## Requirements

| ID | 요구사항 | 확인 방법 |
| --- | --- | --- |
| NFR3.1.1 | 최초 설정과 리마인더 생성은 각각 저장 단위가 원자적이어야 한다. 이미 커밋한 항목은 정상 재시작 뒤 조회 가능하다. | 구성원 생성이나 회차 저장 단계에 실패를 넣어 부분 상태가 남지 않는지 확인한다. 성공 후 재시작하여 같은 업무와 회차를 다시 조회한다. |
| NFR3.2.1 | 재시도 중 동일 작업 범위·키·입력은 같은 등록 결과에 수렴한다. | 동시 요청과 응답 유실 뒤 재시도에서 리마인더·최초 회차가 중복 생성되지 않는다. 다른 입력을 같은 키로 보내면 충돌 처리한다. |
| NFR4.1.1 | 시간 조건은 UTC instant와 IANA 시간대를 유지한다. 기본 시간대는 가구에서 오며 기존 일정은 표시 시간대 변경으로 이동하지 않는다. | 같은 일정의 표시 시간대를 다르게 조회해도 저장 시각과 최초 회차가 유지된다. |
| NFR4.2.1 | 현지 시각이 DST 간격에 속하면 간격만큼 이동시키고 중복 시각은 먼저 발생한 instant를 선택한다. | 합성 시간대 경계 사례의 UTC 결과를 기대값과 비교한다. Android 예약 재조정 및 반복 일정 전체는 U3·U4에서 검증한다. |
