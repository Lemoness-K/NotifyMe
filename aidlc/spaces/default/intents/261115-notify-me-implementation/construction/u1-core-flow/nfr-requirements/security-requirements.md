# U1 보안 요구사항

## Sources

U1의 `functional-spec.md`, `rules.md`, Inception `requirements.md`, `contract-summary.md`와 CodeKB `technology-stack.md`를 기준으로 한다.

## Requirements

| ID | 요구사항 | 확인 방법 |
| --- | --- | --- |
| NFR1.1.1 | 보호 요청은 신원과 현재 앱 세션을 각각 검증하고, 활성 사용자 및 같은 주체인 경우에만 처리한다. | 만료·취소·잘못된 신원과 사용자 불일치는 401이며 데이터가 반환되지 않는다. |
| NFR1.1.2 | 현재 웹 세션을 로그아웃하면 해당 세션은 종료된다. 앱 세션 발급은 확인 가능한 새 로그인을 요구하고 종료된 로그인에 해당하는 토큰과 단순 갱신 토큰으로 다시 발급할 수 없다. | 두 세션 중 하나를 종료한다. 이전 세션 사용·앱 세션 재발급·갱신 후 재발급은 거절되고 나머지 세션은 유지된다. 새 로그인 후에는 신규 세션이 발급된다. 서버가 무엇을 새 로그인 증거로 인정하는지와 발급·취소·재시도의 규칙을 구현 전 계약에 정의한다. |
| NFR1.2.1 | 가구와 역할은 서버가 활성 Membership을 기준으로 판단하고 최초 Admin은 운영 명령에서 한 번만 등록한다. | 신원만 있고 소속이 없거나 다른 가구에 속한 요청은 거절한다. 공개 경로로 최초 Admin을 등록할 수 없다. |
| NFR1.3.1 | 모든 조회와 변경을 승인된 가구와 객체 범위에 결합한다. | 다른 가구의 ID와 목록 요청에 대해 데이터·존재 정보가 새지 않으며 저장이 발생하지 않는다. |
| NFR2.1.1 | U1은 시간 조건 검증에 필요한 일정과 가구 데이터만 다루고 보호된 경계 안에서 저장·전송한다. | 로그와 오류에 토큰·세션 자격·제목·설명 입력 원문이 없고 U1 인증 및 조회 경로는 HTTPS 계약을 따른다. |
| NFR2.3.1 | 계정 데이터와 로그 접근은 승인된 사용자 또는 운영 권한을 따른다. | 다른 사용자의 계정 정보와 로컬 운영 로그를 업무 API로 읽을 수 없다. |
