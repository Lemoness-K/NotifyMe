# U1 빌드·검증과 배포 준비

## Sources

U1 `performance-design.md`, `security-design.md`, `scalability-design.md`, `reliability-design.md`, `observability-design.md`, `logical-components.md`, 도메인 `components.md`, `functional-spec.md`, `contract-summary.md`와 기존 Raspberry Pi 운영 설계를 근거로 한다.

## Pipeline

| 순서 | 작업 | 확인 기준 |
| --- | --- | --- |
| 1 | 코드와 잠금 파일에서 의존성 설치·빌드 | 실행 환경과 버전을 기록하고 웹·서버 빌드를 재현한다. |
| 2 | 타입 검사와 단위·통합·종단 검증 | 합성 계정과 임시 SQLite로 인증, 가구 차단, 등록 및 재조회, 재시작 후 데이터 보존을 확인한다. |
| 3 | 커버리지와 실행 결과 기록 | 승인된 80% 라인 기준과 검증 범위, 실행 커밋을 기록한다. U1 개발 담당이 앱 CI 작업과 검증 근거를 코드 계획에 포함한다. |
| 4 | 승인된 별도 연동 환경 검증 | 실제 Firebase·Google 검증은 비운영 자격으로 수행한다. 환경 미확보 시 대기로 기록한다. |
| 5 | 나중에 승인받을 대상 배포 준비 | 대상 ARM64 호환성, 서비스 구성 검토, 복구·롤백 조건을 기록한다. |

## Release and rollback

자동 운영 배포는 구성하지 않는다. 승인 후 목표 Pi에 올릴 때 앱 버전과 데이터 스키마를 짝으로 확인한다. 새 바이너리와 기존 스키마가 호환되지 않으면 앱 파일만 되돌리지 말고 검증된 복구 절차를 사용한다. U5에서 오래된 테스트 백업의 전체 검증을 수행한다. CI 자격 권한은 최소로 제한하고 운영 자격 증명과 외부 테스트 자격을 분리한다.
