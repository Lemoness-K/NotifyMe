# U1 상세 설계 초안

## 최소 통합 흐름

운영자가 검증된 Google 신원으로 최초 가구와 관리자를 설정한다. 관리자는 공유 웹에서 로그인하고 리마인더를 등록한다. 웹 요청은 인증과 가구 권한 확인을 거쳐 실제 저장소에 기록된다. 서버 재시작 뒤 로그인한 구성원이 같은 리마인더를 조회할 수 있는지 확인한다.

```text
운영자 초기 설정 → 사용자 로그인 → 가구 권한 확인
                                    ↓
                  리마인더 등록 → 실제 저장소에 기록 → 재시작 후 조회
```

## 모델과 규칙

- 외부 인증 신원은 내부 사용자 ID에 연결한다. 가구 소속은 별도로 확인한다. 같은 가구의 승인된 사용자는 공유 리마인더를 생성·조회할 수 있고, 다른 가구의 데이터는 조회 결과에 포함하지 않는다.
- 최초 가구와 관리자 소속은 한 트랜잭션에서 생성한다. 초기화가 이미 끝났거나 신원이 검증되지 않으면 추가로 생성하지 않는다. 보호된 사용자·가구 데이터는 인증 세션이 유효할 때만 제공한다. 만료·취소·로그아웃의 범위는 승인된 설치별 동작을 따른다.
- 등록에는 필수 제목, 선택 설명, 작성자, 요청자, 담당자, 알림 조건과 최초 회차가 연결된다. 최소 통합 시연은 시간 리마인더로 검증한다. 제목·설명은 원문을 보존하고 승인된 작성자·요청자·담당자 기본값을 적용한다.
- 검증 실패 시 데이터는 저장하지 않고 수정할 수 있도록 입력과 필드 오류를 화면에 남긴다. 실패 응답의 코드와 구조화 데이터는 언어에 중립적이다. 화면은 너비에 따라 재배치되고 키보드와 터치로 조작할 수 있다.
- 공통 스토리의 범위는 승인된 작업 단위 배정을 따른다. 계정 언어 선택은 가구·설정(U2), 반복·완료·장소 조건의 상세 동작은 리마인더 업무(U3), 실제 Android 동기화와 알림은 Android 단위(U4)에서 상세화한다.
- 로컬 경로는 합성 계정으로 확인한다. 실제 Firebase·Google 연동은 승인된 비운영 환경에서 별도로 검증한다.

- 저장과 권한 경계뿐 아니라 중복 초기화, 인증 실패, 잘못된 입력, 다른 가구 접근을 처리하는 방법을 명시한다.
