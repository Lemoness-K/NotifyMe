# U5 운영·백업·복구 기능 설계 질문

U5는 일관된 암호화 SQLite 백업, 격리 복원과 확정 삭제 재적용, 단일 Raspberry Pi 운영 상태 점검을 다룬다. 복구는 인증된 동일 스냅샷 기준점과 사후 삭제 원장의 연속성을 확인한 뒤에만 재개한다. 기존 U3 검토의 삭제 기록 미확정 경합과 설치 정리 장애의 영향은 백업 전 검증한다.

## Q-070 — Q-064 운영 보고·장애 전달 상세

D-092에 포함된 주간 운영 보고와 즉시 장애 알림을 이번 U5에서 어느 전달 범위까지 구현할까요? 같은 Raspberry Pi 안의 감지는 앱 서비스 장애를 기록할 수 있지만 호스트 전원이나 인터넷이 끊겼을 때는 외부 수신을 보장하지 않습니다.

- A. 로컬 운영 기록부터 구현 (권장). 운영자가 주간 상태 요약과 감지 즉시 생성된 장애 기록을 명령이나 journald로 확인합니다. 외부 수신 연동은 후속으로 둡니다.
- B. 기존 외부 채널까지 연동. 사용하는 채널과 수신 대상을 알려 주세요. 해당 채널을 대상으로 설계합니다.
- C. 보고·장애 알림은 후속으로 보류. 이번 U5는 백업·복구와 기본 운영 상태 점검에 집중합니다.
- X. Other (please specify)

[Answer]: A. 로컬 운영 기록부터 구현 (권장)
