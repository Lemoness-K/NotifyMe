# U5 운영·백업·복구 구현 결과

## Summary

- 운영 명령과 권한 제한 로컬 소켓을 추가했다. 선택 설정으로 주간 요약과 장애 전이를 기록하고, 중복 실행의 기록 ID를 유지한다. 외부 수신 채널은 D-098에 따라 후속이다.
- 활성 SQLite 쓰기 연결에서 `VACUUM INTO`로 일관 사본을 만들고 AES-256-GCM으로 암호화한다. 카탈로그와 원장은 최신 인증 위치를 확인한 뒤 게시한다. 최대 30일 보존과 복구 기준점 뒤 증거 보호를 함께 적용한다. [SQLite의 일관 사본 설명](https://sqlite.org/lang_vacuum.html#vacuum_with_an_into_clause)
- 운영 DB 밖의 권위 원장 증거를 새 삭제의 DB 쓰기 전과 종결 때 기록한다. 최초 요청의 쓰기 전 권한 거절은 ABORTED로 기록하고, 기존 요청은 커밋 증거를 확인한다. U4 설치 정리 실패와 삭제 원장 조정의 실패 경계를 분리했다.
- 복원은 공개 차단 후 격리 경로에서 백업과 원장을 검증하고 확정 삭제를 멱등 재적용한다. 통과한 후보의 DB·epoch를 결합하고, 불일치 시 API와 Worker 시작을 막는다. systemd 서비스와 예약 작업의 예제를 추가했다.

## 독립 리뷰 보완

- R-01. 최신 인증 원장의 확정 삭제와 DB에서의 부재 및 커밋 증거를 양방향 검사한다. 정리한 구간의 커밋 집합은 독립 권위 기록에 인증값으로 남긴다. 최초 기동은 검증한 전체 경계가 여전히 최신인지 리스너·Worker를 시작하기 전에 확인한다.
- R-02. 복원 사본의 기존 로그인 세션과 챌린지, 세션에 묶였던 설치 자격을 무효화해 재인증을 요구한다.
- R-03. 30일 만료 시각을 검증된 활성화 기록에 묶고 처음 공개하기 직전에도 확인한다. 공개 실패는 검증 대기 상태를 유지한다.
- R-04. 주간 보고만 활성화했을 때도 장애 전이를 집계하고 별도 장애 기록은 설정에 따로 따른다.
- 기존 합성 검증에서 일곱 추가 회귀 사례의 실패를 확인했다. 이어 추가한 DB 재시작 시험에서 열린 WAL 쓰기 연결로 인해 SQLite 읽기 오류가 발생했고, 재시작 전 테스트 연결을 닫아 의도한 검증을 통과시켰다. [최종 보완 후보 `357774d`의 애플리케이션 CI](https://github.com/Lemoness-K/NotifyMe/actions/runs/44780195844)

## 현재 시도 재검증

- 소스 매니페스트의 35개 경로가 U5 구현 커밋 `2035730`의 AI-DLC 산출물 외 변경 경로와 모두 일치한다. 당시 변경한 `docs/06-deployment-and-operations.md`와 `docs/decision-register.md`를 포함했다. 공유 결정 등록부에서 D-098은 운영 호스트의 주간 요약 및 장애 기록이며 Q-070의 결정이다. U3 완료 검증 결정 D-094~D-096과 U4 신규 설치의 장소 수용 한도 D-097은 각각 `b21d350`과 `5bf6785`에서 들어왔다.
- `.aidlc-source-paths.json`의 제외 경로 5개가 요구사항 분석 커밋 `7022058`의 내용과 일치하고 Delivery Planning 승인 이후 변경 이력이 없음을 Git으로 확인했다. 구현 중 변경된 문서 5개는 U3~U5 매니페스트에 있다. 소스 경계 확인의 세부 근거와 단계 전체 완료 검사 결과는 [문서 변경 이력](../../code-generation/document-provenance.md)에 연결한다. 전체 완료 검사는 U5 독립 리뷰 및 체크포인트 이후에 실행한다.
- 이번 재검증은 기존 구현을 대상으로 실행했다. 위에 기록된 구현 전 Red와 기존 CI 실행은 당시 작업의 증거다.

## 백업 보존 수정

- U5 R-05(만료 정리의 권위 원장 종속)를 보완했다. `prune-backups`는 앱의 운영 소켓이나 권위 원장에 연결하지 않고 백업 키로 카탈로그를 인증한다. 등록된 만료 사본만 제거한다. 인증에 실패하면 파일을 보존하고 `BACKUP_RETENTION_FAILED`를 기록한다.
- 백업 생성, 복원 파일 읽기, 보존 정리는 백업 볼륨의 SQLite 잠금을 공유한다. 정리 중단 시 만료 상태를 기록한 카탈로그를 다시 읽어 정리를 재시도할 수 있다. 수명이 남은 사본과 새 백업의 임시 파일은 독립 정리 대상에서 제외된다.
- D-058(암호화 백업 최대 30일 보관)의 30일 경계부터 복원 선택이 차단된다. 실제 파일은 호스트와 백업 볼륨에 접근 가능한 다음 정리 실행에서 제거된다. 배포 예제 타이머는 UTC 매시 15분에 동작하고 일시적 잠금 경합 후에도 재시도한다. [운영 경로](../../../../../../../../deploy/u5/README.md)

- DS-014의 대표 요청 p95, 피크 메모리와 저장장치 쓰기량은 대상 환경에서 측정한다. 실제 원장 최신성 확인은 별도로 보호하는 권위 저장 매체의 무결성과 가용성에 의존한다.
