# U2 보안 요구사항

## Sources

U2 `functional-spec.md`와 `rules.md`, Inception `requirements.md`와 `contract-summary.md`, CodeKB `technology-stack.md`를 근거로 한다. 현재 실행 스택은 U1의 `package.json`, `package-lock.json` 및 `docs/u1-local-run.md`에서 확인했다.

## Requirements

| ID | 요구사항 | 확인 방법 |
| --- | --- | --- |
| NFR1.1.3 | 초대 수락은 검증된 Google 공급자, 확인된 대상 이메일 및 명시적 수락을 요구한다. 미가입 신원에는 초대 수락 경계만 허용하고 일반 업무에는 유효한 앱 세션을 요구한다. | 공급자 불일치·검증 안 된 주소·다른 주소·세션 없음·공급자 일시 실패를 분리해 부수 효과가 없는지 확인한다. |
| NFR1.2.2 | 역할 변경·구성원 제거·초대 발급·취소·가구 설정 수정은 같은 가구의 활성 Admin이어야 한다. 권한 회수 커밋 뒤 권한 검사는 제거된 소속을 즉시 거부한다. | 동시 권한 변경과 재시도, 이미 로그인한 제거 계정, 후임 여부에 대한 테스트를 실행한다. |
| NFR1.3.2 | 모든 가구·사용자 설정과 구성원 변경에 대해 인증 주체, 소유 범위, 해당 요청 대상의 결합을 서버가 확인한다. | 가구·사용자 ID 변경, 멤버 권한으로 관리 쓰기, 없거나 다른 가구 객체를 건드리는 시도에서 데이터·저장 변경이 없어야 한다. |
| NFR1.4.1 | 초대 코드는 독립 무작위 비밀로 만들고 저장 및 로그에는 원문을 넣지 않는다. 승인된 원본 발급 응답에서만 원문을 반환하고 캐시하지 않는다. 관리 목록이 필요하면 활성 Admin에게 상태·ID만 제공하고 원문·대상 이메일은 제공하지 않는다. | 발급·수락·취소·만료·재시도에 대해 응답, 영속 데이터, 운영 로그를 대조한다. 무효 초대 검증을 제한한다. |
| NFR2.1.2 | 대상 이메일은 활성·미만료 초대에서만 조회 가능하며 종결 시 삭제한다. 수락과 취소는 같은 트랜잭션에서 삭제하고, 만료 뒤 접근은 즉시 거부하며 별도 정리 실행으로 원문을 제거한다. | 활성·취소·수락·경계 시각에 보관 위치를 검사하고, 조회가 전혀 없는 만료 사례도 정리가 실행되는지 확인한다. |
| NFR2.3.2 | 계정 선호와 로그는 소유자 또는 기존 운영 인가 경계에서만 읽는다. 공유 변경 이력에는 승인된 엔티티 식별자와 상태·필요한 값만 기록한다. | 초대 코드·대상 이메일·토큰이 이력, 에러, 운영 로그에 없고 다른 계정 정보가 응답되지 않는지 확인한다. |
