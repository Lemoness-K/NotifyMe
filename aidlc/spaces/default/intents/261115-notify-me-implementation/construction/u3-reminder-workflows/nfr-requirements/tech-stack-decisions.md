# U3 기술과 검증 요구사항

## Sources

U3의 `functional-spec.md` 및 `rules.md`, 승인된 `requirements.md`, `contract-summary.md`, `technology-stack.md`와 현재 U1·U2의 실행 환경을 사용한다.

## Requirements

| ID | 요구사항 | 확인 방법 |
| --- | --- | --- |
| NFR6.1.3 | 할 일·상세·검증 대기·이력·보관·삭제 확인 화면은 가용 폭에 맞춰 재배치한다 | 대표 뷰포트와 줌·긴 제목을 시험하며 고정 최소 지원 폭은 두지 않는다. |
| NFR6.2.3 | 키보드와 터치로 업무 변경·검증·삭제 확인이 가능하다 | 초점 순서, 오류 뒤 이동과 취소, 확인 동작을 계약으로 검증한다. |
| NFR6.3.3 | 회차와 수명주기 상태, 검증 가능한 작업은 색 이외의 단서를 갖는다 | 문구와 접근 가능한 이름으로 구분한다. |
| NFR6.4.3 | 기본 업무와 이력은 설치의 OS 권한 거부에서도 동작한다 | 브라우저와 기능 어댑터 대역에서 거부·미지원 상태를 시험한다. |
| NFR7.1.3 | UI 및 시스템 문구를 기존 번역 리소스로 표현한다 | 신규 상태·오류에 한국어와 영어 항목을 검증한다. |
| NFR7.2.3 | 저장 계정 locale과 기존 fallback 정책을 U3 화면이 동일하게 사용한다 | 두 언어 및 미지원 기기 언어를 전환한다. |
| NFR7.3.3 | 현지 시간·표시용 시간대와 날짜·수치를 일관된 형식으로 표시한다 | 서버 instant가 바뀌지 않고 출력 시간대만 달라지는지 확인한다. |
| NFR7.4.3 | 오류·전이 상태·처리 가능한 동작은 언어에 중립적인 값이다 | 언어 변경 뒤 구조화 오류와 상태 값을 동일하게 반환한다. |
| NFR7.5.3 | 사용자 제목과 설명을 변경 없이 저장하고 표시한다 | 다국어 및 공백 원문을 비교한다. |
| NFR8.1.3 | U3 서버와 화면은 U4 타입 포트만 의존하며 Android SDK를 직접 참조하지 않는다 | 포트 대역으로 U3 로컬 검증을 독립 실행한다. |
| NFR8.2.3 | Node.js·NestJS·React·Prisma/SQLite 및 대상 ARM64 경계를 유지한다 | 새 운영 의존성을 추가할 때 잠금 파일과 아키텍처를 확인한다. |
| NFR9.1.3 | 기존 앱 흐름과 사용자 결정의 변경 테스트를 구현 전에 작성한다 | Red와 Green의 증거를 남긴다. |
| NFR9.2.3 | 새 반복 벡터·동시 쓰기·복구용 삭제 실패·브라우저 UI를 자동화하고 U1·U2 회귀를 유지한다 | 실제 임시 DB, 독립 저널 및 합성 인증을 포함한다. |
| NFR9.3.3 | 전체 라인 커버리지 80%를 유지한다 | 승인된 전체 검증 명령으로 이전 Unit과 U3를 함께 측정한다. |
