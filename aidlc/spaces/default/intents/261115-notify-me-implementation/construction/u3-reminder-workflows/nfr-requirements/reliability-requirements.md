## Sources

U3의 `functional-spec.md` 및 `rules.md`, 승인된 `requirements.md`, `contract-summary.md`, `technology-stack.md`와 현재 U1·U2의 실행 환경을 사용한다.

## Requirements

| ID | 요구사항 | 확인 방법 |
| --- | --- | --- |
| NFR3.1.3 | 업무·회차·완료 검증·감사·피드 및 해당 연결 효과가 하나의 쓰기로 커밋된다 | 동시 승인·철회·회수와 연결 효과 실패에서 중복 상태나 부분 쓰기를 금지한다. |
| NFR3.2.3 | 같은 입력은 같은 리마인더·회차 동작 결과를 재사용하며 회차 생성은 안정 키로 멱등하다 | 동시 생성, 저장 뒤 응답 유실, 낡은 revision, 변경된 키 입력, 재시작을 각각 검증한다. |
| NFR3.3.3 | 계획 후보와 피드 상태는 명령이 커밋된 뒤에만 U4가 소비한다 | 실제 OS 및 FCM 재조정은 U4 검증으로 연결하고 U3에서 계약 대역으로 실패 및 재실행을 확인한다. |
| NFR3.4.3 | 삭제 성공 응답 전에 독립 기록의 REQUESTED 및 확정을 검증한다 | 커밋 전후와 확정 전 장애, 동일 키의 처리 재개, 커밋 증거 미확정 시 실패를 로컬에서 검증한다. 백업 복원은 U5다. |
| NFR4.1.3 | 반복의 각 구간에 IANA 시간대와 현지 날짜·주 기준을 보존하고 실행은 UTC instant로 처리 | 가구 기본 시간대와 계정 표시 시간대를 변경해도 기존 일정과 완료 이력이 이동하지 않는지 확인한다. |
| NFR4.2.3 | DST 간격과 중첩, 월말·종료일·첫 주·주 anchor 규칙은 단일한 결과를 낸다 | 서머타임 간격·중첩 사례와 윤년, 특정 31일, 종료일 당일, 주간 기준 변경을 표준 벡터로 검증한다. |
