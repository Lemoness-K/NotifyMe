# U3 보안 요구사항

## Sources

U3의 `functional-spec.md` 및 `rules.md`, 승인된 `requirements.md`, `contract-summary.md`, `technology-stack.md`와 현재 U1·U2의 실행 환경을 사용한다.

## Requirements

| ID | 요구사항 | 확인 방법 |
| --- | --- | --- |
| NFR1.1.4 | 업무 요청은 유효 세션과 승인된 신원 교환 규칙을 따른다 | 만료 및 취소 시 업무·이력·검증·삭제 읽기와 쓰기가 거절된다. |
| NFR1.2.3 | 업무·회차·검증·삭제에서 호출자의 현재 가구 접근과 작업별 자격을 검사 | 적격 지정 검증자만 응답하고 제출자만 철회한다. 소속 회수와 응답이 경합하는 경우 먼저 커밋한 합법 상태만 남는다. |
| NFR1.3.3 | 다른 가구의 대상, 피드, 요청 키 및 삭제 증거를 묶지 않는다 | 다른 가구의 같은 형태 식별자·revision 요청과 타 주체 키를 시험해 데이터 및 존재를 공개하지 않는다. |
| NFR2.1.3 | 장소 좌표는 조건의 승인된 사용 경계에서만 읽고 이력·로그·삭제 기록에는 남기지 않는다 | 합성 위치를 넣어 API 접근 범위와 감사 및 운영 기록을 대조하고 삭제 뒤 원문이 남지 않는지 확인한다. |
| NFR2.3.3 | 사용자 이력은 가구 인가 범위에 한정하고 독립 삭제 기록과 운영 로그 접근을 분리 | 일반 사용자·운영자 권한별로 조회 표면을 검증한다. 승인된 보존 기한에 맞는다. |
