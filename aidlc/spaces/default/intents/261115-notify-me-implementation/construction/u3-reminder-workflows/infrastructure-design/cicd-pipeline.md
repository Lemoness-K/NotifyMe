# U3 CI/CD 설계

## Build and Test

| 단계 | 검증 |
| --- | --- |
| 설치 및 빌드 | Node.js 24, `npm ci`, Prisma 생성, 타입 검사, 기존 Vite/NestJS 빌드 |
| DB와 원장 | 빈 DB 및 U2 데이터가 있는 DB에 순방향 마이그레이션, 조건부 쓰기 경쟁, 디스크 오류와 내구 기록 실패, U5 대역 경계에 대한 정확한 재시도만 허용하는지 검증 |
| 웹 | 순차·동시 업무 변경, 한국어/영어, 큐 정렬과 커서 분리, 좁거나 넓은 뷰포트와 줌·키보드·터치 및 권한 거부 흐름. NFR6.1.3~NFR6.4.3 및 NFR7.1.3~NFR7.5.3 |
| 회귀 | 기존 `npm run verify:u1`에 U3를 연결해 U1/U2와 함께 실행한다. Red/Green 증거와 전체 라인 80%를 확인한다. NFR9.1.3~NFR9.3.3 |
| ARM64 | ARM64 Node 24에서 native 모듈 로드, 격리된 DB 마이그레이션, 실제 SQLite 트랜잭션의 커밋·롤백을 검증한다. 대상 Pi는 별도 기록한다. NFR8.2.3 |

## Promotion and Rollback

1. 개발 및 CI에서는 임시 DB와 원장을 사용한다. 테스트 인증 설정은 외부 계정 없이 동작한다.
2. Pi 배포 승인 후 서비스 계정 접근과 원장 경로를 점검한다. DB 마이그레이션 전후 native 트랜잭션 및 loopback 상태와 HTTPS 동작을 확인한다.
3. 실패 시 Caddy 경로와 systemd 상태를 확인하고 적용된 마이그레이션과 호환되는 앱으로만 코드 롤백한다. DB 교체가 필요한 경우 원장을 유지한 채 인스턴스를 격리한다. 복원과 삭제 재적용 검증은 U5에서 수행한다.

## Secrets

기존 운영 서비스 환경 파일과 권한을 유지한다. CI는 제품의 DB·독립 저널·운영 자격 증명을 사용하지 않는다.
