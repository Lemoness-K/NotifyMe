# U3 구현 결과

## Summary

- 기존 업무·배정·가구 설정을 유지하는 순방향 SQLite 마이그레이션을 추가했다. 시간 또는 장소 조건, 반복 구간과 회차별 예외, 완료 시도, 이력·피드·DB 삭제 커밋 증거를 각각 저장한다.
- 반복 회차의 월말·일광절약시간·종료일을 계산한다. 완료 검증은 D-094~D-096을 적용하며 여러 담당자, 승인·철회·소속 회수의 경합을 서버에서 처리한다.
- 가구 범위별 할 일, 검증 대기, 이력, 보관·복원을 공유 웹에 연결했다. 가구 정책과 계정 언어 및 표시 시간대에 맞춰 회차와 상태를 표시하고 삭제를 확인한다.
- 같은 삭제 작업 ID로 운영 DB와 별도 SQLite 원장의 처리 상태를 연결한다. 누락·잘못된 원장, 시간 초과한 독점 핸들, 미확정 삭제는 정상 완료로 처리하지 않는다. 다른 작업 키가 같은 리마인더를 먼저 삭제했을 때는 해당 커밋 증거를 확인해 뒤따른 요청을 명시적으로 중단한다. 유지보수 흐름이 반복 작업과 정리를 실행한다.

## 문서 변경 이력 재검토

- U3 구현 커밋 `b21d350`의 변경분과 현재 문서를 대조했다. `docs/00-master-design.md`의 F-REM-009 선택적 완료 검증, `docs/01-product-requirements.md`의 PR-AC-069 검증자 자격·철회·소속 회수, `docs/decision-register.md`의 D-094~D-096 확정 결정과 Q-066~Q-068 질문 이력을 매니페스트에 추가했다.
- 결정 등록부는 U4의 D-097 신규 설치 위치 감지 결정과 U5의 D-098 운영 보고 전달 결정도 담고 있다. 해당 변경 이력은 각각 `5bf6785`와 `2035730`에서 확인했다. 현재 U3 문서의 해당 정책은 기존 회차 동작 및 HTTP 테스트와 대조했다.
- 아래 Verification 표와 Red/Green 기록은 U3 최초 구현의 결과다. 앞선 재검토에서는 문서의 Git 이력과 검토 범위를 확인했고, 당시 체크아웃에서 U3 전용 Vitest의 테스트 38개가 통과했다.

## 현재 재검증

- `b21d350`의 AI-DLC 기록 외 변경 경로 39개를 소스 매니페스트와 대조했다. 세 설계 문서를 포함해 39개 전부 일치했다. 공유 결정 등록부는 검증자 자격, 요청 철회 및 소속 회수(D-094~D-096)의 U3 변경과 신규 설치 지오펜스 용량(D-097), 로컬 운영 보고(D-098)의 후속 변경을 Git 이력으로 구분했다.
- U3 전용 Vitest는 7개 파일에서 38개가 통과했다. 승인된 `npm run verify:u1`은 타입 검사, 빌드, Vitest 211개, Playwright 4개를 통과했고 전체 라인 커버리지는 87.26%였다. U3 브라우저 시나리오는 11.5초에 통과했다.
- Chromium의 탭 페이지 확대를 200%로 설정하는 보조 검증은 이 환경에서 실행을 완료하지 못했다. 전체 Chromium은 `libatk-bridge-2.0.so.0`, `libcairo.so.2`, `libpango-1.0.so.0`가 없어 시작하지 못했다. 기존 헤드리스 셸에서는 합성 계정으로 앱에 진입한 뒤 확대를 설정하는 확장 서비스 워커가 시작되지 않았다. 브라우저 확대는 미검증 상태다. 별도로 기존 Playwright 시나리오의 320·420·850 CSS px 가로 넘침 검사는 통과했다.

## Independent review repairs

- 무담당 업무에서도 지정 검증자가 자기 요청을 제출하거나 승인·거절할 수 없도록 서버와 호출자별 동작을 함께 수정했다.
- 전체 반복 수정과 이후 재실행에 앞선 논리적 회차를 대조해 확정 회차 및 검증 대기의 ID와 상태를 보존한다.
- 내구 증거와 요청이 일치하고 삭제 대상을 확인할 수 있을 때 백그라운드 유지보수가 운영 DB 추가 삭제 없이 원장 기록을 확정한다. 증거가 불충분한 작업은 대기로 남는다.
- 새 순방향 마이그레이션은 삭제된 CREATE의 범위와 입력 해시를 남겨 지연된 재실행을 차단한다. 삭제 본문과 결과는 계속 제거한다. U1에서 생성한 업무의 같은 입력은 U3 업그레이드 후 기존 업무를 반환한다.

## API and configuration

- 기존 API 호환을 유지하면서 회차 조회의 `allowedActions`, 상세의 `pendingVerificationCount`, 검증 필터와 `WITHDRAW_VERIFICATION`을 적용한다. 활성 목록의 추가 `sections` 값은 업무 ID별 서버 분류를 제공한다. 회차 예외는 해당 회차에만 적용하며, 이력의 `reminderId`로 업무별 필터를 사용할 수 있다.
- 서비스 예제에서 운영 DB와 다른 `NOTIFY_DELETE_JOURNAL_PATH`를 지정하고 서비스 디렉터리와 파일 권한을 제한한다. Node.js 24 ARM64에서 SQLite 모듈과 실제 마이그레이션·트랜잭션을 시험했다.

## Remaining verification

- 대상 Raspberry Pi의 부하·자원·조회 지연과 실제 Google/Firebase 연동은 운영 환경에서 별도 검증한다.
- U4 실제 Android 설치·OS 재조정은 계획 참여 포트 범위 이후의 작업이다.
- U5는 실제 스냅샷의 증거·내용을 검증하고 암호화 백업, 격리 복원 및 삭제 재적용의 운영 훈련을 맡는다. U3의 테스트에서는 스냅샷 대역과 함께 미확정 삭제 또는 만료된 독점 핸들이 기준점을 발행하지 못하는지 확인했다. 실제 반복 규칙의 수정에서는 빈 값의 의미를 승인된 요청 계약에 맞춰 유지한다. 반복 종료는 현지 종료일로 지정한다.
