# 로컬 상관 분석

웹, 단일 NestJS 런타임, SQLite와 로컬 운영 작업의 경계는 기존 로그와 상태 조회로 확인한다. 중앙 추적 수집기와 외부 전송은 후속 범위다.

| 경계 | 상관 증거 |
| --- | --- |
| 앱 및 작업 시작·종료 | systemd 유닛, 관측 시각, 오류 상태 코드 |
| 관측 이벤트 | `LOCAL_OPERATIONS`의 `id`, UTC `at`와 `kind`. 재전송은 같은 ID의 중복 기록으로 해석 |
| 백업 | `BACKUP_FINISHED`의 결과 및 시작·완료 시각. 성공 시 불투명 백업 ID |
| 보호 API·Android | 성능 또는 합성 검증에서 고정 경로 코드와 시험 시간 구간으로 묶는다. 현재 저장소에 전체 요청의 분산 추적 이력이 존재한다고 가정하지 않는다. |

진단 범위를 넓힐 때에도 본문, 토큰, 좌표, 가구 식별값을 상관 키로 사용하지 않는다. [로그 조회](log-queries.md)
