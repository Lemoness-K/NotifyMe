# 서비스 지표와 검증 목표

| 지표 | 계산·증거 | 목표와 범위 |
| --- | --- | --- |
| 보호 API p95 | 인증·인가·DB 처리를 포함한 요청 소요 시간 표본을 경로별로 집계 | DS-014 대상 Pi의 승인된 부하와 측정 구간에서 p95 ≤ 500ms. 각 경로의 표본 수와 시간 구간도 기록 |
| 헬스와 오류 | 로컬 `READY`, `UNAVAILABLE`, `CHECK_FAILED`를 별도로 집계. 호스트가 동작하지 않아 표본이 없는 시간을 별도 표기 | 운영 가용성 목표와 관측 창은 추후 결정. 요약 이벤트 빈도만으로 가용률을 계산할 수 없다. |
| API 오류율 | 성능 시험에서 보호 경로 요청 수와 5xx·전송 실패 수를 수집. 예상된 인가 거절은 별도 분류 | 이번 단계는 계측 계획을 기록. 운영 오류율 목표·경보 기준은 추후 |
| RSS와 저장장치 쓰기량 | 같은 시험 구간에서 피크 RSS와 장치 쓰기 증가량을 별도로 측정 | 대상 Pi 및 수치 예산은 DS-014에서 확정 |
| 백업과 관측 작업 | 예정 횟수, 성공·실패·미실행 횟수를 보고한다. 기록은 유닛과 구조화 이벤트에서 확인 | 장기 성공률과 복구 목표는 후속 검증 |

U5는 백업 중 보호 API p95와 삭제의 최대 차단 시간을 따로 수집한다. 차단 시간의 합격 기준은 실제 시험 조건 마련 후 판단한다. [U5 성능 설계](../../construction/u5-operations-and-recovery/nfr-design/performance-design.md)

대표 보호 경로는 U1 목록·상세, U2 구성원·설정, U3 할 일·상세·이력, U4 설치 동기화·용량 조회다. U5 백업과 삭제가 겹치는 구간은 별도로 측정한다. 개발 시험 시간과 런타임 테스트 통과를 Pi 실측값으로 사용하지 않는다. [성능 테스트 계획](../../construction/build-and-test/performance-test-instructions.md)
