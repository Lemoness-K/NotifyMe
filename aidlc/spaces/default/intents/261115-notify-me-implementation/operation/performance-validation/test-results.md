# 성능 시험 결과

## 실행 환경

2026-11-23, 앱 소스 커밋 `ea062ca`에서 빌드를 다시 실행한 뒤 [예비 시험 코드](load-probe.mjs)를 실행했다. Raspberry Pi 5 Model B Rev 1.1, Linux ARM64, Node v24.21.0, 약 7,932 MiB 시스템 메모리, 작업 폴더 ext4 환경이다. 임시 SQLite 본체 파일은 측정 종료 시 786,432바이트였다. 이 값에 SQLite WAL 크기나 장치가 기록한 쓰기량은 포함되지 않는다.

`npm run build`와 예비 시험 명령은 종료 코드 0이었다. 집계 요청 2,160건이 모두 HTTP 200을 반환했다. HTTP 비정상 응답과 전송 오류는 0건이다. 준비 요청 216건과 데이터 준비용 등록 100건은 집계에서 제외했다.

## 해석

- 이 시험에서 가장 높은 경로별 p95는 동시 요청 8개의 목록 조회에서 나온 86.28ms였다. 목록에 응답 지연이 상대적으로 집중됐으며 단일 반복의 관찰값이다. 데이터 규모에 따른 페이지 비용과 쿼리 경합은 후속 검증으로 남았다.
- RSS 최고 표본은 442.93 MiB였다. 서버·부하 클라이언트가 한 프로세스에서 순차 실행한 관찰값이다. 제품 프로세스 단독 예산 비교, 저장장치 물리 쓰기량, 장시간 안정성은 검증되지 않았다.
- 외부 인증, Caddy/TLS, Android 동기화, U5 백업·삭제 동시 부하와 복구는 이 시험의 범위 밖이다. 운영 기동과 배포 적합성은 별도 근거가 필요하다.

시험 절차와 확대 조건은 [부하 시험 계획](load-test-plan.md), 공식 목표 상태는 [NFR 검증표](nfr-validation-matrix.md)에 기록했다.
