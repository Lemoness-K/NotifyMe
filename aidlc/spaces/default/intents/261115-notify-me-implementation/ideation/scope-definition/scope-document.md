# Notify Me 범위 정의

## 범위 기준과 출처

이번 작업은 기존 설계 문서에 정의된 Notify Me MVP를 상세 설계하고 구현한다. 기능 범위의 기준은 [마스터 설계 §7](../../../../../../../docs/00-master-design.md#7-mvp-제안-범위), 사용자 동작과 수용 기준은 [제품 요구사항](../../../../../../../docs/01-product-requirements.md), 우선순위와 상세 설계 순서는 [기능 설계 커버리지 및 백로그 §4](../../../../../../../docs/09-feature-design-coverage-and-backlog.md#4-구현-전에-진행할-상세-설계-작업)다. 이번 작업의 의도와 초기 경계는 [intent-statement](../intent-capture/intent-statement.md)에 기록되어 있다.

기존 문서는 계속 기준 문서로 사용한다. 이 범위 정의는 기존 설계 문서를 대체하거나 폐기하지 않는다. 아래에서 승인된 두 기능 추가는 요구사항 분석 단계에서 수용 기준과 ID를 정하고, 마스터 설계·제품 요구사항·추적표 등 해당 기준 문서에 반영한다. 확인이 필요한 세부 정책은 결정 전까지 미결정으로 유지한다.

## 이번 작업에 포함

### 문서화된 MVP 기준 범위

- 상세 설계, 구현, 자동 검증, 필요한 Android 검증, Raspberry Pi 배포 준비를 완료한다.
- MVP 기능은 마스터 설계 §7.1 및 세부 문서의 관련 요구사항을 따른다. 주요 영역은 계정·단일 가구·구성원 관리, Reminder 생성과 관리, 목록·완료 이력·보관함, 반복 회차, Android 시간·위치 알림, 설정, 접근 통제, 로그·백업·복구다.
- 설계와 구현은 [테스트 전략](../../../../../../../docs/08-test-strategy.md)의 개발 루프 및 환경 분리 원칙을 따른다. 자동 검증에 운영 계정·운영 데이터·실제 외부 서비스 자격 증명을 사용하지 않는다.
- 기존 설계가 이미 정한 기술·제품 결정을 우선 적용하고, 결정되지 않은 동작을 임의로 확정하지 않는다.

### 이번 작업에서 승인된 MVP 범위 추가

- **선택적 완료 검증 (`Q-063`)**: Reminder마다 완료 검증을 선택적으로 설정한다. 담당자의 완료 표시는 검증 대기 상태로 전환하고, 지정된 검증자의 승인은 완료로 확정하며, 거절은 미완료 상태로 돌린다. 검증 응답이 없을 때는 검증 대기 상태를 유지한다. 검증자 알림은 필요할 때 제공한다. 검증자 권한, 대기 상태 해소·재알림 정책, 구체적인 데이터·화면 동작은 요구사항 분석과 상세 설계에서 정한다.
- **운영자 주간 보고 및 즉시 장애 알림 (`Q-064`)**: 서비스 운영자가 주간 운영 보고를 받고, 장애가 발생하면 즉시 알림을 받을 수 있도록 한다. 보고 내용, 장애 판정·중복 억제 기준, 수신자 자격과 전달 채널은 상세 설계에서 정한다. 기존 문서에 없는 유료 서비스나 외부 사업자 사용을 전제하지 않는다. 비용 또는 외부 계정이 필요한 선택은 별도 확인 후 정한다.

두 추가 기능의 포함 결정은 기록되었지만, 이 문서는 세부 동작의 미결정 사항까지 확정하지 않는다. Q-063·Q-064는 정식 요구사항과 추적성 갱신 단계에서 관련 ID 및 검증 위치에 연결한다.

## 이번 작업에서 제외

- 마스터 설계에서 MVP 이후로 분류한 기능과 [후속 작업 목록 §5](../../../../../../../docs/09-feature-design-coverage-and-backlog.md#5-기능-단계가-도래한-뒤-상세화할-항목)에 있는 기능은 이번 구현에 포함하지 않는다. 예: iOS 앱·iOS 알림, 추가 인증 제공자, 사용자 계정 삭제·가구 종료 흐름, 다중 가구 전환 UI, snooze, 고급 검색·필터와 캘린더, 고급 반복 규칙, 데이터 내보내기, 상용 운영자 콘솔.
- Play Store 배포, 결제·구독, 캘린더·메신저·음성비서 연동, 파일 첨부·댓글·우선순위·태그, RFC 5545 전체 반복 규칙, 완전한 오프라인 편집과 기기 간 충돌 해결은 제외한다.
- 운영 Raspberry Pi에 실제 설치·배포하거나 서비스를 외부 인터넷에 공개하고 라우터 포트를 여는 일은 제외한다. 배포 파일·운영 절차·사전 점검 등 배포 준비는 포함한다.
- 기존 후속 기능은 버리거나 deprecate하지 않는다. `docs/09-feature-design-coverage-and-backlog.md`의 후속 범위로 보존하고, 별도의 이후 작업에서 범위를 다시 정해 진행한다.

## 순서와 제약

- 별도의 완료 기한은 정해지지 않았다.
- 상세 설계 순서는 기존 로드맵을 따른다. 우선 `DS-002`부터 `DS-003`, `DS-004`, `DS-005` 보완, `DS-010`, `DS-006`, `DS-007`, `DS-011`, `DS-009` 순으로 진행한다. 기존 우선순위와 의존성은 [로드맵](../../../../../../../docs/09-feature-design-coverage-and-backlog.md#41-전체-실행-로드맵과-현재-위치)을 따른다.
- Q-063의 제품 규칙은 Reminder 화면·도메인·API·검증 설계에 반영한다. Q-064의 운영 보고와 장애 알림은 상태 관측, 알림 전달, 보안 및 배포 준비와 함께 상세화한다. 요구사항 분석에서 대상 기능과 추적 항목을 확정한 뒤 작업 단위 및 설계 순서에 반영한다.
- 테스트 전략에 따라 코드 변경에는 해당 동작의 자동 검증을 포함하고, OS 의존 Android 기능은 필요한 에뮬레이터·실기기 검증 절차와 결과를 구분한다. Raspberry Pi 실배포 검증은 실제 설치를 수행하지 않고 배포 준비 범위로 제한한다.

## 범위 완료 기준

- 문서화된 MVP와 두 승인된 범위 추가가 요구사항·수용 기준·설계·테스트 추적표에 연결되어 있다.
- 세부 설계와 구현이 승인된 요구사항 및 기존 결정과 일치하며, 미결정 정책을 임의로 가정하지 않는다.
- 테스트 전략에서 이번 작업에 해당하는 자동·Android 검증과 배포 준비 결과가 기록되어 있다.
- 기존 문서화 후속 기능은 이번 구현에서 제외된 상태로 보존되어 있다.

## 미결정 사항

- 완료 검증을 지정할 수 있는 구성원·권한, 검증 요청 만료·재알림, 검증 취소 및 반복 회차와의 상호작용.
- 운영자 정의, 보고서 내용·주기 기준 시간대, 장애 신호·판정 기준, 알림 전달 채널과 재시도 정책.
- 위 세부사항이 기존 기술 경계 안에서 해결되지 않거나 비용·외부 서비스·개인정보 범위를 바꾸면 구현 전에 사용자 결정을 받는다.
