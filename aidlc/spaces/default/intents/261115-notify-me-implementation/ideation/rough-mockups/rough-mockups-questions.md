## 기존 결정으로 해소된 항목

- 앱 진입 화면은 `할 일`이며, 주 내비게이션은 `할 일`·`이력`·`보관함`이다 (`D-072`, `D-079`, `PR-AC-064`).
- `할 일` 안에는 `내 할 일`·`내가 요청한 일`·`가구 전체 보기`가 있고, 좁은 화면은 선택 메뉴로 전환한다 (`D-076`, `D-078`, `PR-AC-063`).
- 모바일·태블릿·데스크톱에 대응하고, 최소 320 CSS px부터 넓은 화면까지 가로 넘침 없이 재배치한다 (`PR-AC-043`). Android와 브라우저는 주요 공유 UI를 사용한다.
- 이력은 담당 Reminder 범위로 시작하고, 보관함은 최근 보관 순서다 (`D-080`, `D-088`, `D-089`).
- 완료 검증은 선택 기능이며 담당자 완료 후 검증 대기, 승인, 거절·미응답 동작을 표시한다 (`Q-063`, 의도서). 검증자 권한과 세부 상태 처리는 후속 설계에 남겨 둔다.
- 운영자 주간 보고와 즉시 장애 알림은 운영 흐름으로 표현한다 (`Q-064`). 사용자용 운영 콘솔을 새로 만들지 않으며 보고·알림 채널은 미결정으로 둔다.

## 가정 및 미결정 사항

- 저장소에서 기존 브랜드 자산이나 디자인 시스템을 찾지 못했다. 이번 결과는 색상·서체를 확정하지 않는 저충실도 구조 스케치로 만들고, 화면은 중립적인 텍스트·선으로 표현한다.
- **사용자 요청 — 향후 UI 가이드 적용**: 나중에 UI 가이드가 정해져도 큰 코드 수정 없이 view 계층 중심으로 반영할 수 있도록 화면 표현과 사용자 동작·업무 흐름의 경계를 설계에 포함한다. 공통 표현 요소와 화면 구성의 변경 지점은 보이되, 정확한 코드 구조와 기술 선택은 후속 상세 설계에서 정한다.
- 정확한 넓은 화면 내비게이션 배치와 breakpoint는 기존 설계대로 추후 상세 설계에서 확정한다 (`DS-002`, `DS-005`).
- `Q-063` 검증 동작의 권한·미응답 처리 세부사항과 `Q-064` 운영자·보고 내용·장애 기준·전달 채널은 초기 사용자 흐름에서 선택지로 표시하고, 임의의 정책은 추가하지 않는다.

## Consolidated Summary Confirmation

다음 해석으로 저충실도 화면 구성과 사용자 흐름을 작성합니다.

- 기존 문서가 정한 `할 일` 기본 진입, `할 일`·`이력`·`보관함` 내비게이션, 세 가지 할 일 보기와 이력·보관함 동작을 유지한다.
- 모바일 우선으로 브라우저·Android 공유 UI를 스케치하고 tablet·desktop 재배치, 키보드 접근과 색상 외 상태 표시를 고려한다. 기존 결정이 정하지 않은 breakpoint와 넓은 화면 배치는 확정하지 않는다.
- 나중에 UI 가이드가 제공되면 화면 view 계층 중심으로 스타일과 배치를 적용할 수 있도록 구조를 표시한다. 화면 표현은 공통 구성요소를 통해 일관되게 바꾸고 사용자 동작·업무 흐름은 view 변경에 종속시키지 않는다. 구체적인 코드 구조는 후속 상세 설계에서 정한다.
- Reminder 생성·상세·완료와 선택적 검증 흐름을 표현하되 Q-063의 미결정 정책은 열어 둔다.
- 주간 보고와 장애 알림은 별도 운영자 콘솔 화면 없이 운영 흐름으로 표현하고, 채널·판정 기준은 열어 둔다.
- 브랜드가 정해지지 않았으므로 중립적인 저충실도 스케치만 작성한다. 기존 설계 문서는 계속 기준으로 사용한다.
