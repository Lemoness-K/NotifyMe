# Notify Me 의도 단계 결정 기록

이 기록은 현재 작업에서 승인된 범위와 의도 단계의 결과를 연결한다. 기존 결정 등록부와 설계 문서는 원본으로 유지하며, 여기서는 관련 내용을 요약하고 현재 작업에 미친 영향을 기록한다.

## 범위와 제품 방향

| 기록 | 내용 | 현재 처리 및 근거 |
|---|---|---|
| Intent Capture Q1 — 그룹의 부탁을 잊지 않고 수행하도록 돕는 리마인더 | 가구 구성원은 부탁을 등록하고 담당자는 수행을 표시한다. 일반 완료는 담당자의 완료 표시로 확정한다. | 승인된 기본 흐름. [의도서](../intent-capture/intent-statement.md) |
| Intent Capture Q2 — 첫 버전의 주요 사용자 | 첫 사용자는 가족·동거 가구 구성원이다. | 주요 사용자로 반영. [의도서](../intent-capture/intent-statement.md) |
| Intent Capture Q5 — 이해관계자의 관심사 | 가구 구성원은 부탁 등록과 수행 확인을, 운영자는 저비용·안정 운영을 중시한다. | 실제 가구 구성원의 별도 동의나 사용성 확인은 기록되지 않았다. [이해관계자 지도](../intent-capture/stakeholder-map.md) |
| Intent Capture Q6 — 범위 결정자와 의견 제공자 | 요청 사용자가 범위를 결정하고 실제 가구 사용자가 사용성 의견을 보탠다. | 다른 가구 사용자의 합의는 확인되지 않았다. [이해관계자 지도](../intent-capture/stakeholder-map.md) |
| Intent Capture Q7 — 주간 운영 보고와 즉시 장애 알림 | 프로젝트 초기에는 두 기능이 필요하며 이후 제거 가능한 선택 기능으로 다루길 요청했다. | 현재 작업에 포함. 내용·운영자·기준·채널은 후속 설계에서 결정. Q-064와 연결. |
| Intent Capture Q8 — 첫 작업의 제품 범위 | 문서화된 MVP를 현재 작업의 기준으로 삼는다. | 범위 정의에서 Q-063·Q-064 추가가 별도 승인되었다. [범위 정의](../scope-definition/scope-document.md) |
| Intent Capture Q12 — 현재 MVP와 후속 기능의 경계 | 나머지 MVP 이후 기능은 현재 구현에서 제외하고 후속 작업에서 범위를 다시 정한다. | 이번 사용자가 후속 항목을 지금 제외하고 나중에 추가하자고 재확인했다. [범위 정의](../scope-definition/scope-document.md), [백로그](../scope-definition/intent-backlog.md) |
| Intent Capture Q9 — Raspberry Pi 설치 및 외부 공개 | 이번 작업은 코드·검증·배포 준비까지 진행하고 실제 설치와 외부 공개는 하지 않는다. | 배포 준비까지만 범위에 포함. [의도서](../intent-capture/intent-statement.md) |
| Q-063 — Reminder별 선택적 완료 검증의 첫 출시 포함 | 담당자의 제출 후 검증 대기, 검증자의 승인·거절 흐름을 현재 범위에 추가했다. | 현재 작업 범위에는 포함. 권한·기한·재알림·미응답 처리의 제품 규칙은 미결정이며 Requirements Analysis에서 다룬다. 결정 등록부의 원 질문은 정책 정합화 전까지 열린 상태로 보존한다. |
| Q-064 — 주간 운영 보고와 즉시 장애 알림의 첫 출시 포함 | 운영자용 주간 보고와 장애 알림을 현재 범위에 추가했다. | 현재 작업 범위에는 포함. 운영자 자격·보고 내용·장애 판정·전달 정책은 미결정이며 Requirements Analysis와 운영 설계에서 다룬다. 결정 등록부의 원 질문은 정책 정합화 전까지 열린 상태로 보존한다. |

## 기존 설계 결정의 적용

기존 결정 등록부의 최신 상태가 이 요약보다 우선한다. 이번 작업은 관련 결정을 재승인하거나 바꾸지 않는다.

| 결정 | 요약 | 적용 |
|---|---|---|
| D-011 — MVP의 상시 네트워크 연결 전제 | 앱과 Raspberry Pi 서버는 집 안팎에서 HTTPS로 연결할 수 있는 제품 동작을 전제로 한다. | 제품 설계 기준으로 유지. 이번 작업에서 운영 장비를 설치하거나 인터넷에 공개하지는 않는다. |
| D-019 — 가구·개인 설정과 기기 상태 분리 | 가구 설정, 개인 설정, OS 권한·기기 상태를 구분한다. | 화면과 설정 설계에서 유지. |
| D-052 — 공유 TypeScript UI와 플랫폼별 어댑터 | 반응형 Web UI를 공유하고 Android 네이티브 기능은 Kotlin 어댑터로 분리한다. | 기존 기술 기준으로 유지. |
| D-053 — Raspberry Pi의 SQLite 데이터베이스 | MVP는 로컬 영속 저장소의 SQLite와 단일 Worker 운용을 기준으로 한다. | 기존 기술 기준으로 유지. |
| D-057 — Caddy 기반 HTTPS 진입 | DDNS·HTTPS·정적 UI 제공·API reverse proxy 경계를 정의한다. | 배포 설계에서 기준으로 사용하되 실제 외부 공개는 별도 승인 전 수행하지 않는다. |
| D-072 — 기본 진입은 `할 일` | 앱 진입 시 담당자의 할 일부터 확인한다. | 승인된 화면 구성의 기준. |
| D-078 — 목록 보기 선택의 반응형 표현 | 넓은 화면에서는 세 보기 버튼, 좁은 화면에서는 현재 선택을 보여주는 메뉴로 전환한다. | 화면 상세화의 기준. |
| D-079 — `할 일`·`이력`·`보관함` 주요 내비게이션 | 세 영역을 주요 내비게이션으로 제공하고 모바일에서는 하단 메뉴를 사용한다. | 승인된 화면 구성의 기준. |
| D-080 — 이력의 기본 조회 범위 | 현재 로그인 사용자가 담당자로 지정된 Reminder의 이력으로 시작하고 가구 전체 이력으로 전환할 수 있다. | 상세 화면 설계에서 유지. |
| D-081 — 이력 표시 순서 | 완료·놓침·건너뜀 회차를 한 목록에 표시하고 상태 발생 시각 최신순으로 정렬한다. | 상세 화면 설계에서 유지. |
| D-088 — 이력 재진입 기본값 | 이력 화면에 다시 들어올 때마다 담당 Reminder 범위로 초기화한다. | 상세 화면 설계에서 유지. |

## 검토 결과와 열린 위험

- **R-01 — 검증 대기 항목의 검증자·담당자 화면 배치:** Rough Mockups 검토의 minor finding이며 사용자가 수용 위험으로 남겼다. 검증자의 할 일에는 표시하고 작업자의 화면에서는 별도 탭에서 확인하는 제안은 후보일 뿐 확정되지 않았다. Requirements Analysis에서 화면·권한 요구사항으로 정리한다.
- **Q-063 — 선택적 완료 검증:** 이번 작업 범위에는 들어가지만 상세 업무 규칙은 열린 상태다. 요구사항 분석에서 미응답·재알림·취소·반복 회차 상호작용을 정리한다.
- **Q-064 — 주간 보고·장애 알림:** 이번 작업 범위에는 들어가지만 운영 규칙은 열린 상태다. 운영자 정의, 보고 주기와 내용, 장애 임계·중복 억제, 채널·재시도 정책을 정리한다.
- Market Research와 Feasibility 단계는 현재 `classic` 작업 경로에서 실행하지 않았다. 시장 수요나 공식 실현 가능성이 검증된 것으로 기록하지 않는다.
- Team Formation 단계는 실행하지 않았다. 인력·일정 확약은 없으며, 필요한 경우 후속 계획에서 구체화한다.
- 기존 MVP 이후 기능은 후속 범위로 보존한다. 새로운 후속 기능을 현재 작업에 임의로 추가하지 않는다.

## 인계 기준

1. 기존 설계 문서와 결정 등록부를 계속 기준으로 사용한다.
2. Requirements Analysis는 Q-063 (선택적 완료 검증)과 Q-064 (운영 보고·장애 알림)의 요구사항·수용 기준·추적 ID를 구체화하고, 원 결정 등록부와의 정합성을 다룬다.
3. R-01 (검증 대기 항목의 화면 노출)은 확정 요구사항으로 바꾸지 않고 적절한 사용자 결정 시점까지 열린 상태로 유지한다.
4. 현재 범위 밖의 MVP 이후 기능은 기존 백로그에서 관리하고 별도 후속 작업에서 범위를 정한다.
5. 실제 Raspberry Pi 설치와 외부 공개는 이번 작업 범위 밖으로 둔다.
