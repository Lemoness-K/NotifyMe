# Refined Mockups — 설계 기준과 확인

## 추가 질문 검토

현재 승인된 요구사항, 사용자 스토리와 기존 화면 설계가 제품 동작·접근성·언어·반응형 방향을 이미 정하고 있으므로 새 제품 정책 질문은 추가하지 않는다. Q-063 완료 검증 세부사항과 Q-064 운영 보고·장애 알림 전달 정책은 열린 상태로 유지한다.

아래 설계 요약은 기존에 승인된 동작을 화면 구조로 옮기는 제안이다. 넓은 화면의 내비게이션 배치와 표현 토큰은 이 단계 mockup의 검토 대상이며 새 도메인 규칙을 만들지 않는다.

## 적용할 기존 답변과 결정

- 주요 목적지는 `할 일`, `이력`, `보관함`이고 앱 진입 화면은 `할 일`이다. 모바일 주요 내비게이션은 하단에 둔다 (`D-079`).
- 할 일 세 보기의 이름을 나란히 놓기 어려우면 현재 선택값이 보이는 선택 메뉴로 바꾼다 (`D-078`).
- 지원 가능한 디스플레이 폭에 최소값을 두지 않는다. 이전 거친 와이어프레임의 320 CSS px 표기는 최소 지원 경계로 사용하지 않으며, 예시 viewport도 지원 범위를 제한하지 않는다 (`NFR6.1`, `NFR-UX-001`).
- 화면과 업무 동작을 분리하고, 이후 UI 가이드는 공통 표현 요소·view 계층에서 적용한다. 현 단계에서 브랜드 색상·서체·로고 값을 새로 정하지 않는다.
- 사용자용 화면은 WCAG 2.1 AA를 목표로 한다. 상태를 색상만으로 전달하지 않고 키보드·터치·스크린 리더를 지원한다.
- 화면은 loading, empty, success, error, partial 상태를 고려한다. 오류와 권한 부족은 가능한 경우 입력을 보존하고 복구 경로를 안내한다.
- 선택적 완료 검증은 승인된 흐름만 표현하고 Q-063의 세부 권한·취소·만료·재알림 정책을 만들지 않는다. 운영 보고·장애 알림은 별도 운영자 콘솔로 표현하지 않고 Q-064 세부 정책을 만들지 않는다.

## 통합 설계 요약

1. 가구 초대·로그인, 할 일 목록, Reminder 생성·상세, 이력, 보관함·삭제 확인, 설정의 핵심 화면을 다룬다. 서비스 운영 흐름은 제품 앱의 새 화면을 추가하지 않는다.
2. 좁은 가용 폭에서는 단일 콘텐츠 열과 하단 주요 내비게이션을 사용한다. 더 넓은 화면은 상단 가로 내비게이션과 제한된 콘텐츠 폭을 권고한다. 보기가로/세로 전환은 기기 명칭이나 최소 너비가 아니라 제목·버튼·콘텐츠가 들어맞는지에 따라 정한다.
3. 모든 가용 폭에서 내용을 유동적으로 재배치하고 가로 넘침을 만들지 않는다. 폭 전환 지점은 CSS viewport의 지원 최소값이 아니라 화면 요소의 레이아웃 전환 기준이다.
4. 색상·타이포그래피 등 브랜드 값은 확정하지 않고 의미 기반 디자인 토큰과 공통 컴포넌트 역할을 정의한다. 향후 UI 가이드는 표현 계층에서 적용한다.
5. 화면 문구는 `ko-KR`·`en-US` resource로 현지화하고, 사용자 작성 Reminder 문구는 입력 원문을 유지한다. 사용자 저장 locale이 기기 locale보다 우선하며, 최초 선택은 승인된 fallback 규칙을 따른다.
