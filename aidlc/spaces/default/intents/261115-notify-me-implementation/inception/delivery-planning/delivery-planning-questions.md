# Notify Me 구현 순서와 검증 계획 초안

## 확인된 출발점

- 구현 단위는 다섯 개다. U1은 로그인 → 리마인더 등록 → SQLite 저장 → 재조회까지 실제로 연결하는 최소 통합 흐름이다. U2는 가구·설정, U3는 리마인더 업무, U4는 Android 알림·동기화, U5는 운영·복구를 담당한다.
- Bolt는 완료 기준과 검증할 결과를 가진 한 번의 구현 작업이다. 한 단위를 한 Bolt로 두고, 현재 설정대로 단위별 설계와 구현 및 검증을 순차 진행하는 안을 제안한다. U4와 U5는 의존 관계상 독립 가능하다. 병렬 실행은 별도 실행 방식 변경이 필요하다.
- 승인된 계약은 로컬 인증 확인과 비운영 Firebase·Google 연동을 구분한다. 로컬은 합성 사용자로 실제 웹·API·SQLite 경로를 확인하고, 별도 승인된 테스트 환경이 준비되면 공급자 연동을 검증한다.
- 프로젝트에 실행 가능한 앱 검증 명령이 아직 없다. 구현에서 실제 명령이 마련된 뒤 첫 검증 전에 명령과 적용 범위를 확인한다. 테스트 우선 개발과 기존 검증·커버리지 기준을 계획에 반영한다.
- 공식 점수표 없이 사용자 가치와 위험으로 순서를 설명하는 안을 제안한다. 외부 환경이나 실기기가 필요한 검사에는 책임자, 필요한 시점과 환경 미확보 시 대체 검사 및 남는 한계를 기록한다.

## Q1. [구현 우선순위] 공통 기능 이후에 먼저 낮출 위험

최소 통합 흐름(U1), 가구·설정(U2), 리마인더 업무(U3)의 의존 순서는 정해져 있다. 이후 Android 알림 검증과 운영 복구 중 어느 쪽의 불확실성을 먼저 줄일지 선택한다.

- A. Android 알림을 먼저 실기기에서 확인한다. Android(U4)에서 백그라운드 알림·권한·재시작을 확인한 뒤 운영·복구(U5)를 통합한다. U3의 삭제 기록 계약 확인과 삭제 실패 시나리오 검증은 U3에 포함한다. (Recommended)
- B. 삭제 복구의 안전성을 먼저 확인한다. U3 완료 기준에 오래된 백업과 미확정 삭제를 사용한 합성 복구 시나리오를 추가한다. Android(U4)와 운영·복구(U5)의 전체 구현은 현재 순차 설정을 따른다.
- X. Other (please specify)

[Answer]: A. Android 알림 먼저

이 질문과 답변은 당시 기록으로 보존한다. 질문의 표현과 실제 선택 효과가 달라 답변을 계획에 적용하지 않는다. 아래 Q2에서 다시 결정한다.

## Q2. [구현 우선순위] Android 착수 전에 완료할 복구 검증

리마인더 업무(U3)에서 기록 누락이나 저장 실패 시 삭제 성공으로 응답하지 않는지 검증하고, 운영·복구(U5)에서 테스트 데이터로 전체 백업 복구 절차를 검증한다. 두 안에서 이 기준과 기능 구현 순서는 같다. 오래된 테스트 백업으로 하는 모의 복구까지 Android 알림(U4) 착수 조건에 넣을지 선택한다.

- A. Android 착수 전에는 삭제 기록과 실패 처리 검증까지 완료한다. 오래된 테스트 백업의 복원 검사는 U5에서 전체 복구 검증과 함께 한다.
- B. Android 착수 전에 오래된 테스트 백업으로 모의 복구까지 통과한다. 확정 삭제가 다시 나타나지 않고 미확정 삭제가 있으면 데이터 제공이 차단되는지 U3에서 확인한다. U5의 전체 복구 검증도 수행한다.
- X. Other (please specify)

[Answer]: A. Android 착수 전에는 삭제 기록과 실패 처리 검증까지 완료한다. 오래된 테스트 백업의 복원 검사는 U5에서 전체 복구 검증과 함께 한다.

## Consolidated Summary Confirmation

- U1부터 U5까지 단위별로 설계·구현·검증한다. 첫 단위(U1)는 인증된 사용자가 웹에서 리마인더를 등록하고 실제 SQLite에 저장된 내용을 재조회하는 최소 통합 흐름이다.
- 리마인더 업무(U3)에서 삭제 기록과 실패 처리 검증을 완료한 뒤 Android 알림·동기화(U4) 작업에 들어간다. 오래된 테스트 백업의 복원과 삭제 재적용, 서비스 재개 차단은 운영·복구(U5)에서 전체 절차로 검증한다.
- 테스트 우선 개발을 적용한다. 로컬 통합 검증, 승인된 비운영 환경의 Firebase·Google 연동 검증, Android 실기기 검증의 범위를 구분한다. 프로젝트에서 실행할 통합 검증 명령이 준비되면 승인받는다.
