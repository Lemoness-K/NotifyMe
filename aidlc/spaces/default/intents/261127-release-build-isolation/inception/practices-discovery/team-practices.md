# Notify Me 개발·운영 방식 — DS-030

상태: 사용자가 답변 요약을 확인한 내용을 최종 통합했다. 이 단계의 승인과 규칙 승격은 아직 대기 중이다. 대상은 DS-030(사용 릴리스와 개발·테스트 build 경로 분리)이며 제품 기능 확대는 포함하지 않는다.

## Way of Working

- 변경 전에 `AGENTS.md`, `AGENT.md`, 결정 등록부·마스터와 대상 상세 설계를 읽고 현재 코드·운영 경로를 읽기 전용으로 대조한다. 문서와 구현의 차이는 근거와 함께 기록한다.
- 승인된 단계 산출물만 별도로 커밋·반영하며, 다음 단계의 미승인 산출물이나 다른 세션의 변경을 섞지 않는다. 이 프로젝트의 최신 기록은 기본 브랜치 직접 반영과 원격 이력 보존을 정하고 있다. 승인 전 커밋·푸시는 실행하지 않았다.
- 사람에게 검토할 문서는 기존 Issue·Pages 절차를 사용한다. 비밀값·개인정보·감사 기록·상태·단계 일지는 게시하지 않는다.
- 현재 미커밋 코드와 DS-027(상태 배지와 실행 버튼 구분)을 보존한다. 과거 버전으로 임의 복원하거나 전체 작업 트리를 정리하지 않는다. 읽기 전용 재확인 → 최소 계획 → 분리 구현·검증 → 전환·복구 준비 순서를 지킨다.

## Walking Skeleton

- 기존의 최소 전체 흐름 검증 원칙을 유지한다. 이번 작업은 새 제품 기능 대신 별도 작업 복사본에서 build·관련 테스트를 수행해도 사용 릴리스의 경로·asset hash·DB 대상이 유지되는 첫 작은 결과부터 확인한다.
- 고정 릴리스와 웹/API 전환·복구는 후속 구체 설계의 검증 대상으로 연결한다. 이 문서 자체가 동작하는 분리를 증명하거나 실제 서비스 전환을 승인하지 않는다.

## Testing Posture

- **Methodology**: tdd
- **Methodology evidence**: D-071(테스트 우선 구현)과 `AGENT.md` §8, `docs/08-test-strategy.md` §2에서 이미 확정했다.
- **Ordering**: 변경 동작과 주요 위험을 검증하는 테스트를 먼저 작성·검토하고 가능한 경우 실패를 확인한 뒤 구현하여 통과시키며 관련 회귀 검증을 실행한다.
- D-070(개발 루프·환경 분리)에 따라 TypeScript 전체 typecheck, 관련 unit/UI, 임시 SQLite API integration을 적용하고 Kotlin 변경 시 해당 JVM 테스트를 추가한다. 기능·운영 변경에 맞춰 브라우저 E2E와 운영 검증을 별도로 수행한다.
- 전체 line coverage 80%를 유지한다. 현재 `docs/08-test-strategy.md` §3와 `vitest.config.ts`의 `thresholds.lines: 80`은 일치한다. 이전 팀 기록의 coverage 충돌 메모는 현재 파일과 맞지 않아 다시 질문하지 않는다.
- 자동 테스트에는 synthetic fixture·임시 SQLite·fake provider를 사용한다. 운영 데이터·계정·자격 증명을 사용하지 않는다. build 또는 `verify:u1`처럼 `dist`를 쓰는 검증은 사용 서비스가 참조하지 않는 별도 작업 복사본에서만 실행한다.
- 분리된 환경의 build 전후 사용 asset hash·서비스 실행 경로·DB 대상의 불변성을 검증하고 실행 환경·명령·결과·미수행을 각각 남긴다. 환경 파일 전체와 DB 내용은 출력하지 않는다.

## Deployment

- 현재 사용 서비스는 실제 systemd·Caddy로 실행되고 있다. 과거 팀 기록의 “계획만 존재”라는 문장을 현재 운영 사실로 사용하지 않는다. D-077(systemd 프로세스 감독)을 유지한다.
- 고정 사용 릴리스, 개발·테스트 산출물, 영속 데이터·권위 볼륨·설정·비밀·백업의 경계를 구분한다. 사용 웹/API를 같은 검증 버전으로 전환·복구할 최소 구체안을 준비한다.
- 실제 서비스·프록시 전환은 구체 설정·검증·복구 절차를 제시하고 사용자 승인을 받은 범위에서 수행한다. 계획 선택과 실제 전환 승인은 별개다. 서비스 재시작·프록시 reload·주소 변경을 이 조사에서 실행하지 않는다.
- 기존 DB·계정·주소·보호 키·권위 볼륨·백업과 DS-027(사용자 수용 화면)을 보존한다. 자동 배포 확대, 새 외부 서비스·유료 인프라·공개 네트워크 노출을 이번 범위에 자동 포함하지 않는다.
- 완료 시 실제 변경, 대상·적용 버전, 검증 명령/결과와 미수행, 전환·복구 근거, 사용자 확인과 잔여 작업을 로드맵 세션에 반환한다.

## Code Style

- 기존 TypeScript·ESM, React·NestJS 경계와 언어 관례를 따른다. 현재 작업을 이유로 새 formatter·linter나 패키지를 임의로 설치하지 않는다.
- 제품 문서와 설명은 한국어로 작성하고 안정 ID 바로 옆에 짧은 요약을 둔다. 새 사용자 정책을 임의로 확정하거나 열린 질문을 닫지 않는다.
- 문서 변경은 실제 영향 범위의 원본·추적표·운영 안내를 함께 정리하고 로컬 링크·heading anchor와 문자 escaping을 확인한다.
