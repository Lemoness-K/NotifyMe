# Notify Me 모바일 최초 관리자 등록 요구사항

## 변경 목표

운영자가 안드로이드 Chrome에서 Notify Me에 처음 로그인한 뒤, 화면에서 계정을 확인하고 바로 첫 리마인더를 저장할 수 있게 한다. 적용 범위는 Raspberry Pi에서 Tailscale HTTPS로 접근하는 단일 가구 설치다.

완료된 구현의 최초 관리자 등록 요구사항 `FR1.6`과 기준 결정 `D-074`는 서버 CLI 흐름의 이력이다. 이 문서에서 정하는 변경 범위는 모바일 설정이며, 기존 사용자의 로그인, 세션, 이메일 지정 초대는 회귀 검증에 포함한다.

## Functional Requirements

`FR11` — 모바일 최초 관리자 등록. 아래 하위 요구사항이 독립된 검증 항목이다.

| ID | 동작 | 수용 기준 |
|---|---|---|
| FR11.1 | 의도적으로 준비된 신규 설치·초기화 상태에서 서버가 처음으로 Google/Firebase 인증 성공을 처리한 검증 계정을 최초 관리자 후보로 지정한다. | 모바일 로그인 성공 시 해당 계정으로 확인 화면이 열린다. 인증 실패나 경쟁 중인 다른 계정은 후보로 등록되지 않는다. |
| FR11.2 | 모바일 화면에 검증된 Google 계정과 “이 계정이 Notify Me의 최초 관리자가 됩니다. 가구를 만들고 구성원을 초대할 수 있습니다.”라는 안내, “설정 시작” 및 “취소”를 표시한다. | 안드로이드 Chrome의 좁은 화면에서 로그인 계정을 구분할 수 있고 두 동작이 모두 가능하다. 토큰 복사, 개발자 도구, PC 또는 SSH를 사용하지 않는다. |
| FR11.3 | 유효한 후보가 확인하면 가구와 해당 계정의 `ADMIN` 멤버십을 생성하고 같은 로그인으로 리마인더 화면을 연다. | 확인 후 해당 계정으로 리마인더를 저장하고 조회할 수 있다. 다른 계정의 확인 요청은 가구나 권한을 부여하지 않는다. |
| FR11.4 | 취소하면 가구와 관리자 멤버십을 생성하지 않는다. 후보가 창을 닫거나 응답을 잃어도 만료 후 다른 시도가 가능하다. | 취소 후 데이터베이스에 가구·관리자 생성이 없다. 새로고침, 창 닫기, 만료 전후 재인증으로 중복 생성이나 무기한 선점이 발생하지 않는다. 구체적인 만료 시간·갱신·취소 후 재시도 규칙은 설계에서 정한다. |
| FR11.5 | 설정이 끝난 설치에서 기존 구성원의 Google 로그인과 이메일이 지정된 초대 가입을 유지한다. | 기존 DB를 업그레이드한 뒤 기존 구성원이 로그인하고 초대 대상이 기존 흐름으로 가입한다. 최초 관리자 확인 화면은 표시되지 않으며, 미초대 계정의 기존 접근 제어가 유지된다. |
| FR11.6 | 운영 가이드에 첫 설치, 운영자가 의도적으로 다시 설정할 때의 절차, 실제 모바일 검증 방법을 적는다. | 운영자가 가이드만 따라 별도 테스트 설치에서 첫 설정 및 재설정을 할 수 있다. 가이드에서 대상 확인, 승인 경계, 복원·가구 종료와 재설정의 차이를 찾을 수 있다. |

## Non-functional Requirements

| ID | 품질 기준 | 수용 기준 |
|---|---|---|
| NFR11 | **원자성·멱등성.** 하나의 SQLite 트랜잭션으로 최초 가구와 관리자 멤버십을 함께 확정한다. | 두 계정의 동시 인증·확인, 같은 계정의 중복 제출과 응답 유실 후 재시도, 트랜잭션 중간 실패를 검증한다. 같은 설치에서 성공한 최초 가구와 관리자 멤버십은 각각 한 건이며, 중간 실패 시 둘 다 생성되지 않는다. |
| NFR12 | **실패 시 차단.** 설치가 의도적으로 준비되었음을 긍정적으로 확인할 수 있을 때만 등록이 열린다. | DB 장애·경로 누락·일시적 빈 결과, 복원 중·복원 직후 이전 스냅샷, 가구 종료, 이미 사용한 설치에서 새 관리자 등록을 열지 않는다. 저장 상태가 불명확한 경우 가구·관리자 생성 건수는 0이다. |
| NFR13 | **인가 범위.** 초기 등록은 Tailscale 내부 HTTPS 배포를 대상으로 하며 후보 권한은 자신의 온보딩 확인·취소에 한정한다. | 인증 전 요청과 유효 후보가 아닌 요청으로 등록할 수 없다. 유효 후보도 확인 전에는 리마인더 조회·변경, 초대, 관리자 API를 사용할 수 없다. 공개 배포 시 요구되는 보호 정책은 별도 결정으로 남긴다. |
| NFR14 | **실기기 수용 검증.** Raspberry Pi의 격리된 테스트 설치에서 실제 모바일 경로를 검증한다. | Wi-Fi를 끈 안드로이드 Chrome에서 모바일 데이터와 Tailscale을 켜고 처음 Google 로그인 → 계정과 설명 확인 → 설정 시작 → 리마인더 저장 및 재조회까지 확인한다. 환경·기기 사용 여부와 실제 검증 결과를 기록한다. |

## 제약

- 별도 승인 없이 운영 DB 삭제·초기화 및 운영 환경에 대한 파괴적 검증을 실행하지 않는다. 자동화 테스트는 임시 SQLite, 합성 데이터, 테스트 인증 경계를 사용한다.
- `D-074` 최초 관리자 서버 등록 이력을 보존한다. 새 결정과 `Q-048` 첫 가구·관리자 등록, `DS-003` 계정·가구 온보딩, `F-HH-001` 초기 가구 설정, `PR-AC-058` 최초 관리자 수용 기준을 양방향으로 연결한다. 마스터 설계, 제품 요구사항, 도메인·보안 설계, 추적표와 운영 가이드를 같은 변경으로 갱신한다.
- 현재의 단일 가구 모델, Google/Firebase 인증 경계와 기존 초대 흐름을 사용한다.

## Assumptions & Open Questions

- 확인 필요 — 독립된 SQLite 경로 및 테스트용 Google/Firebase 설정을 가진 Pi 테스트 설치와 안드로이드 실기기를 사용할 수 있는지 배포 검증 시 확인한다. 자동 테스트 결과와 실기기 증거를 각각 기록한다.
- 설계 결정 예정 — 설치 허용 상태·실패 시 차단의 저장 경계, 현재 tailnet에서 후보 경로에 접근할 수 있는 범위, 후보 만료·취소·재시도 정책, 성공 직후 응답 유실 복구를 정한다.
- 공개 인터넷 배포의 보호 정책은 별도 결정으로 남긴다. 다중 가구 UI와 운영 DB의 실제 삭제·초기화는 이번 범위 밖이다.
